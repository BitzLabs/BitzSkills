# Codex 専用の補足

共通ルールはリポジトリルートの `AGENTS.md` を正とする。本ファイルは、そこから明示的に読ませる補足である。

## サブエージェントの設定

- 共通の委譲方針と役割一覧は `AGENTS.md` の「サブエージェントへの委譲」に従う
- カスタムエージェントは `.codex/agents/*.toml` に定義する。各定義の `name` で役割を指定する
- 共通の4役（`fixture-author`、`implementer`、`worker`、`reviewer`）は、各定義の
  `developer_instructions` から `agents/<役割>.md` を読む。パスはリポジトリルートを基準とする
- 司令塔の既定モデルと推論の設定は `.codex/config.toml`、役割別の設定は各 TOML に記載する。
  モデル名は Markdown に重複して記載しない
- 同時起動数は `.codex/config.toml` の `agents.max_concurrent_threads_per_session` で設定する。
  利用環境の上限がこれより低い場合は、その上限に従う
- コードベースの広範な探索には `.codex/agents/explorer.toml` の `explorer` を使う。
  同名の組み込みエージェントより、この専用定義が優先される。探索役の行動原則はこの TOML に記載する

## 委譲と検収

- 担当範囲と役割定義のパスを渡して起動し、必要な結果を回収してから司令塔が統合・検収する
- 実装が難航して別モデルでの調査が必要な場合は、司令塔がモデルを指定した別の調査を行う。
  カスタムエージェントの固定モデルを、起動時の指定で上書きする運用にはしない
- 独立レビューには作業者と別のエージェントを使い、対象の commit と検証方法を渡す
- サブエージェントは親セッションの権限を継承する。TOML に独自の権限設定を置かない
- `reviewer` の編集禁止や `fixture-author` の Core ソース参照禁止は、共通役割定義の行動原則である。
  役割の定義だけで、ファイル操作を機械的に制限できるとは扱わない
