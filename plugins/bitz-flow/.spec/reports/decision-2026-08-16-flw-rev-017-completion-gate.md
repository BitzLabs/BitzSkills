## 1. Completion Gate — 保留を継続する

M2 出口条件は **8項目中 7項目 PASS**（`FLW-REV-016` 時点では3項目 BLOCKED）まで到達したが、
Gate は通さない。理由は2つある。

**理由1: 残る1項目が半分しか満たされていない。**
「operation 外変更の audit 検出・quarantine 接続」は、`SI-FLW-064` で検出器が動くようになった
（`SI-FLW-059` の「実装不能」宣言は覆った）が、audit の出力語彙に **quarantine 接続に
対応する語が無く**、SKILL.md も B2 の規範へ追随していない（`SYN-011`）。
出口条件の文言は「検出・quarantine 接続」であり、検出だけでは満たさない。

**理由2: 最終状態を独立に評価した観点が無い（`GP-005`）。**
`FLW-REV-017` の4観点は**是正前後の異なる commit を見ている** —
`data-integrity` / `risk` / `operations` は `a7c1545`（PR #289 / #290 の前）、
`consistency` は `56418fc`（後）。critical 4件が「解消済み」であることを判定したのは
司令塔自身であり、独立の検分を経ていない。
本リポジトリには**自己レビューが独立レビューより +1.3 甘く出る実測**があり
（自己 3.62 対 独立 2.31）、自己判定を Gate 通過の根拠にはできない。

**却下した選択肢**:

| 案 | 却下理由 |
|---|---|
| 条件付きで通し `SYN-011` / `GP-005` を M3 の着手条件へ引き継ぐ | 出口条件を満たさないまま次段へ進む前例になる。`FLW-REV-015` / `016` が繰り返し指摘してきた型 |
| `SYN-011` 解消のみを条件に自動的に通す | `GP-005` を放棄して自己判定を受け入れることになり、理由2に反する |

## 2. 予備枠 — 2 PR をそのまま充てる

第2次予算は PR #291 の記録で本体枠（3 PR / 9 session）を使い切り、
**予備枠（2 PR / 6 session）に入った**。この予備を通過条件6件へ充てる。

| PR | 内容 | 効果 |
|---|---|---|
| **PR-A** | `SYN-011` ＋ `SYN-012` ＋ `SI-FLW-066`（`SYN-008` / `SYN-009`） | **出口条件が 8/8 になる** |

PR-A の4件はいずれも「**実装は済んでいるのに宣言・語彙・証跡が追いついていない**」という
同じ型の負債であり、1つの関心事として束ねられる。

これで 6件すべてが閉じ、予備枠をちょうど使い切る。予備まで使い切った時点で自動停止する
（2026-08-15 の付帯条件3を継承）。**追加予算が要るなら PR-B の後に改めて裁定する。**

## 3. business 観点 — PR-B のレビュー周回に含める

`FLW-REV-017` の business 観点は、Claude Code の自動モード分類器が独立エージェントの起動を
ブロックしたため欠測した（測定重み 0.85、感度 0.01）。

`GP-005` でどのみち最終状態のレビューを1周するため、**その一観点として発注する**。
レビューという文脈で発注すれば、回避策を取らずに自然な形で埋まる。
限界費用も小さい。

なお欠測を放置しても判定は変わらない（3.13 対 3.14）。business は前回 3.20 と
**最高スコアの観点**であり、欠測は「実態より低く見える」方向にしか効かないため、
保守的な材料としてはそのままでも使用できた。埋めるのは精度のためであって、
判定を覆すためではない。
