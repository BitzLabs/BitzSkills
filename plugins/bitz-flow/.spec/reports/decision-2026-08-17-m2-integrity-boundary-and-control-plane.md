## 裁定

1. **M2 の integrity 境界を限定する。** M2 は、通常運用で生じる receipt の破損、
   worktree の生成・消失、binding 不整合を検知して quarantine 語彙へ接続する。
   M2 単独では、receipt store とその保護境界の双方を書き換えられる攻撃者に対する
   真正性保証を主張しない。この強度の保証には外部 trust anchor を必要とするため、
   M3 以降または別の security 設計で扱う。
2. **Completion Gate は保留を継続する。** この裁定は M2 出口条件4・6・7を PASS と
   読み替えるものではない。公開出荷面は M0 read-only 3 operation のままとする。
3. **`SI-FLW-074` を受理し、統制層の回復を最優先で実施する。** ROADMAP、budget SSOT、
   出口条件と証跡の対応、PR と task の対応を実体へ追随させ、再発を機械検査で止める。
4. **`SI-FLW-072` / `073` / `075` は未受理のまま保持する。** `SI-FLW-072` は上記境界を
   反映した設計差分を先に作成してから再裁定する。`SI-FLW-073` / `075` は統制層回復後に、
   独立した scope・task・陽性/陰性対照を持つ作業単位として提示する。
5. **`GP-006` の M3〜M5 予算再校正は未裁定とする。** 統制層に正しいM2実績を記録した後、
   裁定材料を再提示する。

## 要件ライフサイクルへの適用

`FLW-FR-012` の「milestone開始時にbudget・実績・レビュー修正回数・出口未達理由をrun manifestへ
記録する」受入基準は、M2の実体と一致していない。したがって同要件を `verified` から
`implementing` へ戻し、`SI-FLW-074` の統制回復タスクが完了するまで再度の verified 化を行わない。
これは契約追加ではなく、既存契約の未充足を可視化する是正である。

## 根拠

- `FLW-REV-019` は、receipt chain が破損検出には有効でも、自己整合的な改ざんの真正性を
  証明できないことを P0 とした。この性質を M2 の単独責務として扱い続けると、外部 trust
  anchor の設計なしに出口を満たすという過大な主張になる。
- 同レビューは、3周回にわたり記録・予算・タスク境界の追随不全が反復し、レビューのたびに
  同型の不整合が再発していることを確認した。最初に統制層を回復しなければ、次の技術是正の
  根拠も信頼できない。
