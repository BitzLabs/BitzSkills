## 裁定 — 検証予算 +2 PR（是正 PR と実測 PR を分離）

**accept。** 根拠は次の3点。

1. **是正が記述に閉じており、実装リスクがほぼ無い。** `SI-FLW-028` の案1・案2 は
   `--base` の help 文字列と v2 fixture の記述だけを変え、`flow.py` の挙動・result・schema を
   変えない。単独 revert できる。
2. **1ラウンドで判定がつく。** 未達は SFCR ただ 1 点で、失敗は単一 task へ集中している。
   効いたかどうかは第12ラウンドの `diff-summary` self-retry で直接見える。
3. **scope 縮小は、直せると分かっている欠陥を残したまま M0 の目的を放棄することになる。**
   縮退出荷境界へ切り替えても M0 read-only prerelease を維持するだけで、
   「write 機能へ進む前に単一 dispatcher の価値を検証する」目的は未達のまま残る。
   第1回で「次は scope 縮小を第一候補」としたのは**原因不明のまま是正を続けることへの戒め**で
   あり、原因が記述欠陥1点まで特定できた本件はその射程外と解する。

### なぜ 1 PR ではなく 2 PR へ分けるか

第1回は「修正 + 実測」を 1 PR で想定していた。今回は分離する。

- **`1 PR = 1 関心事`（AGENTS.md）を守るため。** 混ぜると、実測が未達だったときに
  是正だけを revert できない。
- **検証の性質が違う。** 是正 PR は `release_check.py` と pytest で検証が閉じる。
  実測 PR は外部エージェント3種の実行を伴い、再現性の担保も成果物も別物である。
- **#179 の再発を防ぐため。** 第1回の超過は、実測準備の PR に新規発見の是正が混入して
  膨らんだことが原因だった。分離しておけば、是正 PR で新たな欠陥が見つかっても
  実測 PR の予算を侵食しない。

| 改訂後の M0 残予算 | 用途 |
|---|---|
| 検証（eval 反復） **2 PR** | 1本目 = `SI-FLW-028` の是正 / 2本目 = 第12ラウンド実測と M0 出口判定 |
| session 4（累計 14。**据え置き**） | PR 枠のみ増やす。session が制約になっていないため |

### 本裁定に付ける歯止め

第1回よりも条件を強くする。

1. **第12ラウンドが未達なら、scope 縮小を第一候補ではなく唯一の候補とする。**
   これ以上の「是正 → 再測定」の反復を M0 では認めない。
2. **是正 PR（1本目）で新たな欠陥を見つけても、本 PR では是正せず起票にとどめる。**
   #179 で起きた混入を機械的に禁じる。
3. **実測 PR（2本目）は claude-code を含む 3 platform で行う。** 第11ラウンドは
   claude-code 未実測であり、**そもそも M0 出口判定が成立していない**。
   2 platform の再測定では予算を使っても出口へ到達できない。

## 採らなかった案

- **scope 縮小（第1回で第一候補としたもの）**: 上記3の理由で今回は採らない。
  **次回は唯一の候補とする**
- **是正と実測を 1 PR にまとめる（+1 PR）**: 予算は小さいが `1 PR = 1 関心事` を破り、
  未達時に是正だけを戻せない。#179 と同じ混入を招く形でもある
- **`SI-FLW-029` も同時に是正する**: `SI-FLW-029` は被測定物（`flow.py`）の挙動変更を伴い
  影響が大きい。効く指標も SFCR ではなく `help_invocations` で別である。
  **028 単独で先に進め、029 は open のまま据え置く**
