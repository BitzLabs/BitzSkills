## 裁定

### 1. `SI-FLW-057` — **accept（M2 分と M3 分へ分割）**

| finding | 内容 | 所属 |
|---|---|---|
| `SYN-003` | 例外遮蔽により破壊的な部分適用が `BLOCKED` と誤報される | **M2**（`apply()` は `create` / `resume` も通る） |
| `SYN-002` | receipt の step 語彙が安全核と不一致 | **M3**（`FINISH_STEPS` / `DISCARD_STEPS` は破壊系のみ） |
| `SYN-010` | `--backup-receipt` 未実装・`branch -D` の retention 再照合欠落 | **M3**（`discard` 専用） |

`SI-FLW-057` は **M2 分（`SYN-003`）に scope を絞る**。
M3 分（`SYN-002` / `SYN-010`）は `SI-FLW-060` として分離起票する。

なお `SYN-002` の調査で、**`create` / `resume` には `worktree_cleanup` 側の
reconcile 経路がそもそも存在しない**ことが判明した。これは M2 の論点であり、
`SI-FLW-057` の確認観点へ含める。

### 2. `SI-FLW-058` — **accept**

M2 出口条件「`write_target: local` の被測定物 confirmation が 3 platform で PASS」の実体であり、
`FLW-REV-016:GP-004` に対応する。現状 hazard / residual が恒真値であるため、
accept しなければ出口判定の根拠が得られない。scope は起票時のまま
（`SYN-004` / `005` / `007` / `008` / `009`）。

### 3. `SI-FLW-059` — **accept（`SYN-016` を除外）**

残る `SYN-006`（`create` / `resume` を公開 dispatcher 経由 E2E で網羅）と
`SYN-011`（`worktree.audit` の契約層接続と quarantine 接続）を accept する。
