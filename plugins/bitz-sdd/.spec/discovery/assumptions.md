## Go / No-Go 裁定案（最終裁定は人間が PR レビューで行う）

**裁定案: 条件付き Go。**

- **根拠1（Feasibility 済）**: 崩壊クリティカルな F1 は実装・unit-test・CI で検証済み
  （`tests/test_spec_inspect.py`、SI-CORE-001〜003 で誤検知も是正）。F2/F3 も運用実績あり。
- **根拠2（Desirability の非対称性）**: D1 は本人ドッグフーディングで弱く検証済み。ただし D3
  （OSS 外部需要）は**未検証かつ事前閾値が未定義**（テスト自体は仮説表で定義済み）——
  本来なら No-Go トリガに該当する。
- **根拠3（遡及 discovery の特殊性）**: 本プロダクトは既にリリース済みで**主要ペルソナ（P1）
  向けには設計着手可否を問う段階を過ぎている**。よって「P1 主要スコープは Go、D3（OSS 拡大）は
  Go の前提にしない open 仮説として追跡」とするのが妥当。

**条件（Go の付帯）**:
1. D3（OSS 需要）は崩壊クリティカルな open 仮説として明示追跡し、OSS 拡大に賭ける施策
   （オンボーディング改善等）に着手する前に、fake-door/導入計測＋事前閾値を定義する。
2. ~~V2（本文肥大化）は 3段階読み込み（SI-CORE-013）で早期に対処する。~~ — **消化済み**。
   ただし観測（本文サイズ・実行トークン）は依然未実施であり、仮説の検証には至っていない。
3. 指標の実測基盤（metrics.md の `TBD` 群）整備を別 issue 化する — **部分的に前進**
   （`spec_status` / `sdd_report` / `.spec/verification/`）。目標値の設定と自動収集は未着手。

> **最終裁定は人間が本ファイルを含む PR のレビューで行う**（sdd-core のゲート規約が正）。
> エビデンスが届いたらゲートは再訪し、一度きりの儀式にしない。docs/ 該当ドラフトが影響を
> 受けたら再伝播プロトコルに乗せる。

## 1.1 追記 — 内部品質の再評価（SDD-REV-006）

本ゲートは Desirability / Viability / Feasibility を扱うが、**内部の規律が保たれているか**は
対象外だった。SDD-REV-006（2026-07-29、判定 CONDITIONAL_PASS）は次を指摘している:

- Design 層（`domain-model.md` / `ROADMAP.md`）が欠落し、要件の46%が実装からの逆起票
- レビュー指摘が spec-issue 化されず消える構造（前回レビューの P1 が7日以上放置）
- 代行遷移の担保である Promotion Gate が全ワークスペースで未実行（promoted 0 件）

F1（機械検証の実現可能性）は依然「検証済み」だが、**機械検証が回ることと規律が守られることは
別問題**である。Go の判断は変えないが、SDD-REV-006 の GP-001〜005 を消化するまで
Design Gate を通さない条件を追加する。
