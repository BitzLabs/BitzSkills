# 裁定記録 — SI-SDD-011（Discovery成果物の同期マッピング不足）

- **日付**: 2026-07-29
- **裁定者**: hide（リポジトリ所有者）
- **対象**: SI-SDD-011 の要件化（SDD-FR-149 / SDD-FR-150）と Design Gate 裁定点3件
- **裁定の形式**: 代行可視化経路（`--on-behalf-of hide`）。エージェントが3つの裁定点を
  推薦つきで提示し、裁定者は個別選択を行わず、前セッションで与えた自動進行の明示承認
  （「push → PR 作成 → CI green で squash merge まで」「以降の各段階も同じ運用で自動進行する」）
  および本セッションの指示「SI-SDD-011 を進めましょう」に基づいて委任した。
  したがって**各裁定点は推薦（第1候補）を採用**した。本記録は Promotion Gate で裁定者が
  内容を確認・修正できるようにするための一次資料であり、本人性は機械検証されていない。

## 背景

`sdd-discovery` の SKILL.md は Discovery 5ステップの成果物を `docs/00_はじめに/` の6文書へ
同期すると宣言していたが、`sdd_sync.py` の `DEFAULT_MAPPING` には vision と scope しか無く、
metrics・personas・positioning・制約が同期されなかった。pull は正常終了するため、
利用者は欠落に気づけない。宣言と実装の乖離である。

## 裁定点1: scope.md → 対象外.md / 制約.md の 1:2 分割をどう解決するか

**採用: `.spec/discovery/constraints.md` を新設して全マッピングを 1:1 に保つ**

- pull と push の対称性が保たれ、SDD-FR-135（frontmatter 境界を保持する本文双方向同期）の
  契約をそのまま適用できる。1つの `.spec` 文書を2つの docs 文書へ分割すると、
  逆同期（push）の反映先が決まらない。
- `sdd-discovery` の `references/scope.md` は既に「制約の結論は constraints.md ドラフトへ」と
  書いており、宣言側とも整合する。
- 却下: 見出しベースの決定的分割（push が非対称になり見出し表記ゆれに弱い）。
  却下: 制約.md を同期対象外と明記する（乖離の解消を「実装に宣言を合わせる」方向で行うことになり、
  Discovery の結論を docs へ漏れなく展開するという SI-SDD-011 の目的を満たさない）。

## 裁定点2: SKILL.md の同期表と DEFAULT_MAPPING の二重定義をどう防ぐか

**採用: SDD-FR-140 と同じ機械検証マーカー方式（`release_check.py` で照合）**

- 既存の前例（フェーズ正規語彙）をそのまま踏襲でき、リポジトリ内に検証様式が2つ生まれない。
- マーカーと人間可読の同期表の両方を照合するため、可視表だけが古くなるドリフトも検出できる。
- 却下: SKILL.md から列挙を消す（二重定義は消えるが、スキルを読むエージェントが
  マッピングを知るのにコードを読む必要が出る）。
  却下: 外部データファイルを SSOT にする（スキル自己完結の原則と読み込みコストに反する）。

## 裁定点3: このリポジトリ自身の既存 scope.md にある「制約」節の扱い

**採用: 移行しない（契約追加のみ）**

- `constraints.md` 不在のワークスペースは pull で SKIP されるだけで、既存挙動は不変。
  制約を切り出すかは各プロジェクトの裁量とする。
- `plugins/bitz-flow/.spec/discovery/` は本セッション時点で別作業が進行中であり、
  触れると衝突する。
- 「1 PR = 1 関心事」の粒度も超えるため、必要になった時点で別 PR で行う。

## 残余リスク

- 既存プロジェクトの `scope.md` に制約が同居したままだと `docs/00_はじめに/制約.md` は
  手書き文書のままになる。同期対象になったことに気づかず放置される可能性がある
  — SKILL.md と references/scope.md の両方に切り出しの理由を明記して緩和した。
- マーカー照合は「同一行に対で現れること」を見るため、可読表の説明文だけが誤っていても
  検出できない。語推定はしない方針（SI-CORE-033 の裁定）を踏襲した意図的な限界。
