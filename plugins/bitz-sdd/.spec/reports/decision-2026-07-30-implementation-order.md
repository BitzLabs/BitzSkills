## 裁定A — V4 リリース方針（破壊的変更の寄せ先）

**採用: 破壊的変更を実装順序の後半（裁定1・裁定5・裁定4）へ寄せる**

- `.claude-plugin/marketplace.json` は `"source": "./plugins/bitz-sdd"` でありバージョンを
  固定しない。**main へマージした時点で即配布**され、ステージング状態が存在しない。
- したがって破壊的変更を 3.x の minor として main へ入れると、破壊的変更が minor で配布され、
  `bitz-sdd>=2.0` を宣言する bitz-ddd が無警告でそれを拾う（2026-07-29 Design Gate の
  「破壊的変更の波及」節が指摘済み）。
- ROADMAP の依存順に素直に従えば加法的な変更が先・破壊的な変更が後になるため、
  **加法的な範囲を 3.x で進め、最初の破壊的変更に着手する時点で 4.0.0 へ一括 bump** する。
  これで「V4 は全部終わった段階」という方針と SemVer 契約の両方を満たす。

## 裁定B — 同一性 fingerprint への任意ツールの扱い

**採用: 存在する任意ツールも fingerprint に含める**

- `CORE-FR-011` の「同一 version で fingerprint 相違 → 安全停止」判定の対象を広げ、
  同一バージョンなのに片方のキャッシュだけ任意ツールを欠く**部分インストールを競合として
  検出できる**ようにする。
- fingerprint は実行時比較専用で永続化しないため、既存バージョンの fingerprint 値が
  変わっても後方互換は壊れない。
- **本裁定は `SI-CORE-038` の実装スコープに属し、裁定C により実施時期が後ろへ移った**。
  任意ツール概念を導入する時点で有効になる。

## 裁定C — `SI-CORE-038` のスコープ縮小と実装順序の見直し

**採用: `SI-CORE-038` を縮めて裁定1の直前へ移し、順序7（`SI-SDD-028` / `SI-SDD-031`）から着手する**

2026-07-29 Design Gate が `SI-CORE-038` を最先行（順序6）に置いた根拠
「これが無いと sdd-test 側へ判定を置けない」は、着手時の実測で成り立たないことが判明した。
詳細と是正提案は **`SI-SDD-035`** に起票した。要点:

- `spec_verify.py` は既に sdd-test に存在して動作しており、ラッパーの必須解決集合は
  sdd-core 側の4ツールなので sdd-test への追加は衝突しない
- スキル内からの呼び出しはスキル相対パスでバージョン非依存に解決できる。リポジトリ内の
  直接実行4ツールの呼び出しにバージョン直書きは1件も無い
- 裁定1が実際に要求するのは `scripts/spec:40` の `REL` の sdd-core 固定の一般化であり、
  任意ツール概念の導入よりはるかに小さい

したがって `SI-CORE-038` のスコープを **`REL` のツールごと相対パス一般化 ＋ 呼び出し規約の
明文化**に縮め、裁定1の直前へ移す。任意ツール概念と新規サブコマンド公開（裁定B を含む）は
必要になってから行う。着手は**他の裁定に依存せず完全に加法的な順序7**とする。
