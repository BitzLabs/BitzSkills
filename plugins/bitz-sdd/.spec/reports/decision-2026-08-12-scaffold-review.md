# 裁定記録 — spec scaffold へ review 種別を追加する

- **日付**: 2026-08-12
- **裁定者**: hide
- **対象**: `SI-SDD-041`

## 裁定

**採用する。** レビューを今後も継続するため、V4 を待たず V3 系で先に対応する。

## 根拠

`spec_inspect` はレビュー成果物を `SDD-FR-158` / `SDD-FR-161` で厳格に検証するが、
**生成側の支援が無い**。他の4種別（requirement / task / spec-issue / design / gate）は
`spec scaffold` が必須キー入りの雛形を出すため取りこぼしようがないのに対し、
レビューだけ手書きで schema は散文としてのみ存在する。

2026-08-12 の `FLW-REV-011` 作成時に、この非対称が 111 問題・3往復の手戻りとして現実化した。
検証層は正しく機能したが、**すべての手戻りが「書いた後」に発生**した。

## V4 との切り分け

V4 の13テーマを確認し、該当が無いことを確認した。

- テーマ3「レビュー品質目標の引き上げ」— スコア基準（4.5 以上等）の話であり生成支援ではない
- テーマ13「検証活動の成果物化」— 測定定義・計測器・検証履歴・予算消費のモデル化であり、
  レビュー成果物の書きやすさは対象外

種別の**追加**であり既存生成物を変えないため、V4 のカットオーバーを待つ理由が無い。

## 実装方針

`spec_scaffold.py` へ `review` 種別を追加し、`<REV-ID>.json` と `<REV-ID>.md` を採番付きで生成する。
`--findings N` / `--preconditions N` で雛形の件数を指定できるようにし、
`basis: verified` の雛形には `evidence` を空文字で置いて「埋めるべき欄」として見せる。

**受入の要点**: 生成した雛形が**そのまま** `spec_inspect` を通ること。
雛形が検証を通らなければ、この対応は目的を果たしていない。
