- **目的**: 2026-07-29 の Design Gate は裁定1（検証判定を sdd-test へ移設）の帰結として
  「`SI-CORE-038`（ラッパーの任意ツール対応）が裁定1の実装前提になる」「**これが無いと
  sdd-test 側へ判定を置けない**」と記録し、ROADMAP はこれを実装順序の**最先行（順序6）**に置いた。
  2026-07-30 に着手して実測すると、この前提が成り立たない:
  1. `spec_verify.py` は**すでに sdd-test に存在して動作している**（SI-SDD-016 で導入・検証済み）。
     ラッパーの必須解決集合は sdd-core 側の4ツール（`TOOLS.values()` ＋ `V3_SUPPORT_SCRIPTS`）で
     あり、sdd-test へツールを追加しても衝突しない。
  2. スキル内からの呼び出しはスキル相対パスでバージョン非依存に解決できる
     （`sdd-report/SKILL.md:37` が既に `python3 <このスキル>/scripts/sdd_report.py` と記述）。
     リポジトリ内で直接実行4ツール（`spec_verify` / `sdd_sync` / `docs_inspect` / `sdd_report`）を
     呼ぶ箇所にバージョン直書きは**1件も無い**。`tests/*.py` と `release_check.py` は
     作業ツリーを検査する側であり、ラッパー化してはならない呼び出しである。
  3. 裁定1が実際に要求する制約は `scripts/spec:40` の `REL = ("skills", "sdd-core", "scripts")` の
     sdd-core 固定であり、判定機能が sdd-test へ移っても利用者が同じ `scripts/spec inspect` で
     呼び続けるならラッパーが sdd-core の外へ手を伸ばす必要がある。これは「任意ツール概念の導入」より
     はるかに小さい変更である。

  検証されていない前提が最先行タスクを1件生み、実装順序全体を拘束していた。これは
  `SI-SDD-031` が扱う「レビュー指摘の消化が追跡されない」と同じ構造の欠落であり、
  対象がレビュー指摘ではなく**裁定の帰結**である点だけが異なる。
- **提案する修正**:
  1. 裁定記録に訂正を追記する（裁定1の帰結の記述を実測に合わせる。記録は書き換えず訂正として残す）
  2. ROADMAP の実装順序を見直す — `SI-CORE-038` を裁定1の直前へ移し、スコープを
     「`REL` のツールごと相対パス一般化」＋「呼び出し規約の明文化」に縮める。
     任意ツール概念の導入と新規サブコマンド公開は必要になってから行う
  3. 裁定記録に「前提条件」を書くときは、それが**検証済みの事実か未検証の想定か**を区別して
     明示することを規定する（`SI-SDD-031` の `ReviewFinding` 設計の入力とする）
  4. 呼び出し規約を明文化する — ラッパー経由は sdd-core の4ツール、それ以外はスキル相対、
     作業ツリー検査は repo 相対。`SI-CORE-038` の提案4 の実体
- **対象ファイル**: `plugins/bitz-sdd/.spec/reports/decision-2026-07-29-design-gate.md`（訂正の追記）、
  `plugins/bitz-sdd/.spec/ROADMAP.md`（順序と依存）、`AGENTS.md`（定型手順の呼び出し規約）、

- **確認観点**: 訂正後も裁定そのもの（裁定1の案B 採用）は変わらないこと。順序変更後も裁定1が
  着手可能であること（`SI-CORE-038` 未実装でも sdd-test 側へ判定を置けること）。明文化した
  呼び出し規約が実体と一致すること（`tests` / `release_check` は repo 相対、`SKILL.md` はスキル相対、
  `scripts/spec` は sdd-core の4ツール）。提案4 を `CORE-CON-*` 要件として起票すべきかは裁定点。
- **影響推定・ロールバック**: 記録と計画の訂正が主でコード変更を伴わない。提案4 は AGENTS.md への
  加法的な追記。ロールバックは追記の revert のみ。軽量レーンで実施可（公開契約に触れない）。
  ただし提案2 は `SI-CORE-038` の実装スコープを変更するため、同 spec-issue の再裁定を伴う。
