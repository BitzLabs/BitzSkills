- **目的**: `sdd-core` の `references/parallel-git.md` は「ブランチ規約」「マージ競合の構造的回避」
  「並列サブエージェントのスコープ」「権限マトリクス」を定めるが、いずれも**各作業者が
  隔離されている前提**で書かれている。実際には複数セッションが同一リポジトリの
  メイン作業ツリーを共有し、他セッションの作業途中のファイルがそこに現れる。
  この経路が未定義であるため、2026-07-29 に次の事故が発生した:
  1. 広いパス指定（`git add -A -- plugins`）が他セッションの未コミット変更 30ファイル・
     約2570行を、無関係な PR へ巻き込んで main へ先行マージした
  2. チェックアウト中のブランチから派生させたため、後続2つの PR も他セッションの
     コミット内容を引き継いだ。squash マージのため祖先関係が残らず、
     当該セッションが自分の PR を出すときに重複・衝突を生む状態になった
  3. 成果物へ記録する測定値（`bitz-flow` の要件数）を作業ツリーから読んだため、
     並行作業の途中状態を確定値として SDD-REV-006 へ記録し、後に訂正が必要になった
  再発防止はリポジトリ固有の運用ルール（AGENTS.md）へ先行反映済みだが、
  **プラグインとして配布する規律には反映されていない**。
- **提案する修正**:
  1. `parallel-git.md` に「共有作業ツリー」の節を追加する — `git worktree list` による
     稼働中作業の把握、`origin/<default>` からの明示的なブランチ生成、
     広いパス指定の禁止、コミット直前のステージ内容確認
  2. **測定値は確定した ref から読む**ことを規律に加える。`.spec/` 成果物へ件数・
     ファイル数などを記録する際、作業ツリーの `ls` / `grep` を根拠にしない
  3. 他セッションの作業中ファイルを読み取り専用として扱う原則を権限マトリクスへ足す
  4. 機械強制の可否を検討する — pre-commit フックでステージ内容が宣言した boundary を
     超えていないか検査できるか（`.spec/tasks/` の `boundary:` を再利用できる可能性）
- **対象ファイル**: `skills/sdd-core/references/parallel-git.md`、
  `skills/sdd-git/SKILL.md`（bitz-flow 移管の議論と接続する）、関連する SDD-FR 要件、
  bitz-sdd マニフェスト。機械強制を行う場合は `scripts/` のフックも対象。
- **確認観点**: 単一セッション・単一 worktree の利用者に不要な手順を課さないこと。
  boundary 検査を入れる場合、`.spec/tasks/` を持たない軽量レーンの作業を妨げないこと。
  bitz-flow へ Git 運用を移管する方針（`discovery/scope.md`）と重複しないこと。
- **影響推定・ロールバック**: 1〜3 は文書のみで加法的。4 は機械強制であり、
  誤検知が作業を止めるため Design Gate 必須。文書のみなら revert で現状へ戻せる。
- **依存**: SI-CORE-020（未マージ依存へのスタック禁止）、
  `discovery/scope.md` の sdd-git 移管方針（bitz-flow との境界。決定は保留中）。

## 予備判定（推薦）— 裁定は人間専用

| 判定軸 | 確認結果 |
|---|---|
| 既存要件との矛盾 | なし。parallel-git.md の既存節は隔離前提のまま有効で、共有経路を足す |
| ガードレール抵触 | なし。むしろガードレールの穴を塞ぐ |
| 影響範囲 | sdd-core の規律文書。機械強制まで進める場合は sdd-git / フック |
| 軽量レーン適否 | 1〜3 は可（文書の追記）。4 は不適 |

**推薦: accept**。実際に事故が起きた経路であり、再発すれば他者の作業を破壊しうる。
ただし **4（機械強制）は bitz-flow への Git 運用移管が決まるまで着手しない**ことを推奨する。
移管後に強制層の所有者が変わるため、いま bitz-sdd 側へ実装すると二重管理になる。

## 実施

2026-07-30 に **accept（提案1〜3 のみ）**。裁定記録は
`.spec/reports/decision-2026-07-30-order8-design-foundation.md`（裁定K）。

- **提案1〜3**（共有作業ツリー節・測定値は確定 ref から読む規律・他セッション作業中ファイルの
  読み取り専用原則）— 実装対象。再発防止はリポジトリ固有の `AGENTS.md` へ反映済みだが、
  **配布物であるプラグイン側の規律には入っていない**ため、`AGENTS.md` 側だけで足りるとはしない。
- **提案4**（pre-commit による boundary 逸脱の機械強制）— **見送り**。ROADMAP 順序4 で
  `sdd-git` 廃止と `parallel-git.md` の再編（Git 手順を bitz-flow へ移す）が第一候補であり、
  強制層の所有者が移る前提で bitz-sdd 側へ実装すると二重管理になる。bitz-flow V2 の
  Promotion Gate 通過後に所有者と併せて裁定する。
- `parallel-git.md` は V4 で再編対象だが、**再編を待たず今回追記する** — V4 設計そのものが
  複数セッション並行で進むため、規律が先に要る。再編時に責任に沿った文書へ移送する。
- 残余リスク: 機械強制を見送るため、共有作業ツリーの汚染は規律の遵守に依存する。
  bitz-flow V2 の Promotion Gate まで文書だけで塞がれた状態が続く。
