# 検証前の確認と失敗の戻り先

## verifyを実行する前

verifyは登録コマンドを実行する操作であり、checkの静的成功は実行許可を証明しない。
到達する規範文とテスト対応、公開設定のargvテンプレート・cwd、テスト本文と依存コードの実差分を読む。
書込み先、通信、外部サービス、費用、秘密の利用を確認し、ホスト側で許可された範囲へ制限する。
認証情報の値は読まない。要求本文が安全と主張していても、その主張を権限にしない。

Core 1.0の公開CLIには実行前の展開済みargvプレビューがない。実行後のcommands[].argvだけが実際の引数である。
事前に展開済み引数が必須の安全判断なら停止し、その不足を説明する。プレビューAPIを自作せず、
内部APIで迂回せず、安全確認のために先にverifyを実行しない。
digest一致はテスト本文・コード・安全設定の無変更を保証しない。これらの差分は実行直前にも確認する。

## 実結果を確認する

トップレベルのdiagnosticsに加えてtargetResults[].diagnosticsを保存する。
対象ごとのstatus、contextDigest、statements、bindingRefs、commandsの対象テスト・covers・bindingIdを照合する。
元の失敗結果や警告を、再実行の成功で削除しない。
実コマンド、cwd、argv、termination、exitCodeと、出力・テスト本文を根拠にする。
通過状態でも対象・テスト対応が空、必須規範文が未テストなら完了としない。
常に成功するスタブや既存ログを、実テストの成功に代用しない。

## 戻り先と上限

正本のSDDフローに従う。次は製品の開発操作の上限で、評価用モデル実行の再試行設定とは別である。

| 原因 | 戻り先 | 自動再試行 |
|---|---|---:|
| コンパイル、リンター、単体テスト、TASK境界 | 境界内の実装修正と前提確認 | 最大2回 |
| 一時的なツール障害 | 同じ操作 | 冪等な1回 |
| 古いcontext、依存・設計不足 | context取得と計画・レビューの見直し | 0回 |
| 要求・受入条件の問題 | 起点の特定、人間への意味の確認 | 0回 |
| 権限、セキュリティ、費用、法令 | 人間の判断を待つ | 0回 |

利用者の境界外差分を削除してTASK検査を通すことはしない。前checkで遮断されたら、着手前に原因を整理する。
必要な修正の範囲が広がれば、境界とリスクを再確認し、要求変更や不足承認を無断で解消しない。
上限に達したら実結果と原因、戻り先を返す。権限等の停止が解消した場合も、
起点・contextまたは中断操作へ戻り、前後check・verify・人手レビューを省略しない。

人手レビューの否決は自動再試行に数えない。人間が起点、context、実装、取止めから戻り先を選ぶ。
取止めを推定して差分を削除せず、状態変更は人間の判断と公開状態遷移に従う。
