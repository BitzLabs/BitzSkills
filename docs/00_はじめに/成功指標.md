# 成功指標

> テレメトリと利用台帳は未整備。根拠のない数値目標は置かず、現時点は `TBD` とする。

## North Star Metric

- **指標**: BitzSkillsの標準プロファイルを利用し、定められた検証を通過して完了した開発サイクル数。
- **定義**: インストール数やスキル起動回数ではなく、「共通規律が実際の開発を最後まで支えた回数」を測る。
- **測定方法/ソース**: 現状は `.spec/reports/` とPR本文の検証結果を手集計。
- **目標値**: `TBD`（計測基盤未整備のため）。

## 入力指標

| 更新追従率 | 最新互換版へ更新され、doctor / release checkを通過した導入環境の割合 | `TBD` |

## ガードレール（NSM最適化中に劣化させない対抗指標）

| ガードレール指標 | 閾値 | なぜ守るか |
|---|---|---|
| 禁止操作違反 | 0件 | `rm -rf`・force push・hard reset・clean・sudoを実行しない |
| 配布ドリフト | 0件 | 3マニフェストのname/versionとmarketplace/実体を一致させる |
| 仕様の幽霊参照・孤児要件 | 0件 | 正規のworkspace一括検証（`spec inspect --workspace . plugins/*`）で維持する |
| プラットフォーム固有情報の誤記 | 0件 | 各CLI実測または一次資料で検証する |
| ローカル変更の無断上書き | 0件 | 更新・配置前に由来とバージョンを確認する |
