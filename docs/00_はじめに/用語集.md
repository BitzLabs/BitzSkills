# 用語集

## 用語

### マーケットプレイス
- **定義**: このリポジトリのルートが指す配布単位。`.claude-plugin/marketplace.json` が
  `plugins/` 配下の各プラグインを列挙し、Claude Code / Codex CLI が
  `marketplace add` でこのリポジトリごと登録する。
- **使い分け**: 「プラグイン」は個々の機能単位、「マーケットプレイス」はそれらをまとめて
  配布するリポジトリ全体を指す。

### プラグイン
- **定義**: `plugins/<name>/` 配下の1フォルダ。3つのマニフェスト
  （`.claude-plugin/plugin.json` / `plugin.json` / `.codex-plugin/plugin.json`）と
  `skills/` を持ち、単独でインストール・バージョン管理できる単位。
- **使い分け**: 「スキル」はプラグイン内の個別機能。1プラグインは複数スキルを含む。

### スキル（Agent Skill）
- **定義**: `SKILL.md` を中心にしたフォルダ単位の自己完結した能力定義。
  [Agent Skills](https://agentskills.io/specification) オープン標準に準拠する。
- **使い分け**: 他スキルの `references/` を相対参照しない（連携はスキル名の言及に限る）。

### SDD（仕様駆動開発）
- **定義**: 探索→設計→実装→検証→報告を仕様（`.spec/`）で追跡しながら進める開発様式。
  本リポジトリでは `bitz-sdd` プラグインが提供する。
- **由来/文脈**: このリポジトリ自身の開発もSDD準拠で行う（ドッグフーディング）。

### `.spec`
- **定義**: 検証可能な契約・実行状態（EARS要件、設計成果物、タスク、STATE）を持つディレクトリ。
- **使い分け**: `docs/` は意図・WHY・人間向けWHATの層で、`.spec/` へは書き込まない
  （`docs/_conventions.md` 参照）。派生方向は `docs/` → `.spec/` の一方向。

### ガードレール
- **定義**: 危険操作の禁止・事前確認・検証義務からなる安全制約。
  `AGENTS.md` にナラティブとして書かれ、`.claude/settings.json` の permissions と
  各プラグイン同梱フックが機械的に強制する。
- **使い分け**: ナラティブ（AGENTS.md）と機械強制（settings.json / hooks）は別レイヤーで、
  緩めるときは両方を見直す。

### 司令塔／委譲
- **定義**: 最上位ティアのモデルが計画立案・検収・最終判断に徹し、定型作業や深い調査は
  下位ティアのサブエージェントへ委譲する運用モデル。
- **由来/文脈**: `CLAUDE.md` の委譲レジストリ（`deep-reasoner` / `fast-worker` 等）が
  Claude Code側の実装。Antigravity側は `bitz-env` の協調運用（委譲型・相談型・合議型）が担う。

### プロファイル
- **定義**: 用途別に組み合わせるプラグインの構成（標準開発・DDD拡張・軽量Git・スキル開発・
  プラグイン開発）。全プラグイン一括導入の代わりに使う最小単位。
- **由来/文脈**: `.spec/discovery/scope.md` の標準プロファイル表が正。

## ユビキタス言語のルール

- 同義語を新設しない（1概念1用語）。
