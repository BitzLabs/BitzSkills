# ペルソナ・ジャーニー

> 実利用の根拠は現在の管理者によるドッグフーディングが中心。詳細は
> `.spec/discovery/personas.md`（CORE-DSC-004）を正とする。共同開発者像は
> `[proto / 未検証]` とし、発言や感情を事実として捏造しない。

## 主要ペルソナ: BitzLabsの開発者・標準環境メンテナ

- **1行要約**: 複数のAIエージェントとモノレポ／個別リポジトリを開発し、標準自体も保守する。
- **文脈と行動**: 新しいリポジトリでの開発開始（J1）、エージェント／セッション切り替え時の
  規律引き継ぎ（J2）、標準規律の改善と配布（J3）、失敗時の局所的なやり直し（J4）、
  完了報告時の検証証跡提示（J5）。
- **Pains**: 環境別の仕様差、同じ規律の再説明、更新ドリフト、危険操作への不安。
- **Gains**: プラグイン導入だけで共通規律を再現し、機械検証で完了を判断できる。
- **生の声**: `TBD`（BitzSkillsリポジトリでのドッグフーディングが根拠。利用規模はn=1系統）。

## その他のペルソナ

| ペルソナ | 区分 | 1行要約 |
|---|---|---|
| BitzLabsの共同開発者 | served / `[proto / 未検証]` | 既存プロジェクトへ参加し、選択したAIエージェントで作業する |
| 実行主体としてのAIエージェント（Claude Code / Antigravity 2.0 / Codex） | システム参加者 | 明確な権限境界・段階的に読めるスキル・定型スクリプトを必要とする実行主体 |
| 既存の別組織標準で統制されているチーム | アンチペルソナ | BitzLabs規律を採用しない |
| OS／クラウド／IDE込みの端末プロビジョニングだけを求める利用者 | アンチペルソナ | 標準環境のスコープ外 |

## Jobs-to-be-Done

- J1（開始）: 新しいリポジトリで安全設定・Git規律・仕様検証方法を一から説明せず開始したい。
- J2（継続）: エージェント／セッション切り替え時も同じ契約と検証方法を引き継ぎたい。
- J3（変更）: 標準規律の改善をバージョン付きプラグインとして安全に配布・移行したい。
- J4（復旧）: 失敗時に禁止された破壊的操作に頼らず、変更を局所化してやり直したい。
- J5（監査）: 完了報告を自己申告ではなく検証コマンドの実出力で示したい。

## 優先順位付き機会

1. 標準プロファイルの導入手順を短く、3プラットフォームで同じ構造にする。
2. `AGENTS.md`・スキル・検証スクリプトの責務を明確にし、再説明を減らす。
3. 更新・doctor・migrationで導入後のドリフトを検知する。
4. 実利用プロジェクトが増えた時点で共同開発者ペルソナの仮説を検証する。
