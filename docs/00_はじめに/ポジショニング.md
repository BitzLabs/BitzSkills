# ポジショニング

> 詳細と根拠は `.spec/discovery/positioning.md`（CORE-DSC-005）を正とする。

## ポジショニング・ステートメント

AIエージェントと開発する **BitzLabsの開発者** にとって、**BitzSkills** は、
ガードレール、Gitフロー、仕様駆動開発、ドメイン設計、拡張ツールを用途別プロファイルで提供する
**標準エージェント開発環境** である。プロジェクトごとの手書き規約やプラットフォーム別設定と異なり、
同じ中核規律をバージョン付きプラグインとして3環境へ配布し、機械検証可能な証跡まで含める。

## キャンバス

1. **競合代替**: 各リポジトリでAGENTS.mdとプロンプトを都度作る／プラットフォーム別に設定を
   別々に整備する／汎用テンプレートをコピーする／都度「安全に」「テストして」と指示する。
2. **独自の属性**: BitzLabsの開発規律を実行可能な形（スキル・フック・スクリプト・マニフェスト・
   検証）で一体化し、3プラットフォームへ配布しながら仕様・実装・検証を追跡できる。
3. **価値（と証拠）**: 環境説明・再設定の重複が減り、規約ドリフトを検出できる。
   証拠は `release_check.py` / spec inspect / pytestの実出力（自己申告ではない）。
4. **ターゲットセグメント**: BitzLabsのリポジトリをAIエージェントと開発・保守する開発者。
5. **市場カテゴリ**: 「組織内AIエージェント開発標準のプラグイン・ディストリビューション」。
   外部市場規模や直接競合は未調査のため `TBD`。

## PoD / PoP

| 区分 | 属性 | 方針 |
|---|---|---|
| PoD | 実行可能な規律（スキル/フック/検証の一体化）と仕様・実装トレーサビリティ、3プラットフォーム共有 | 集中投資（防衛可能性: 少人数保守でも自己完結スキルとして横展開できる） |
| PoP | Git・テスト・ドキュメント・プラグイン導入の一般的な開発作法 | 効率よく同等に達する（過剰投資しない） |

## 崩壊クリティカルな差別化仮説

- H-D3（Desirability）: BitzLabsの開発者はSDDと権限分離を標準として受け入れる。
  現状は部分支持（n=1系統）。
- H-F1（Feasibility）: 同じ中核スキルを3プラットフォームへ配布し、機能差を明示して安全に
  劣化できる。現状は部分支持（配布は検証済み、`bitz-env`のCodex機械ガードは未対応 = `SI-ENV-023`）。

対応する仮説表は `.spec/discovery/assumptions.md`（CORE-DSC-006）。
