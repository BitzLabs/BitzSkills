# システム仕様

機能・非機能・制約の人間向け索引です。検証可能な契約の正本（EARS 受入基準・検証手段）は
`.spec/requirements/<ID>.md` です。本章では要件IDとその意味を人間語で一覧化するだけに留め、
本文はコピーしません。プラグイン単位でグルーピングします。

## bitz-sdd（仕様駆動開発の中核）

| ID | 概要 |
|---|---|
| CORE-FR-001 | `sdd-design` 成果物表で必須/任意（条件付き）を利用者が誤解なく読み取れるようにする |

| CORE-FR-004 | `spec_scaffold.py` による採番付き雛形生成（**廃止**。後継 SDD-FR-144 へ移行） |
| CORE-FR-005 | `spec_update.py` による status 遷移の権限強制と STATE.md 更新（**廃止**。後継 SDD-FR-143 へ移行） |
| CORE-FR-010 | `spec_scaffold.py` が frontmatter の統制語彙を生成時に検証し、DSN 種別を追加する |
| CORE-FR-011 | `scripts/spec` ラッパーが SDD ツールをバージョン非依存で解決し委譲する |

## リポジトリ共通規約（governance ドメイン）

frontmatter・マニフェスト・命名・整合性・コミット規約などリポジトリ全体に適用される規約です。

| ID | 概要 |
|---|---|
| CORE-CON-001 | プラグインの3マニフェスト（Claude Code / Antigravity 2.0 / Codex CLI）の version は常に同値 |
| CORE-CON-002 | 全スキルの SKILL.md frontmatter に metadata（version/author/created/updated）を必須化 |
| CORE-CON-003 | `marketplace.json` の `plugins[]` と `plugins/` ディレクトリ実体の双方向整合 |
| CORE-CON-004 | 各スキルはフォルダ単位で自己完結し、他スキルの `references/` を相対参照しない |
| CORE-CON-005 | プラグイン内のスキル名は単一プレフィックス（skill-* / sdd-* / ddd-* / plugin-* 等）で統一 |
| CORE-CON-006 | コミット・PRタイトルは Conventional Commits に従う（squash merge でマージコミットタイトルになる） |
| CORE-CON-007 | 委譲は無条件の善ではなく、往復コストが節約を上回る小さな単発タスクは委譲しない（損益分岐） |
| CORE-CON-008 | 全プラグイン共通のライフサイクルスキル標準名（init/doctor/update/uninstall） |
| CORE-CON-009 | `update` のバージョン移行（マイグレーション）機構 |
| CORE-CON-010 | version bump は変更を届ける同一PR内に配置する規約 |
