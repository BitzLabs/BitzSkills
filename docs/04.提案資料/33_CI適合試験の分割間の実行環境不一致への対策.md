# CI適合試験の分割間の実行環境不一致への対策

- 状態: `Closed`（2026-10-28、§4の推奨1・2を実施し、main で Gate A・Gate B の認定が通ることを確かめた。決定は ADR-069）
- 起草日: 2026-10-27
- 対象: `.github/workflows/ci.yml`、`fixtures/conformance/reports.py`、
  [ADR-056](../02.設計書/10_決定記録/ADR-056_適合試験の分割実行とCIのGate-B集約を確定する.md)
- 目的: GitHub の runner のイメージが入れ替わる間に、「Coreの適合試験」の集約が失敗し続けるのを防ぐ

## 1. 起きたこと

2026-10-27 に、PR BitzLabs/BitzSkills#384 と main への push（`dbf6adc1`）の両方で、「Coreの適合試験」の集約が
`分割間で実行環境が一致しません`で失敗した。適合試験の分割ジョブはすべて成功していた。

- 分割ジョブの runner の Git が、`git version 2.55.0`と`2.56.0`で混在していた（`ubuntu-24.04`のイメージの入れ替え中）。
- 集約（`fixtures/conformance/reports.py`の`merge_reports`）は、ADR-056 に従い、分割の間で`host_tool_versions()`
  （Python・uv・Git のバージョン）が完全に一致することを求める。
- 「Re-run all jobs」で全分割が同じイメージに当たったときだけ通った。「Re-run failed jobs」では、集約だけが
  2回目の実行になり、Gate B の集約（`tests/bitz-core/ci_gate_b.py`）が
  ``ワーカーのコミット・`runId`・実行条件が一致しません``で必ず失敗する。
- 失敗の文言には、どの値が違ったかが出ない。原因を特定するには、各ジョブのログから Git のバージョンを拾う必要があった。

## 2. 前提

- ADR-056 の一致の要求は、独立した実行の結果を同じ条件で比べるためのもので、弱めるべきではない。
- fixture の一部は Git のバージョンに依存する動作を固定している（`fixtures/conformance/runner.py`の`build_git_shim`）。
  Git の違いを比較から外すと、本当の違いを見落とす可能性がある。
- `runs-on: ubuntu-24.04`はイメージの版を固定しない。GitHub はイメージを段階的に入れ替えるので、同じ run の中でも版が混在しうる。

## 3. 案

| 案 | 内容 | 長所 | 短所 |
|---|---|---|---|
| A. 実行環境の固定 | 分割と集約のジョブを、digest で固定したコンテナ（Git・uv を含む）で実行する | 一致の要求を保ったまま、イメージの入れ替えの影響を受けない | コンテナの用意と、digest を更新する運用が要る |
| B. Git を明示的に入れる | 各ジョブの最初に、版を固定した Git を入れる | 変更が小さい | 配布元の版の固定が難しい。Python 以外の差（uv、OS のライブラリ）は残る |
| C. 比較を緩める | Git のパッチ番号の違いを許す | 変更が最小 | ADR-056 の改訂が要る。Git に依存する fixture の違いを見落とす |
| D. 運用で回避する | 失敗したら「Re-run all jobs」を待って再実行する | 変更なし | 入れ替えの期間は CI が赤いまま。再実行の手順を誤ると必ず失敗する |

## 4. 推奨

1. **すぐに行う（小さい変更）**: 集約の失敗の文言に、分割ごとに違った項目と値を出す。原因の特定がログを読まずに済む。
   `fixtures/`の変更なので、ADR-051 に従って Gate A を再認定する。
2. **本対策**: 案A（digest で固定したコンテナ）を採る。一致の要求を変えずに、原因そのものをなくせる。
   コンテナの digest を更新するときは、Core の単体試験・適合試験を通す（定義と digest の更新を分ける手順は ADR-069）。
3. 案Cは採らない。ADR-056 の目的（独立した実行の一致）と衝突する。

## 5. 判断が必要な点

- 案Aを採るか（採る場合、コンテナのイメージの置き場所と、digest の更新の頻度）
- 1（失敗の文言の改善）を先に行うか

## 6. 判断の記録

2026-10-27に利用者が判断を委任し、§4の推奨を採った。

- 失敗の文言の改善を先に行う（`fixtures/conformance/reports.py`）。
- 案Aを採る。イメージは GHCR（`ghcr.io/bitzlabs/bitzskills-ci`）に置き、Python・uv・Git のいずれかを上げる必要が
  生じたときに digest を更新する。定期の更新はしない。決定と手順は [ADR-069](../02.設計書/10_決定記録/ADR-069_適合試験のCIをdigestで固定したコンテナで実行する.md) に記録した。
- 2026-10-28: CI用のイメージを main で GHCR へ push し（`sha256:8a65a932…`）、適合試験の分割と集約を、
  そのdigestで指定したコンテナで実行するようにした（`.github/workflows/ci.yml`）。
- 2026-10-28: main（`899e0609`）への push の CI（run 40612556005）で、コンテナで実行した独立2組の8分割と集約、
  Gate B（`Passed`）、Gate A の認定が通った。
