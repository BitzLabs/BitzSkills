# EARS-AI 適合性・バージョン・移行仕様

## 1. 適合レベル

| レベル | 名称 | 条件 |
|---|---|---|
| C0 | Syntax | Markdownとタグを解析できる |
| C1 | Core | Core構文・意味規則に適合する |
| C2 | Profile | 宣言Profileに適合する |
| C3 | Trace | REQ、TECH、コード、テストを追跡できる |
| C4 | Verified | 対応する実行可能テストの結果が揃う |

「EARS-AI準拠」とだけ表示せず、Core版、適合レベル、Profile版を宣言する。

## 2. バージョン

- CoreとProfileは独立してセマンティックバージョニングする。
- 必須タグ追加、意味変更、削除、AST破壊はメジャー変更とする。
- 後方互換な任意タグやValidator追加はマイナー変更とする。
- 文言と実装不具合の修正はパッチ変更とする。
- Diagnostic正本スキーマへのフィールド追加はマイナー、必須化・削除・意味変更はメジャーとする。

## 3. 旧検討版

`01.検討資料/` の第2版、第3版、第5版は非規範の調査資料とし、正式版履歴へ含めない（[ADR-001](../../02.設計書/10_決定記録/ADR-001_EARS-AI旧検討版の位置づけ.md)）。正式規格の履歴はCore 1.0.0から開始する。

```text
EARS-AI Core 1.0.0
EARS-AI SDD Profile Deferred Draft
EARS-AI Quality Profile Deferred Draft
EARS-AI DDD Profile Deferred Draft
```

## 4. 主要移行

| 旧表現 | 正式表現 | 自動変換 |
|---|---|---|
| ACTORが承認者を表す | 承認者をFrontmatterへ移す | 不可（人間確認） |
| THENだけで必須を表す | `[MUST] [THEN]` | 可 |
| GENERATEだけでAI処理 | 規範強度を併記 | 不可（強度の判断が必要） |
| `STATE` | SDD Profileの正式化まで未移行 | 不可 |
| `AGGREGATE_ROOT` | `[ddd:AGGREGATE_ROOT=...]` | 可 |
| `THRESHOLD` | `[quality:THRESHOLD=...]` | 可 |
| `GATE` | Core 1.0では移行対象外 | 不可 |
| 3階層ID（`REQ-001:AC-01:R-01`） | 2階層IDへ分割 | 不可（[ADR-005](../../02.設計書/10_決定記録/ADR-005_規範文IDの階層と記法.md)） |
| 親子分割記法 | 発動条件を繰り返した複数の規範文 | 不可（人間確認） |
| 全行へID付与 | 規範文だけにIDを付ける | 可 |
| `EAI-DDD-*` 診断コード | `BD-*` | 可 |

## 5. 移行処理

1. 旧文書を読み取り専用で解析する。
2. 曖昧なタグ用途を一覧化する。
3. 決定論的な部分だけ提案パッチへ出す（§4の「自動変換: 可」のみ）。
4. 意味が重なる箇所を人間へ確認する。
5. C0/C1と利用Profileを再検証する。
6. 元文書と提案diffをGitで確認できるようにする。

移行ツールはdry-runを既定とする。自動変換不可の項目を勝手に変換してはならない。

旧Profile表現は、該当Profileが正式実装されるまでCoreへ自動変換しない。Core構文として決定論的に変換できる部分だけを対象とする。
