# EARS-AI 拡張プロファイル仕様 1.0

## 1. 目的

ProfileはCoreを変更せず、プラグイン固有の語彙、制約、検証、投影処理を追加する。

## 2. 名前空間

```text
[<namespace>:<TERM>]
[<namespace>:<TERM>=<value>]
```

| 拡張候補 | 名前空間 | 診断OWNER |
|---|---|---|
| SDD Profile | `sdd` | `BS` |
| Quality Profile | `quality` | `BQ` |
| DDD Profile | `ddd` | `BD` |

Coreだけが名前空間なしの予約タグを定義できる。診断コードのOWNERセグメントは所有拡張のものを用い、`EAI`はCoreのみが使用する（[ADR-011](../../02.設計書/10_決定記録/ADR-011_Diagnostic所有者とコード命名規約.md)）。

## 3. Profile Manifest

```yaml
id: "bitz-ddd"
namespace: "ddd"
diagnosticOwner: "BD"
profileVersion: "1.0.0"
requiresCore: ">=1.0.0 <2.0.0"
vocabulary: "vocabulary/ears-ai-ddd.yaml"
schema: "schemas/ears-ai-ddd.schema.json"
validators:
  - "validators/aggregate-boundary"
serializer: "serializers/ears-ai-ddd"
migrations: "migrations/"
```

プロジェクトは `.spec/bitz.yaml` の `earsAi` でEARS-AI Coreの利用メジャー版を指定する。Profileの利用版は同じファイルの `profiles` で宣言する。Core 1.0では `profiles` を予約キーとして保持するだけで、互換性判定へ使用しない（[bitz.yaml仕様](../02_SPECファイル規定/02_bitz.yaml仕様.md) §3）。設定変更は通常のGit diffとして管理する。

## 4. 拡張種別

- `qualifier`: Core文へ文脈を追加する。
- `reference`: 他仕様、証跡、成果物を参照する。
- `declaration`: DDD要素などを宣言する。
- `control`: SDD状態遷移などを制御する。
- `assertion`: 品質条件と評価方法を定義する。

## 5. 競合規則

- Coreタグの名称、意味、順序、既定値を再定義しない。
- 他Profileの名前空間へタグを追加しない。
- 他Profileの語彙を自Profileの検証規則の前提にしない。例外は設けない。Profileは所有プラグインが提供するため、Profile間の依存は拡張プラグイン間の必須依存と同義になり、[ADR-016](../../02.設計書/10_決定記録/ADR-016_Agent-Plugins準拠の複数プラグイン配布.md)が禁止した構成になる。
- 複数Profileで共有が必要な語彙が実際に生じた場合は、Coreの公開語彙へ昇格させるか、各Profileが自己完結して定義する。Profile Manifestに依存宣言を置かない。
- 未宣言プロジェクトへ必須条件を追加しない。

## 6. 未知拡張

- Parserは未知拡張をASTへ保持する。
- 通常モードは `warning`、厳格モードは `error` とする。
- Serializer、Migration、自動修復は未知拡張を削除しない。

## 7. Validator契約

Profile Validatorは共通ASTを入力し、`bitz-core` が所有するDiagnosticスキーマに従う診断を返す（[01_共通アーキテクチャ.md](../../02.設計書/01_共通アーキテクチャ.md) §6）。Profile独自の診断型を定義してはならない。Markdownを独自に再解析してはならない。

```json
{
  "code": "BD-AGG-001",
  "severity": "error",
  "summary": "集約内部Entityへの外部からの直接操作です",
  "source": {"path": ".spec/technical/TECH-001.md", "line": 31, "column": 3},
  "specRefs": ["TECH-001:SPEC-04"],
  "extensions": {
    "bitz-ddd": {
      "profile": "bitz-ddd@1.0.0",
      "boundedContext": "Sales",
      "aggregateRoot": "Order"
    }
  }
}
```

- 人間向け要約のフィールド名は `summary` とする。`message` は使用しない。
- 対象規範文は `specRefs` の配列で表す。単一でも配列とする。
- Profile固有情報は `extensions.<plugin-id>` 配下に置き、正本スキーマへフィールドを追加しない。
