# 配置・命名・探索規則

## 1. ワークスペースの決定

`bitz`は、指定パスまたは現在ディレクトリから親方向へ探索し、最初に見つかった
`.spec/bitz.yaml`の親ディレクトリをワークスペースルートとする。ただしGitリポジトリ境界を越えない。

- `.spec/bitz.yaml`が複数候補になる場合は、最も近いものだけを使用する。
- Gitリポジトリ内で見つからない場合は`blocked`とする。
- Core 1.0は複数ワークスペースを1回の操作で束ねない。
- シンボリックリンクを辿ってワークスペース外のSPECを読み込まない。

## 2. 標準構造

```text
.spec/
├── bitz.yaml
├── requirements/
│   └── REQ-001-user-login.md
├── technical/
│   └── TECH-001-token-storage.md
├── decisions/
│   └── ADR-001-token-format.md
├── tasks/
│   └── TASK-001-login-endpoint.md
└── reports/
    └── 20260825T103000Z-verify.json
```

必須なのは`.spec/bitz.yaml`と、1件以上の要求がある場合の`requirements/`だけである。
`technical/`、`decisions/`、`tasks/`、`reports/`は必要になった時点で作成する。

## 3. 探索対象

| パス | 種別 | 形式 | `bitz check` |
|---|---|---|---|
| `.spec/bitz.yaml` | 設定 | YAML | 常に検査 |
| `.spec/requirements/**/*.md` | 要求 | Markdown | 検査 |
| `.spec/technical/**/*.md` | 技術仕様 | Markdown | 検査 |
| `.spec/decisions/**/*.md` | 設計判断 | Markdown | 検査 |
| `.spec/tasks/**/*.md` | 一時タスク | Markdown | 存在時に検査 |
| `.spec/reports/*.json` |実行結果 | JSON | 入力として検査しない |

`.spec/`直下の未知のファイルまたはディレクトリは警告に留める。Core 1.0は隠しファイル、
一時ファイル、Markdown以外の成果物を暗黙に仕様として読み込まない。

## 4. ID

| 種別 | ID形式 | 例 |
|---|---|---|
| 要求 | `REQ-[0-9]{3,}` | `REQ-001` |
| 技術仕様 | `TECH-[0-9]{3,}` | `TECH-012` |
| 設計判断 | `ADR-[0-9]{3,}` | `ADR-004` |
| タスク | `TASK-[0-9]{3,}` | `TASK-023` |

- IDはワークスペース内で大文字・小文字を区別して一意とする。
- 削除したIDを別の意味で再利用しない。
- 採番の連続性は要求しない。欠番は正常とする。
- IDは意味を持たない安定識別子とし、ディレクトリ移動後も変更しない。

## 5. ファイル名

正規ファイル名は`<ID>.md`または`<ID>-<slug>.md`とする。`slug`は小文字ASCII英数字とハイフンだけを
推奨するが、日本語ファイル名をエラーにはしない。ファイル名先頭のIDとFrontmatterの`id`が異なる場合は
エラーとする。

ファイル名は識別の補助であり、参照解決にはFrontmatterの`id`を使用する。大文字・小文字だけが異なる
ファイル名を作らない。

## 6. パス表現

- SPEC内に記録するパスはワークスペースルート相対とする。
- 区切り文字は全OSで`/`へ正規化する。
- 絶対パス、`..`によるルート外参照、NUL文字を禁止する。
- Git管理外の生成物や依存キャッシュを`implements`または`tests`へ指定しない。
- パス比較は実ファイルシステムの大文字・小文字規則に依存せず、正規化後の文字列で行う。
