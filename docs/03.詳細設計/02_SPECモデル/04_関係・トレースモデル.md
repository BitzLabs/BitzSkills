# 関係・トレースモデル

## 1. 所有範囲

本書はID解決、型付き関係、適用可能性、完全閉包、path、句単位coverageを定義する。
操作ごとの起点入力、Git対象選択、process実行は各操作仕様が所有する。

## 2. 最小trace

```text
REQ/TECH statement
  ├── relations ----> 前提、refinement、後継
  ├── implements ---> 実装file
  ├── tests.covers -> test file
  └── command ------> bitz.yaml command

TASK
  ├── addresses ----> 対象statement / 規範文なしTECH
  ├── requires -----> 前提SPEC/TASK
  └── changes ------> 許可変更path
```

別のtrace台帳を作らない。code symbol、test assertionの意味的充足はCore 1.0の対象外とする。

## 3. 関係

| relation | 意味 | 強さ |
|---|---|---|
| `requires` | sourceの解釈・実行前提 | strong |
| `refines` | sourceがtargetを具体化・制約 | strong |
| `addresses` | TASKが対象句または規範文なしTECHを実装 | strong |
| `supersedes` | sourceが同種の旧文書を置換 | strong |
| `related` | 閲覧用関連 | weak |

強い関係の参照切れ、型違反、禁止循環はfailedとする。`related`は閉包を増やさず、参照切れをwarningとする。

## 4. 型制約

| source | relation | target |
|---|---|---|
| REQ | `requires` | REQ、TECH、accepted ADR |
| REQ | `refines` | REQまたはREQ statement |
| REQ | `supersedes` | REQ |
| TECH | `requires` | REQ、TECH、accepted ADR |
| TECH | `refines` | REQ、TECHまたはそのstatement |
| TECH | `supersedes` | TECH |
| ADR | `requires` | REQ、TECH、accepted ADR |
| ADR | `supersedes` | ADR |
| TASK | `requires` | REQ、TECH、TASK、accepted ADR |
| TASK | `addresses` | REQ/TECH statement、規範文なしTECH |
| 全種別 | `related` | 任意文書 |

`requires`と`refines`を合わせた意味依存graph、`supersedes`連鎖、TASK間`requires`の循環を禁止する。
`related`循環は許可し探索しない。

## 5. ID解決と索引

Coreは全SPECの軽量Frontmatterを1回走査し、次を構築する。

- 文書IDと規範文IDの正引き索引
- relationの正引き・逆引き
- `implements`のpath逆引き
- `tests[].path`のpath逆引き
- statementごとのtest coverage

同じIDが複数fileに解決すればfailedとする。`reports/`、通常`docs/`、Issue、URLをID解決対象にしない。

## 6. purpose別の閉包

### 6.1 `interpret`

1. 起点所有文書を含める。
2. `requires`を終端まで辿る。
3. `refines` targetを含める。
4. targetをrefineするapplicable文書を逆参照で含め、その`requires`を辿る。
5. 置換済み起点は旧文書をadvisory、後継をreplacementとして示す。
6. `related`、TASK、code、testを自動追加しない。

### 6.2 `implement`

`interpret`に加えて次を含める。

- 起点とapplicable refinementの対象句
- 対象句を`addresses`するopen TASK
- 起点TASKの`addresses`と`requires`閉包
- `implements`、test対応、TASK `changes`
- statementごとのaddressed/tested状況

起点TASKの`requires`先TASKがすべてdoneでなければblockedとする。

### 6.3 `verify`

`interpret`に加えて対象statementのtest対応、command、実装pathを含める。TASKは起点指定時だけ含める。
done TASKは再検証でき、cancelled TASKはblockedとする。

## 7. 決定論的探索

1. 全IDと関係の軽量索引を作る。
2. 型、状態、強い関係、循環を検査する。
3. 起点をID辞書順に正規化する。
4. purpose規則で完全閉包を計算する。
5. 文書をroot、requirement、constraint、refinement、replacement、work、advisoryへ分類する。
6. 最短距離、種別順REQ/TECH/ADR/TASK、ID辞書順で並べる。
7. statementを文書順、source line、ID順で並べる。

同一文書が複数経路から到達しても1回だけ収録し、到達edgeを保持する。visited setで循環を隠さない。

## 8. coverage

target statement集合は起点により決める。

- REQ/規範文ありTECH文書ID: 所有する全statementとapplicable refinement
- statement ID: 指定句と直接applicable refinement。兄弟句は`adjacent`
- TASK: `addresses`句と`requires`閉包
- 規範文なしTECH: statement集合は空で文書単位test bindingを保持

| modality | `implement` | `verify` |
|---|---|---|
| `MUST` | 未addressed・未testedをwarning | 未testedが1件あればblocked |
| `SHOULD` | 未対応をwarning | 未testedをwarning |
| `MAY` | 情報 | 情報 |

coverageは`must`、`should`、`may`ごとに`total`、`addressed`、`tested`、`unaddressed`、`untested`を持つ。
test対応は対象宣言であり、assertionの十分性を保証しない。

## 9. path

`implements`と`tests[].path`は通常fileとして存在することを検査する。draftの未作成予定はwarning、approvedは
errorとする。rejected文書のpathは履歴であり存在を要求しない。

`changes`はfile pathと末尾`/`directory prefixを許可し、対象自体の存在を要求しない。すべてworkspace内に限る。

## 10. 状態と閉包

applicableでない文書を強い依存が要求する場合、閉包全体をblockedとする。advisory文書は別区分で提示し、
規範として適用しない。Coreは後継へ暗黙に起点を差し替えない。同じ旧文書に複数の有効な後継があればfailedとする。

## 11. Diagnostic

| code | result | 条件 |
|---|---|---|
| `SPEC-ID-DUPLICATE-001` | failed | 文書IDまたはstatement ID重複 |
| `SPEC-RELATION-LEGACY-001` | failed | 旧`refs`使用 |
| `SPEC-RELATION-MISSING-001` | failed | strong target不在 |
| `CTX-RELATION-TYPE-001` | failed | source/target型不正 |
| `CTX-CYCLE-001` | failed | 禁止循環 |
| `CTX-TASK-DEPENDENCY-001` | blocked | 起点TASKの先行TASKが未完了 |
| `CTX-STATE-001` | blocked | 起点・強い依存先がpurposeに適用不能 |
| `CTX-STATE-SUPERSEDED-001` | blocked | 起点・依存先が置換済み |
| `CTX-STATE-SUPERSEDED-002` | failed | 有効な後継が複数 |
| `CTX-COVERAGE-TASK-001` | passed_with_warnings | implement対象MUSTが未addressed |
| `CTX-COVERAGE-TEST-001` | warning／blocked | implementではwarning、verifyではblocked |
