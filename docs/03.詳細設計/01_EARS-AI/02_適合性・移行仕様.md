# EARS-AI適合性・移行仕様

## 1. 適合level

| level | 名称 | 条件 |
|---|---|---|
| C0 | Syntax | Markdownとtagを解析できる |
| C1 | Core | Core構文と意味軸に適合する |
| C2 | Trace | REQ、TECH、code、testを追跡できる |
| C3 | Verified | 対応testの実行結果が揃う |

「EARS-AI準拠」とだけ表示せず、Core versionと適合levelを宣言する。Profile levelはCore 1.0に含めない。

## 2. version

- CoreはSemantic Versioningを使用する。
- 必須tag追加、意味変更、削除、IR破壊はmajor変更とする。
- 後方互換な任意field追加はminor変更とする。
- 文言と実装不具合の修正はpatch変更とする。
- Diagnostic必須fieldの追加・削除・意味変更はmajor変更とする。

## 3. 旧検討版

`docs/01.検討資料`の旧版は非規範の調査資料とし、正式履歴へ含めない。正式規格はCore 1.0.0から開始する。

## 4. 主な移行

| 旧表現 | 正式表現 | 自動変換 |
|---|---|:--:|
| ACTORが承認者 | actorを実行主体へ修正 | No |
| THENだけで必須 | `[MUST] [THEN]` | Yes |
| GENERATEだけでAI処理 | 規範強度を追加 | No |
| 3階層ID | 独立した2階層IDへ分割 | No |
| 親子分割 | 発動条件を繰り返す複数文 | No |
| 全行へID | 規範文だけにID | Yes |
| Profile固有tag | opaque extensionとして保持 | 変換しない |

## 5. 移行処理

1. 旧文書を読取り専用で解析する。
2. 曖昧なtag用途を一覧化する。
3. 決定論的な部分だけ提案patchへ出す。
4. 意味判断が必要な箇所を人間へ提示する。
5. C0/C1を再検証する。
6. 原文と提案diffをGitで確認できるようにする。

dry-runを既定とし、自動変換不可の項目を変更しない。Profile Manifestがないため、opaque extensionを
別語彙へ自動変換しない。
