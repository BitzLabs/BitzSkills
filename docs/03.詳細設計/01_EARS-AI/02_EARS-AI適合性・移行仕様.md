# EARS-AI適合性・移行仕様

## 1. 適合レベル

| レベル | 名称 | 条件 |
|---|---|---|
| `C0` | Syntax | Markdownとタグを解析できる |
| `C1` | Core | Coreの構文と意味軸に適合する |
| `C2` | Trace | REQ、TECH、コード、テストを追跡できる |
| `C3` | Verified | 対応するテストの実行結果が揃う |

「EARS-AI準拠」とだけ表示せず、Coreのバージョンと適合レベル（conformance level）を宣言する。
プロファイルレベル（プロファイルへの適合を表す適合レベル）はCore 1.0に含めない。

## 2. バージョン

- Coreはセマンティックバージョニング（Semantic Versioning）を使用する。
- 必須タグの追加、意味の変更、削除、意味中間表現の破壊は、メジャーバージョンの変更とする。
- 後方互換の任意フィールドの追加は、マイナーバージョンの変更とする。
- 文言と実装の不具合の修正は、パッチバージョンの変更とする。
- 診断の必須フィールドの追加、削除、意味の変更は、メジャーバージョンの変更とする。

## 3. 旧検討版

`docs/01.検討資料`の旧版は非規範の調査資料とし、正式履歴へ含めない。正式規格はCore 1.0.0から開始する。

## 4. 主な移行

| 旧表現 | 正式表現 | 自動変換 |
|---|---|:--:|
| `ACTOR`が承認者 | `ACTOR`を実行主体へ修正 | 不可 |
| `THEN`だけで必須 | `[MUST] [THEN]` | 可 |
| `GENERATE`だけでAI処理 | 規範強度を追加 | 不可 |
| 3階層ID | 独立した2階層IDへ分割 | 不可 |
| 親子分割 | 発動条件を繰り返す複数文 | 不可 |
| 全行へID | 規範文だけにID | 可 |
| プロファイル固有のタグ | 不透明な拡張タグとして保持 | 変換しない |

## 5. 移行処理

1. 旧文書を読取り専用で解析する。
2. 曖昧なタグの用途を一覧化する。
3. 決定論的な部分だけを、提案パッチへ出す。
4. 意味判断が必要な箇所を人間へ提示する。
5. `C0`／`C1`を再検証する。
6. 原文と提案差分をGitで確認できるようにする。

ドライランを既定とし、自動変換できない項目を変更しない。プロファイルマニフェストがないため、
不透明な拡張タグを別の語彙へ自動変換しない。
