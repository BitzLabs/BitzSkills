# Core実行環境・CLI基盤契約

## 1. 対象

本書は、Core 1.0の配布物、実行環境、CLIの引数列の共通の解析を規定する。各操作が受け付けるオプション、対象、排他関係は、
各操作仕様を正とし、本書と組み合わせて適用する。判断の理由はADR-045、ADR-053、ADR-055に残すが、実装と適合の判定には本書を使う。

## 2. 実行環境と配布物

- Core 1.0はCPython 3.12以上を対象とする。実装には、3.12で使える構文と標準ライブラリのAPIだけを使う。
- Core 1.0の対象OSはPOSIX系のLinuxとmacOSとする。Windowsは対象外とし、WSL上での利用を案内する。
  適合の確認はLinuxで行い、Core 1.0はmacOSでの動作を検証しない（ADR-055）。
  安全性の保証に必要なOSの機能（ディレクトリのファイルディスクリプターを基準にしたファイル操作、`O_NOFOLLOW`、プロセスグループへのシグナル）が
  使えない環境では、保証を弱めた代替の動作へ切り替えない。明示的なレポートの保存は書き込まずに診断`SPEC-REPORT-WRITE-001`を返す。
- PyPIの配布物名、`import`するパッケージ名、CLIの実行体名は、すべて`bitz`とする。
- Agent Pluginsの経路でのプラグインのIDは`bitz-core`と`bitz-sdd`とし、`bitz-core`がCLIを同梱するか参照する。
  どの配布経路でも、利用者が起動するコマンドは`bitz`である。
- ランタイムの依存は、Python標準ライブラリと、1つのYAML解析ライブラリだけに限る。YAML解析ライブラリはロックファイルで厳密なバージョンへ固定し、
  公開物をソースのコミットとビルドの手順に対応付ける。Coreは通常の操作の中で依存を取得または更新しない。
- 下限のバージョン、配布物名、ランタイムの依存の追加・削除は、Coreのマイナーバージョン以上の変更として扱い、パッチリリースでは変更しない。

## 3. YAMLのローダー

YAML解析ライブラリは、YAML 1.2を解釈できる安全な読取り専用のローダーとして使い、任意のオブジェクトの構築やコードの実行を許可しない。
Coreは、値をスキーマへ渡す前に、カスタムタグ、アンカー、エイリアス、マージキー、複雑なキー、複数のYAMLドキュメント、重複したマッピングキーを
明示的に拒否する。タイムスタンプ、`yes`／`no`、先頭の`0`を、ライブラリの既定の日時、真偽値、8進数へ暗黙に変換しない。
受け入れるスカラーと入力ごとの構造は、ワークスペース・設定仕様とフロントマター仕様を正とし、ライブラリの既定の挙動を仕様の代わりにしない。

## 4. Git

Gitは2.30以上を対象とし、CLIの実行体を引数列で直接起動する。シェル、libgit2を呼び出すライブラリ、Gitの機能を独自に再実装したものを使わない。
Gitの版は`git --version`を起動し、標準出力の1行目を`git version <major>.<minor>[.<残り>]`として解析する。
`major`と`minor`はASCIIの数字だけから成る十進の整数として数値で比較し、`<残り>`は比較に使わない。終了コードが0以外の終了、または解析できない出力は
実行できないものとして扱う。
下限に満たない、`PATH`から解決できない、または実行できないGitは、Git不在（Git absent）として、共通の縮退の契約を適用する。複合ワークスペースでの操作では
診断`SPEC-MULTI-GIT-001`（`blocked`）とする。Coreの通常の操作はネットワークへ接続せず、Gitにもネットワークの操作を要求しない。

## 5. CLIの引数列の共通の解析

CLIは、操作固有の処理、ワークスペースの探索、ファイルの読取りより前に、引数列を検査する。公開構文に記載したロングオプションだけを受け付け、
未知のオプション、オプションの値の不足、許可されない値、排他の違反は終了コード4とする。オプション名と値は別々の引数列の要素で渡し、
`--format=json`のような`--name=value`形式、短縮オプション、暗黙の環境変数または設定ファイルによるCLIのオプションの追加は受け付けない。

値を1つ取るオプションと、値を取らないフラグは、1回の起動につき各1回までとし、同じ値であっても重複した指定は終了コード4とする。
反復可能なのは、公開構文で`...`を付けた`context --expand`と`doctor --require-capability`だけである。
反復可能なオプションの同じ値は、入力の順によらず1件へ重複排除し、操作仕様が定める並べ替えの規則を適用する。

空文字列の位置引数と、空文字列のオプションの値は、省略として扱わず、終了コード4とする。空白だけの値も、該当するID、パス、列挙値、
バージョンまたは範囲の構文に一致しないため、終了コード4とする。`context`は1件以上の起点を必須とする。`check`と`verify`の
位置引数0件は、各仕様が定める引数なしの操作であり、空文字列1件とは異なる。

`verify --timeout`は、ASCIIの数字だけから成る十進の表記で、先頭に`0`を含まない`1`から`3600`までを受け付ける。符号、小数、指数表記、
桁区切り、前後の空白は終了コード4とする。

## 6. 対象とワークスペースの不在

対象の字句または種別が、操作の公開構文に適合しない場合は、終了コード4とする。構文上は正しい文書ID、規範文ID、または許可された仕様文書のパスが
カタログに存在しない場合は、操作を開始したうえで、診断`CTX-ROOT-MISSING-001`（`failed`）を返す。
複数の対象のうち一部だけが不在であっても、操作仕様が定める継続単位に従う。`check`は既知の対象の検査を続け、`verify`は独立した既知の対象ごとの
結果を保持する。`context`は、すべての起点を1つのコンテキスト一式として扱うため`failed`とし、既知の起点だけのコンテキスト一式を完全解決として返さない。

`--workspace`は、CLIが解決の基準とする値そのものなので、構文上は正しくてもカタログに存在しない値は終了コード4とし、操作の結果を作らない。
`context --expand`は対象ではなく提示形式の指定であり、完全解決した集合の外であれば診断`CTX-PROJECTION-001`（`failed`）とする。

## 7. `--report`フラグ

`--report`は値を取らない真偽値のフラグで、`check`と`verify`だけが受け付ける。任意の保存パスをCLIから指定する機能はCore 1.0に含めず、
`--report=<path>`は未知のオプションの形式として終了コード4とする。保存ディレクトリとファイル名、排他的な作成、失敗時の処理は、
結果・診断・終了コードの仕様が定めるレポートの契約に従う。`--format json`は`--report`を含意せず、両者は排他ではない。
