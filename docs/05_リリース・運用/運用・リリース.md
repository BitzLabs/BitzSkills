# 運用・リリース

このリポジトリはSaaSやサーバーを運用するappではなく、`plugins/` 配下の
プラグイン・スキルをマーケットプレイス `bitzskills` 経由で配布する library である。
「運用」とは稼働監視ではなく、バージョン管理・リリース前検証・配布経路の維持を指す。

## バージョン管理

- プラグインごとに3つのマニフェストが常に同じ `version` を持つ:
  `plugins/<name>/.claude-plugin/plugin.json`（Claude Code）、
  `plugins/<name>/plugin.json`（Antigravity 2.0）、
  `plugins/<name>/.codex-plugin/plugin.json`（Codex CLI）
- bumpは手作業で3ファイルを揃えず、必ず
  `python3 scripts/bump_version.py <plugin名> [major|minor|patch]` を使う
  （semverの整合と、配下スキルの `metadata.updated` 陳腐化の警告を機械的に担保する）
- スキル（SKILL.md）の内容を変更したらそのスキル自身の `metadata.version` をsemver bumpし、
  併せて所属プラグインの `version` も bump する

## リリース前検証

マージ前に以下を実行し、実出力をPR本文に貼る（自己申告ではなく実行結果で示す）:

1. `pytest tests/ -q`
2. `python3 scripts/release_check.py`
   （version整合・marketplace整合・frontmatter必須項目・委譲レジストリ整合・依存グラフ・
   対訳辞書SSOT・フェーズ正規語彙を一括検査。全PASSでexit 0）
3. `.spec/` を変更した場合は `python3 scripts/spec inspect --workspace . plugins/* --check-only`
   （作業ブランチでは `--check-only` を既定とし、`inspection-report.md` の差分をコミットしない。
   レポート更新は全PR統合後の締め工程で1回だけ行う）

CI（`.github/workflows/ci.yml`）はPRタイトルのConventional Commits検査、
`pytest tests/ -v`、`release_check.py` を強制する。ローカルでの事前実行はCI red回避のため。

## ブランチ運用とマージ

- `main` への直接コミットは行わない。変更は必ずブランチを切って行う
- PRは squash merge とし、マージコミットのタイトル = PRタイトル
  （PRタイトルもConventional Commits準拠。CIが機械検査する）
- 1 PR = 1関心事。`git revert` で丸ごと戻せる粒度を保つ。version bumpは同一PR内に含める
  （実装コミットに同梱、またはbump単独コミットでもよく位置は問わない）

## 配布・更新（3プラットフォーム）

配布経路は2系統（詳細は
`plugins/skill-creator/skills/skill-packager/references/platform-paths.md` が正）:

- **プラグイン一括インストール（推奨）**: マーケットプレイス `bitzskills`
  （ルートの `.claude-plugin/marketplace.json`）経由。
  Claude Code は `/plugin marketplace add` → `/plugin install <plugin名>@bitzskills`、
  Antigravity 2.0 は `agy plugin install`、Codex CLI は
  `codex plugin marketplace add` → `codex plugin add <plugin名>@bitzskills`
- **スキル単体の直接配置**: `skill-packager` が各プラットフォームのパス
  （`.claude/skills/`・`.agents/skills/`・`~/.gemini/config/skills/` 等）へ
  コピー／シンボリックリンクする。リポジトリ外への書き込みはユーザーの事前承認が必要

新プラグイン追加時は `.claude-plugin/marketplace.json` の `plugins[]` にエントリを追加し、
`release_check.py` の marketplace整合チェックに通す（手順は `AGENTS.md`「新しいプラグインの
追加手順」）。

## ロールバック

デプロイやSLOという概念を持たないため、ロールバックは基本的に `git revert` で
該当PRを1つ戻すことに限定される。version bumpも同一PRに含まれるため、revertだけで
マニフェストと内容の両方が整合した状態に戻る。破壊的操作
（`git push --force`／`git reset --hard`／`git clean -f` 等）は使わない。
