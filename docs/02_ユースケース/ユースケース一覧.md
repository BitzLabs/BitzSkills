# ユースケース一覧

利用者（BitzLabs の開発者、およびその指示で動く Claude Code / Antigravity 2.0 / Codex）と
システムの対話への索引です。個別ユースケース文書はまだ作らず、一覧・概要・関連要件IDの
トレースに留めます。各ユースケースの実行手順は、対応するプラグインのスキル
（`plugins/<plugin名>/skills/`）と各プラグインの README が正です。

## UC-001: Web アプリを仕様駆動でゼロから作る

- **誰が**: 通常開発の担当者
- **使うもの**: bitz-sdd
- **概要**: discovery（ビジョン・スコープ確立）→ design（アーキテクチャ・API・データ層）→
  review（多観点レビュー）→ implement/test（要件IDに紐づく実装とEARS由来テスト）まで
  一気通貫で仕様駆動開発を回す。
- **関連要件**: CORE-FR-001, CORE-FR-003, CORE-FR-011

## UC-002: 既存システムのリファクタリング判断（ブラウンフィールド）

- **誰が**: 既存コードの保守担当者
- **使うもの**: bitz-ddd + bitz-sdd
- **概要**: DDD 12基準と MMI 4軸でコードベースを採点し、移行準備度と改善優先度を出す。
  結果は `sdd-design` の再設計工程へ接続する。
- **関連要件**: TBD（bitz-ddd 固有の EARS 要件は本リポジトリの `.spec/requirements/` に未起票）

## UC-003: 本格的な DDD でドメインを設計する

- **誰が**: ドメイン設計担当者
- **使うもの**: bitz-ddd + bitz-sdd
- **概要**: ドメインストーリー（ハッピーパス）→ 2パスモデリングで Entity/Value
  Object/Aggregate と境界づけられたコンテキストを確立し、トランザクション境界を
  `sdd-data` の永続化戦略へ引き継ぐ。
- **関連要件**: TBD（同上）

## UC-004: 複数エージェントで並列開発する

- **誰が**: 複数のAIエージェントを並列運用する開発者
- **使うもの**: bitz-sdd（sdd-implement + sdd-git）
- **概要**: タスクを `implements`/`depends_on`/`boundary` で分解し、依存が無く境界が
  互いに素なタスク群だけを worktree 並列（1エージェント=1worktree=1ブランチ）で投入する。
  失敗時は worktree ごと破棄し再投入する。
- **関連要件**: CORE-FR-006, CORE-FR-007, CORE-FR-008, CORE-FR-016

## UC-005: チーム開発を GitHub Issue 駆動で回す

- **誰が**: チーム・公開リポジトリの開発者
- **使うもの**: bitz-sdd（sdd-git）/ bitz-flow
- **概要**: spec-issue の提案を GitHub Issue 化し、`feat/<issue#>-<slug>` ブランチ →
  Draft PR → CI（テスト + spec_inspect）→ レビュー → squash merge → `Closes #N` の
  定型フローで回す。
- **関連要件**: CORE-FR-014, CORE-FR-015, CORE-CON-006

## UC-006: 自分専用のスキルを作って配布する

- **誰が**: スキル開発者
- **使うもの**: skill-creator
- **概要**: `skill-creator` で対話的に設計し、`skill-validator` → `skill-tester` →
  `skill-evaluator` で品質（スキルあり/なしの比較）を確認、`skill-packager` で配置・配布する。
  運用開始後は `skill-instrumenter`/`skill-observer`/`skill-improver` の自己改善ループへ入る。
- **関連要件**: CORE-CON-002, CORE-CON-004, CORE-CON-005

## UC-007: 両対応プラグイン（Claude Code + Antigravity）を作る

- **誰が**: プラグイン開発者
- **使うもの**: plugin-creator
- **概要**: `create-plugin` の8フェーズガイドで構成決定（`plugin-structure`）、
  コンポーネント実装（`plugin-hooks`/`plugin-mcp`/`plugin-settings`）、
  `plugin-validator` エージェント + `agy plugin validate` で両対応を検証する。
- **関連要件**: CORE-CON-001, CORE-CON-003

## UC-008: リポジトリの規約を「機械検証できる要件」にする

- **誰が**: リポジトリ自身の保守担当者（ドッグフーディング）
- **使うもの**: bitz-sdd
- **概要**: ルートに `.spec/` を置き、AGENTS.md の規約を EARS 要件（CORE-CON-*）として起票、
  `spec_inspect.py` が traceability を常時検証する。エージェント発の改善提案は
  `.spec/spec-issues/` 起票 → 人間裁定 → 実装の一方通行とする。
- **関連要件**: CORE-FR-002, CORE-FR-010, CORE-FR-012, CORE-NFR-001
