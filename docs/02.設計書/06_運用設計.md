# 運用設計

## 1. 運用目標

個人から数人のチームが、既存のGitとテスト環境へ小さな追加だけで導入できることを目標とする。
常駐サービス、データベース、外部管理画面、専用認証基盤を必要としない。

## 2. 導入

```text
uv tool install bitz
bitz doctor
bitz check --full
```

AI CLI向けプラグインは任意であり、コア単体でも全検査を実行できる。
Core 1.0ではPyPIを主配布経路とし、単一バイナリを必須にしない。

## 3. 日常運用

```text
変更意図の確定後:     bitz context <ID> --purpose implement
編集直前・再開時:     bitz context <ID> --purpose implement --expect-digest <digest>
編集直後:             bitz check
実装後:               bitz verify <ID>
CIまたは節目:          bitz check --full
問題発生時:            bitz doctor
```

通常実行はネットワークとLLMを使わず、成功時にファイルを生成しない。

## 4. CI

CIでは次だけを標準とする。

```text
bitz check --full
bitz verify
```

引数なしの`bitz verify`は、検証対象となる全SPECを解決する。
各`MUST`文にテスト対応がない対象は、その対象のコマンドを実行せず`blocked`とする。独立した他対象は継続し、
全体は対象別結果の最も悪いstatusで集約する。

既存のLint、型検査、SAST、テスト基盤を置き換えず、`bitz verify`から呼び出す。
CI専用の別ルールエンジンを作らない。

## 5. 性能予算

基準リポジトリは、EARS-AI規範文1,000件、参照5,000件、仕様ファイル300件とする。

| 操作 | 目標 |
|---|---:|
| 変更範囲の`bitz check` | 1秒以内 |
| 20文書以下の`bitz context` | 1秒以内 |
| 基準リポジトリの`bitz check --full` | 5秒以内 |
| `bitz doctor` | 2秒以内 |
| コアの追加メモリ | 200MB以内 |

`verify`の時間は利用者のテスト時間に依存するため、コア自身のオーバーヘッドを500ms以内とする。
目標は実測に基づいて確定し、達成できない機能は既定経路から外すか増分化する。
この性能目標は上記の基準リポジトリ規模に対するものである。リソースhard limitは入力増幅を防ぐ実装境界であり、
上限近傍の性能を保証しない。

## 6. キャッシュ

- キャッシュなしでも正しく動く。
- キャッシュはGit revision、対象path、コア版をキーにする。
- 不整合を検出した場合は自動破棄して再生成する。
- キャッシュ削除に専用復旧手順を要求しない。

## 7. 更新

- Coreのメジャー版更新前に`bitz doctor`で互換性を確認する。
- 設定とEARS-AIの移行は、決定論的に変換できる部分だけ提案する。
- 更新失敗時は既存`.spec/`を変更しない。
- プラグインがコアを自動更新しない。

## 8. 障害時

| 状況 | 動作 |
|---|---|
| 設定不正 | `error`と該当キーを返す |
| 強い関係の参照切れ・循環 | `failed`とsource、target、edgeを返す |
| Context上限超過 | 部分bundleを使わず`blocked`を返す |
| Context Digest不一致 | 編集を続けず`blocked`を返す |
| テスト環境不足 | `blocked`と不足コマンドを返す |
| キャッシュ破損 | 再生成して継続する |
| LLM利用不能 | 決定論的検査を継続する |
| `.spec/`または`bitz.yaml`不在 | `doctor`が最小設定と作成先を示して`blocked`を返す |
| Git不在 | 差分保護とTASK境界以外を継続し、失われる保証を警告する |

復旧の基本は、Git diffの確認、設定修正、コマンド再実行で完結させる。

## 9. バックアップと観測性

正本はGit管理された`.spec/`であり、追加バックアップ機構をCore 1.0へ実装しない。
観測性は所要時間、対象件数、キャッシュhit/miss、Diagnostic件数に限定する。
テレメトリ外部送信は既定で行わない。
