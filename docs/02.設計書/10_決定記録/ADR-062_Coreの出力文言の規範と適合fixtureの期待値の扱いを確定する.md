# ADR-062 Coreの出力文言の規範と適合fixtureの期待値の扱いを確定する

## Context

[結果・診断・終了コード](../../03.詳細設計/00_共通契約/01_結果・診断・終了コード.md) §4は、診断の`summary`を「人に向けた短い説明」、
`suggestedAction`を「局所的な修正の案」と定めるだけで、文字列を定めない。一方、適合fixtureは`summary`を完全一致で比べるため、
Coreの出力文言はfixtureの期待値として固定されている。[表記規則](../../表記規則.md)はCoreの出力文言を対象外としてきたため、
文言には英語の一般語（strong relation、Frontmatter、file、command、testなど）が多く残り、同じ条件の診断の文言が操作によって割れている。

文言を直すと、多数のfixtureの期待値が変わる。[ADR-051](ADR-051_適合fixtureの変更手続きを確定する.md)は期待値の訂正を
「規範文と食い違う期待値を規範文に合わせる」ものとし、根拠を規範文に限る。文字列を定める規範文がないまま期待値を変えると、
根拠のない変更になり、Coreの観測出力を期待値へ写すことと区別できない。

## Decision

1. **規範**: Coreの出力文言（診断の`summary`と`suggestedAction`、引数不正のときの標準エラー出力の`<reason>`）は、
   [表記規則](../../表記規則.md) §3.5に従う。結果・診断・終了コード §3・§4から表記規則 §3.5を参照する。
2. **期待値の訂正**: 表記規則 §3.5に反する文言を固定している適合fixtureの期待値を、§3.5に合う文言へ変えることは、
   ADR-051の期待値の訂正にあたる。表記規則 §3.5は文言の書き方を定めるが、文字列を1つに決めないため、
   変更後の文字列は作業者が§3.5に合うように選び、人間の管理者が承認したものを固定する。承認は変更ごと（PRごと）に得る。
3. **手順**: 文言の変更は、Coreの文言、適合fixtureの期待値と生成器、監査の回帰試験、Coreの単体試験を同じPRで直し、
   Coreの変更とfixtureの変更は別のコミットにする。そのほかは[適合fixture仕様](../../03.詳細設計/00_共通契約/04_適合fixture仕様.md) §1.1の
   期待値の訂正の手順（レビュー記録、監査、Gate Aの再認定、Gate Bの再判定）に従う。
4. **範囲**: 本ADRは文言の書き方と変更の扱いだけを定める。診断コード、重大度、結果への効果、発生元、`evidence`は変えない。
   `summary`の文字列を規範文で1つに定めること（診断レジストリへ文言の列を加えることなど）は行わない。

## Consequences

- Coreの出力文言の英語の一般語を、根拠と承認を伴って日本語へ直せる。同じ条件の診断の文言の食い違いも、同じ手順で直せる。
- 文言の変更のたびに、管理者の承認、Gate Aの再認定、Gate Bの再判定が必要になる。
- 文字列そのものは規範文で決まらないため、承認した文字列がfixtureの期待値として固定される。fixtureのレビュー記録には、
  文字列が規範文から一意に導いた値ではなく、表記規則 §3.5に合わせて承認した値であることを書く。

## Alternatives

1. **文言だけの変更を非意味的な変更とする**: 通常のレビューだけで済むが、期待する出力を変える変更をADR-051の「入力と期待する動作が変わらない」
   変更に含めることになり、手続きの規則そのものを緩める。採らない（ユーザーの決定）。
2. **`summary`を比較の範囲から外す**: 文言を自由に変えられるが、正規化器の比較の範囲を広げる緩和であり、文言の退行を検出できなくなる。採らない。
3. **診断レジストリに文言の列を加え、文字列を規範文で1つに定める**: 根拠は最も明確になるが、全診断の文言を規範文として管理する負担が大きい。採らない。
4. **規範を表記規則だけに置き、詳細設計から参照しない**: 変更は小さいが、詳細設計の結果の契約から文言の規範をたどれず、
   表記規則が規範文にあたるかが曖昧になる。採らない（ユーザーの決定）。

## Notes

- Core 1.0の出力文の見直し（英語の一般語の書き換え、同じ条件の診断の文言の統一、`doctor`の修復手順）の前提となる決定である。
- ADR-051の当てはめであり、ADR-051の`Decision`を置き換えない。訂正の理由（表記規則 §3.5に反すること）は規範文に基づき、変更後の値は管理者の承認で決める。
