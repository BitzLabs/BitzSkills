# ADR-058 Gate Cから比較タスクの実測を外す

## Context

Core 1.0のGate Cは、簡易フローと通常のMarkdownを比較し、完了時間、欠陥率、レビュー負荷の結果を
記録することを条件としている。この条件は、ADR-009の性能判断にある「追加機能は実タスクで完了時間、
欠陥率、レビュー負荷のいずれかを改善した場合だけ既定化する」という判断に由来する。

比較タスクのプロトコルは、課題の順序を均衡させ、クリーンな複製、外部支援の禁止、正解を伏せたレビューを
必要とする。簡易フローの自己適用は1件完了しているが、同じ参加者が同等の課題を通常のMarkdownでも行った
対照結果はない。少数の実施結果は、課題差、学習効果、参加者とレビュアーの差を分離できず、Gate Cのほかの
機械的な証跡と同じ再現性を持たない。

機能適合、性能SLO、簡易フローの自己適用、人手レビュー、未解決P0/P1の閉包は別々に確認できる。
人の生産性を調べる実験をリリース条件にすると、Coreの機能品質と、実施者を必要とする研究を同じGateで
扱うことになる。

## Decision

1. Core 1.0のGate Cは、簡易フローと通常のMarkdownによる比較タスクの実測結果を要求しない。
2. ADR-009の「性能判断」の3項目目を部分改訂する。Core 1.0の既定経路への採用は、規範で定めたスコープ、
   適合試験、単体試験、簡易フローの自己適用、人手レビュー、機械的な性能SLO、未解決P0/P1の有無で判断する。
   完了時間、欠陥率、レビュー負荷の定量的な改善証明は要求しない。ADR-009のほかのDecisionは変更しない。
3. `fixtures/comparison`の比較タスク、プロトコル、スキーマ、正解表は削除せず、任意の将来研究に使える
   固定済みの資産として保持する。観測結果がないことをGate Cの未完了項目にしない。
4. 有効な比較結果を取得するまでは、Coreまたは簡易フローが通常のMarkdownより完了時間、欠陥率、
   レビュー負荷を改善すると主張しない。

## Consequences

- Gate Cの残件は、未解決P0/P1の閉包だけになる。
- 人の参加を必要とする実験を用意できないことが、Core 1.0のリリースを恒久的に止めなくなる。
- 比較タスクは引き続きスキーマと固定入力の監査対象だが、結果の収集と合否判定はリリース条件ではない。
- Core 1.0について主張できるのは、適合、性能SLO、自己適用、人手レビューで確認した範囲に限られる。
  人の生産性に対する優位性は未検証のままと明示する。

## Alternatives

1. **現行のGate C条件を維持する**: 統制された参加者とレビュアーを用意できるまでリリースを確定できないため採らない。
2. **1件の自己適用記録を比較結果として使う**: 通常のMarkdownによる対照がなく、比較証拠を偽装するため採らない。
3. **比較タスクを削除する**: 将来の任意研究に再利用できる固定済み資産と判断履歴を失うため採らない。
4. **合成値または推定値を記録する**: 人の作業結果ではなく、完了時間、欠陥率、レビュー負荷を示さないため採らない。
