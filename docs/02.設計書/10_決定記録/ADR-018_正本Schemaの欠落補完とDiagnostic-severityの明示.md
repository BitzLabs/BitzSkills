# ADR-018 正本Schemaの欠落補完とDiagnostic severityの明示

## Context

ADR-009以降、プロファイル、複合ワークスペース、改訂履歴、Agent Pluginsの配布を段階的に追加した。
その結果、上位文書が前提とする設定キー・フロントマターの項目・実行パラメーター・診断の重大度が、
下位の正本スキーマに定義されないまま残った箇所が5件生じた。

いずれも文書間で相反する2つの規則があるのではなく、**片方に定義が存在しない**。
このため実装者は仕様から動作を決定できず、同一入力から同一の診断を得るという
適合性試験（[03_CLI統合設計](../../03.詳細設計/03_操作仕様/README.md) §8）を成立させられない。

| # | 欠落 | 参照側 | 正本側 |
|---:|---|---|---|
| 1 | `profiles`の設定キー | 拡張Profile仕様、doctor仕様、複合workspace仕様 | `bitz.yaml`仕様にキーなし |
| 2 | `verify`の実行位置 | `bitz.yaml`仕様が`cwd`を定義 | 参照・トレース・検証仕様が実行位置をワークスペースのルートへ固定 |
| 3 | フロントマターの責任者項目 | Core構文仕様が`owners`を指示 | Frontmatter共通仕様に`owners`なし |
| 4 | `EAI-*`の重大度 | 共通アーキテクチャが終了コードを重大度から決定 | AST・Parser仕様に重大度の列なし |
| 5 | プロファイル間の依存 | 拡張Profile仕様が`dependencies`を許可 | ADR-016が拡張間の必須依存を禁止 |

## Decision

1. `.spec/bitz.yaml`へ`profiles`を予約キーとして追加する。Core 1.0は型だけを検査し、
   未知キーの警告を出さず、互換性判定とコンテキストのハッシュ値へ使用しない。
   `doctor`および複合ワークスペース全体の検査で行うプロファイルの互換性判定は、プロファイルの正式な実装まで行わない。
2. `bitz verify`は解決した`verify.commands[].cwd`で実行する。`cwd`を指定していないコマンドだけ、
   テストを所有するワークスペースのルートを実行位置とする。テストのパスの重複排除は
   `argv`と`cwd`の組を単位とする。
3. 作成者・承認者・説明責任者はCoreの共通のフロントマター項目にせず、`x-owners`などの
   プロジェクト拡張で表す。EARS-AI規格本文の`owners`の記述を`x-`拡張へ改める。
4. `EAI-*`診断へ重大度を定義する。構文・意味系は`error`とし、所有文書が`draft`の場合だけ
   `warning`へ降格する。ID系の3つの診断コードは`status`にかかわらず`error`とする。
   `EAI-CORE-LANG-001`と`EAI-EXT-UNKNOWN-001`は`warning`とする。
5. プロファイルのマニフェストから`dependencies`を削除し、プロファイル間の依存宣言を無条件に禁止する。

## Consequences

- プロファイルが未実装のままでも、`profiles`の宣言が警告を生まずに前方互換の枠として機能する。
- `cwd`を持つ検証コマンドが仕様どおり動作し、結果のJSONの`cwd`と実行位置が一致する。
- `ACTOR`と責任者の分離が、規格本文と正本スキーマで同じキー名を指すようになる。
- すべての`EAI-*`診断コードが重大度を持ち、終了コードが文書から決定できる。
- プロファイル間の共有語彙が必要になった場合、Coreの公開語彙への昇格が唯一の経路になる。
- マーケットプレイスのCIへ、プロファイルのマニフェストの`dependencies`の不在検査が加わる。
- 結果JSONの`commands[].argv`と`commands[].tests`は、`cwd`が`"."`でない場合に一致しない。
  レポートを読む側はこの差を前提にする。

## Alternatives

1. **`profiles`の参照を4文書から削除する**: プロファイルの正式な実装のときに同じキーを再導入することになり、
   その時点で警告を受けていた既存の設定との整合を別途取る必要が生じる。
2. **フロントマターの共通項目へ`owners`を追加する**:
   [02_spec directory仕様](../../03.詳細設計/02_SPECモデル/01_workspace・設定仕様.md)の「owner、日時などは必要なプロジェクトだけが
   拡張する」と、SPEC file規定 原則3の両方を変更する必要があり、影響範囲が逆側の修正より大きい。
3. **重大度を実装の裁量に委ねる**: 同一のfixtureから同一の診断を得る適合性試験が成立しない。
4. **プロファイルの依存をマニフェストで解決する**: Agent Plugins 1.0に依存の解決機構がなく、
   単体で導入するときに未解決の依存を検出できない（ADR-016）。

## Notes

本ADRは[04.提案資料/03_設計書・詳細設計reviewと改訂提案](../../04.提案資料/03_設計書・詳細設計reviewと改訂提案.md)
§2のP1 5件に対する裁定であり、同書 附録Aの差分を適用して確定した。
本ADR作成時点では同書のP2・P3は未裁定であり、本ADRの対象外とした。その後、P2はADR-019、
決定記録の自己適合性はADR-020、P3は提案資料のREADMEの裁定として反映済みである。

`Decision`の2番目の項目のテストのパスの重複排除単位`(argv, cwd)`は、[ADR-030](ADR-030_verify実行bindingの正規識別子と重複排除単位の統一.md)が
`(workspaceId, 正規化argv template, 正規化cwd)`へ置き換えた。本ADRの他の`Decision`の項目は有効である。

`Decision`の1番目の項目の予約キー`profiles`とプロファイルの互換性の判断、および`Decision`の2番目の項目のテスト割当ての同一性は、
[ADR-039](ADR-039_Core-1.0仕様構造の再編とscope縮小.md)がCore 1.0の対象外またはコマンド名の単位へ変更した。
`Decision`の3〜5番目の項目と、`Decision`の2番目の項目の`cwd`で実行する規則は有効である。

`Decision`の4番目の項目の`EAI-CORE-LANG-001`に対する重大度は、診断を返すバージョンでの分類を記録したものである。
Core 1.0は自然言語を決定論的に識別しないため、現行のEARS-AI契約と診断レジストリは同じ診断コードを予約済みとし、
公開結果へ返さない。これは他の`EAI-*`の重大度の判断を変更しない。
