# ADR-045 実行環境と配布物の確定

## Context

[ADR-009](ADR-009_小規模チーム向け軽量CoreとEARS-AI中核化.md)の`Decision`の9番目の項目と、
[ADR-016](ADR-016_Agent-Plugins準拠の複数プラグインの配布.md)は、Agent Plugins 1.0.0のパッケージを主経路、
Python + PyPI + `uv`をCIと非LLM環境の代替経路とすることを確定している。しかし、次が確定していない。

- 対応するPythonの下限バージョン
- 配布物名とCLIの実行体名
- 第三者の依存の許容範囲と、YAMLの解析の実装方針
- Gitの利用形態と下限バージョン

[`bitz doctor`仕様 §3](../../03.詳細設計/03_操作仕様/04_doctor.md#3-検査順序)の検査1は、
「Core実行体、Python version、起動」でバージョンの不適合を`blocked`とするが、比較すべき下限が規範に存在しない。
この検査は、現状のままでは実装できない。

また、`bitz.yaml`は「UTF-8のYAML 1.2部分集合、custom tag・anchor・alias・merge key禁止、重複keyをerror」と
定めているが、広く使われているYAML実装の既定の挙動は、これと一致しない。実装が既定のローダーをそのまま使うと、
仕様が禁止した構文を受理し、`SPEC-CONFIG-SCHEMA-001`を返すべき入力を通す。

## Decision

1. **実行環境**: Core 1.0はCPython 3.11以上を対象とする。`doctor`の検査1は、この下限と比較し、
   下限未満を診断`SPEC-DOCTOR-CORE-001`（`blocked`）とする。3.10以下は、サポートが終了しているか終了が近いため、
   対象にしない。実装は、3.11で動作する構文と標準ライブラリのAPIだけを使い、より新しいバージョンでのみ利用できる機能へ
   依存しない。
2. **配布物**: PyPIの配布物名を`bitz`、`import`パッケージ名を`bitz`、CLIの実行体名を`bitz`とする。
   Agent Pluginsの経路のプラグインIDは`bitz-core`と`bitz-sdd`とし、`bitz-core`がこのCLIを同梱または参照する。
   プラグインIDとPyPIの配布物名を同一にしない。利用者から見て起動するコマンドは、どの経路でも`bitz`とする。
3. **依存**: 実行時の依存を、標準ライブラリとYAMLの解析だけに限る。YAMLは、YAML 1.2を解釈できる第三者のライブラリを
   1つだけ使用し、バージョンを厳密に指定してロックする。ローダーは安全な読取りだけに使い、カスタムタグ、アンカー、エイリアス、
   マージキー、重複するキー、暗黙の日時型への変換を、Core側で明示的に拒否してから値を解釈する。
   ライブラリの既定の挙動を仕様の代わりにしない。
4. **Git**: GitはCLIの実行体を`argv`で起動して利用し、シェルを介さない。libgit2の言語バインディングと、Gitの実装の
   再実装は採用しない。下限はGit 2.30とし、下限未満または実行不能はGit不在として、
   [安全な入出力・互換性 §8](../../03.詳細設計/00_共通契約/02_安全な入出力・互換性.md#8-git不在時)の
   縮退の契約を適用する。複合ワークスペースでは診断`SPEC-MONOREPO-GIT-001`（`blocked`）とする。
5. **ネットワーク**: Coreの実行体は、通常の操作でネットワークへ接続しない。導入と更新のネットワークの利用は、
   パッケージマネージャーとクライアントの責務とし、Core自身は依存物を動的に取得しない。
6. **ロックと再現性**: 依存はロックファイルで固定し、公開物をソースのコミットとビルドの手順へ対応付ける。
   下限のバージョン、配布物名、依存の追加と削除は、Coreのマイナーバージョン以上の変更とし、パッチでは変えない。

## Consequences

- `doctor`の検査1が実装できるようになり、下限未満の環境で一貫して`blocked`を返せる。
- YAMLの解析の責務がライブラリではなくCoreにあることが明確になり、禁止した構文の受理を、適合fixtureで検査できる。
- 実行時の依存が1つに収まり、供給網の面が小さくなる。ロックと固定の対象も少ない。
- Gitをサブプロセスで使うため、Git不在、下限未満、`PATH`にないことを、同じ縮退の経路で扱える。
  一方でGitの操作ごとに、プロセスの起動のコストがかかる。性能予算は、すでにこの前提で測定する。
- CPython 3.11未満しか使えない環境は、Core 1.0の対象外になる。

## Alternatives

1. **下限をCPython 3.9または3.10とする**: いずれもサポートが終了しているか終了が近く、セキュリティ更新を受けられない
   環境を、1.0の対象にすることになる。採用しない。
2. **YAMLを自前で実装する**: 仕様が要求するのは1.2の部分集合だけなので不可能ではないが、
   Core 1.0の中心の価値はEARS-AIとコンテキストの解決であり、YAMLの実装の正しさへ工数を割く理由がない。
   第三者のライブラリを安全な読取りで使い、禁止した構文をCoreで拒否する方が、検査できる。採用しない。
3. **libgit2の言語バインディングを使う**: ネイティブの依存が増え、配布物とビルドの再現性が難しくなる。
   `uv tool install`の単純さも失われる。採用しない。
4. **単一のバイナリを1.0の主経路にする**: ADR-009の`Decision`の9番目の項目が、需要を確認した後の検討としており、
   ADR-016がAgent Pluginsの経路を主とした。本ADRはこれを変更しない。
5. **下限のバージョンを、`doctor`の設定できる値にする**: 環境ごとに適合の判定が変わり、
   「同じ入力とversionから同じ結果」という契約と両立しない。採用しない。
