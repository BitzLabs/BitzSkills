# ADR-075 CLIへ--helpと--versionを加える

## Context

`bitz --help`は、標準エラー出力へ`bitz: (no-operation): 未知の操作です: --help`を書き、終了コード4で終わる。操作の一覧、引数、Coreのバージョンを
人が確かめる手段は、文書を読むことと`doctor --format json`の`core`を読むことしかない。
[結果・診断・終了コード](../../03.詳細設計/00_共通契約/01_結果・診断・終了コード.md)は、未知のオプションを引数不正（終了コード4）とする。
`--help`と`--version`を固定する適合fixtureはない。

## Decision

1. **`--help`**。`bitz --help`は操作の一覧を、`bitz <操作> --help`はその操作の引数を、標準出力へ書き、終了コード0で終わる。
   操作を始めず、結果のJSONとレポートを作らない。`--help`は、ほかの引数があっても優先する。
2. **`--version`**。`bitz --version`は、`bitz <Coreのバージョン>`の1行を標準出力へ書き、終了コード0で終わる。
3. **契約の範囲**。`--version`の1行の形と、2つの終了コードを契約とする。`--help`の文言は契約にしない。
   機械が読むCoreのバージョン、APIのバージョン、能力は、今と同じく`doctor --format json`の`core`を正とする。
4. **変えないもの**。ほかの未知のオプションと未知の操作は、今と同じく終了コード4とする。

## Consequences

- 最初に実行する人が、操作と引数を端末で確かめられる。
- 仕様（結果・診断・終了コード、Core実行環境・CLI基盤契約）を改め、適合fixtureを追加する。Gate Aを再認定する（ADR-051）。

## Alternatives

1. **Core 1.0の後に加える**: 追加なので後でも壊さないが、変更が小さく、最初に実行する人が必ず当たる。採らない（ユーザーの決定）。
2. **`--help`の文言も契約にする**: 文言を変えるたびに適合fixtureの変更が要る。採らない。

## Notes

- 提案34の論点4のうち、Core 1.0へ入れる部分の裁定である。2026-11-16に利用者が採った。
- 起動の細目は[Core実行環境・CLI基盤契約 §5.1](../../03.詳細設計/00_共通契約/06_Core実行環境・CLI基盤契約.md)で定めた。`Decision`の範囲の中の細目であり、
  次の点で`Decision`の文より具体的である。`--help`がほかの引数より優先するのは、最初の要素が`--help`か公開の操作の名前の場合に限る
  （`bitz foo --help`は未知の操作として終了コード4）。`--version`は1要素だけの場合に限る。`--help`と`--version`は標準エラー出力へ何も書かず、
  `--help`の出力はUTF-8で空でなくLFで終わることを契約に含める。`--version`の出力のパッチ部は、`doctor`の`core.version`と同じく適合fixtureで比べない
  （適合fixture仕様 §4）。いずれも2026-11-17の実施の中で司令塔が定め、独立レビューで確かめた。
