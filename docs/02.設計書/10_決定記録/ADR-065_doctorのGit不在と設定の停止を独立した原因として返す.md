# ADR-065 doctorのGit不在と設定の停止を独立した原因として返す

## Context

`doctor --all-workspaces`は、Gitを利用できず、かつリポジトリのルートの設定で全体事前検査が止まると、設定の診断だけを返し、
`SPEC-MULTI-GIT-001`を返さなかった（実装の確認事項C33）。全体事前検査は、Gitの境界を確定できないことを検査項目`git`の`blocked`には反映していたが、設定で止まった段階で診断を加えずに戻っていたためである。

[`doctor`仕様](../../03.詳細設計/03_操作仕様/04_doctor.md) §3は、Gitの利用可否を設定と独立した検査（検査9）とし、独立した検査は先行する失敗の後も
可能な範囲で継続すると定める。単一ワークスペースの`doctor`も、設定の不適合とGitの不在をそれぞれ返している。

一方、[ADR-063](ADR-063_複合ワークスペースの単独操作の全体事前検査を確定する.md)の`Decision`の5番目の項目は、Gitを利用できない場合、
設定自身のスキーマまたはEARS-AIのメジャーバージョンが非対応で止まればその診断とし、そうでなければ`SPEC-MULTI-GIT-001`とする、と定めた。
この項目は`doctor`にも当てはまるように読めた。

## Decision

1. **部分改訂**。本ADRは、ADR-063の`Decision`の5番目の項目を、`doctor`についてだけ次の2.のとおり部分改訂する。ADR-063のほかの`Decision`と、
   `doctor`以外の操作についての5番目の項目は変えない。
2. **`doctor`**。`doctor`（`--all-workspaces`と単独の`doctor`の全体事前検査）は、設定の不適合とGitの不在を独立した2つの原因とする。
   リポジトリのルートの設定（構文、型、必須フィールド、スキーマまたはEARS-AIのメジャーバージョン）で全体事前検査が止まった場合も、
   Gitの境界を確定できなければ、設定の診断に加えて`SPEC-MULTI-GIT-001`（`blocked`）を返す（ユーザーの決定D5）。検査項目`git`は今どおり`blocked`とする。
   単独の`doctor`では、ルートの設定の構文、型、必須フィールドの不正はADR-063の決定4により複合ワークスペースと判定しないため、全体事前検査に至らない
   （単一ワークスペースの`doctor`の扱い）。`--all-workspaces`についての部分は、ADR-063の5番目の項目の改訂ではなく新しい明記にあたる。
3. **ほかの操作**。`context`、`check`、`verify`は、ADR-063の5番目の項目のとおり、設定の停止の診断だけを返す。

## Consequences

- `doctor`が、Gitの不在を設定の不適合に隠さず報告し、利用者が2つの原因を一度に直せる。単一ワークスペースの`doctor`と扱いがそろう。
- `doctor`とほかの操作で、Gitの不在の報告の有無が分かれる。`doctor`は環境の診断が目的であり、ほかの操作は処理を始められない最初の原因を返せば足りるためである。
- この扱いを固定する適合fixtureを追加する（ADR-051の追加）。既存のfixtureの入力と期待値は変えない。

## Alternatives

1. **設定の診断だけを返す（今の挙動）**: `doctor` §3の検査の独立と、単一ワークスペースの`doctor`の扱いに反する。採らない（ユーザーの決定）。
2. **すべての操作で両方を返す**: ADR-063の判断（処理を始められない最初の原因を返す）を変え、`check`と`verify`の結果が増える。採らない。
