# ADR-022 規範文の候補抽出とIDの構文検証の分離

## Context

従来の規範文の候補の走査器は、先頭のトークンが正しい`statement-id`に一致する行だけを構文解析器へ渡していた。
この規則では、`REQ-1:AC-01`、未知の接頭辞、3階層のID、IDの欠落などを通常の本文として無視し、
`EAI-CORE-ID-001`や必須のタグの不足を報告できない。

一方、Markdownの通常のチェックボックスやコードの例まで、規範文の候補の行にすると誤検出が増えるため、
候補抽出と完全な構文検証を分離する必要がある。

## Decision

1. Markdownの処理を、除外する領域の判定、規範文の候補の走査器、Coreの字句解析器／構文解析器／検証プログラムの
   3段階に分ける。
2. 走査器はIDの妥当性を要求しない。コードブロックと引用の外側で、先頭の空白を除いた行が`- [`で始まり、
   最初の角括弧が、文書IDらしい大文字のトークン、Coreのタグ、またはプロファイルの名前空間の形式である行を、
   候補とする。
3. GFMのチェックボックス`- [ ]`と`- [x]`は、候補から除外する。
4. 候補の行のID形式、接頭辞、階層、必須のタグ、順序は、字句解析器／構文解析器／検証プログラムが診断する。
5. 状態が`approved`のREQに妥当な規範文が0件の場合、診断`SPEC-REQ-STATEMENT-001`
   （重大度`error`、結果への効果`failed`）を返す。
6. 不正なID、IDの欠落、3階層のID、通常のチェックボックス、コードブロック、引用ブロックの適合fixtureを必須とする。

## Consequences

- `EAI-CORE-ID-001`が実際に不正なIDへ到達する。
- IDの欠落や先頭のタグの誤りを、通常の本文として黙って受理しない。
- 通常のMarkdownのチェックボックスと規範文の例は、引き続き解析の対象外にできる。
- 走査器は、文書の構造を理解するMarkdownリーダーの後段で動作する必要がある。

## Alternatives

1. **正しいIDに一致した行だけを解析する**: 不正なIDの診断に到達できなくなるため採用しない。
2. **すべての`- [`の行を解析する**: チェックボックスやMarkdownのリンクを誤検出するため採用しない。
3. **状態が`approved`の文書の0件の検査だけを追加する**: 個々の不正の理由が失われ、状態が`draft`の文書では問題を発見できないため採用しない。
