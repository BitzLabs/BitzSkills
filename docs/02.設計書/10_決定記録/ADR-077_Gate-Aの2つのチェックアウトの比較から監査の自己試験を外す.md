# ADR-077 Gate Aの2つのチェックアウトの比較から監査の自己試験を外す

## Context

Gate Aの条件は、規範、fixture、期待値、検証基盤を、Coreの実行体なしで再現できることである（[実装計画](../../04.提案資料/12_Core-1.0実装計画.md) §2、§3.1）。
認定（`fixtures/certify_gate_a.py`）は、`HEAD`から独立したクローンを2つ作り、それぞれで監査（`fixtures/validate_conformance.py`）を実行し、
2つのレポートがバイト列として一致することを求める。2つの比較は、次の2つを示すためのものである。

1. 新しいチェックアウトで実行すること: コミットし忘れた入力、Gitで管理していないファイル、前回の実行の残りへの依存を見つける。
2. 2回の結果が一致すること: 監査の出力が、辞書や集合の順序、時刻、乱数、実行環境に依存しないことを示す。

監査の時間の約9割は、監査の自己試験（`fixtures/test_conformance_audit.py`、2026-11-18の時点で457件）が占める。
自己試験は、監査のプログラムが、fixtureの改変を拒否できるかを確かめる試験であり、レポートへは合否だけを書く。
2026-11-18の測定では、自己試験だけで約530〜580秒、監査1回で約570〜700秒、Gate Aの認定で20分を超えた。

自己試験を2回目のチェックアウトでも実行することは、上の1と2のどちらにもほとんど寄与しない。
1は1回目のチェックアウトで自己試験を実行すれば示せる。2について、自己試験の出力は合否だけである。
fixtureごとの準備の決定性は、監査の中で各fixtureの準備の手順を2回適用して一致を確かめている。

## Decision

1. Gate Aの認定は、今と同じく`HEAD`から独立したクローンを2つ作り、それぞれで監査を実行する。
2. 1つ目のクローンの監査は、自己試験を含むすべての検査を実行する。
3. 2つ目のクローンの監査は、自己試験を実行しない。監査は、自己試験を実行しなかったことをレポートに明示する。
4. 2つのレポートの一致は、自己試験の項目を除いて比べる。自己試験の項目は、1つ目のクローンで通過していることを求める。
5. ほかの条件（エラーのある検査がないこと、未完了の項目が新しいチェックアウトでの再現性の1件だけであること、監査の終了コード）は変えない。
6. 監査を単独で実行したとき（`uv run fixtures/validate_conformance.py`）とCIの監査のジョブは、今と同じく自己試験を実行する。

## Consequences

- Gate Aの認定の時間が、約半分になる見込みである。
- 自己試験の出力が実行環境によって変わる欠陥（たとえば、自己試験の合否が順序に依存する）は、Gate Aの2つの比較では見つからなくなる。
  自己試験は1つ目のクローンと、監査の単独の実行とCIで実行されるので、合否の不安定は別の実行で表に出る。
- 監査のレポートに、自己試験を実行しなかったことを表す値が加わる。
- `fixtures/certify_gate_a.py`、`fixtures/validate_conformance.py`、実装計画 §3.1、それらの試験を改める。

## Alternatives

1. **新しいチェックアウトを1つにし、決定性は乱数シードを変えた監査の再実行で確かめる**: さらに短くなるが、実行環境の違いによる非決定性を、
   2つ目のクローンほどは確かめられない。採らない（ユーザーの決定）。
2. **手元の認定は1つのチェックアウトにし、2つの比較はCIに任せる**: 手元の認定とCIの認定が別物になる。`AGENTS.md`の
   「CIの通過はローカル検証の代わりにならない」の見直しも要る。採らない（ユーザーの決定）。
3. **今のまま、時間の上限を延ばす**: 2026-11-18に上限を延ばしたが、自己試験は作業ごとに増える。認定の時間の問題は残る。採らない。
