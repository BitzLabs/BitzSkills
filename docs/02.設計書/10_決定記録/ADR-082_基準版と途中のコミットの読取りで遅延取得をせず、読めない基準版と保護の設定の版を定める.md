# ADR-082 基準版と途中のコミットの読取りで遅延取得をせず、読めない基準版と保護の設定の版を定める

## Context

承認済みの契約の保護（[ADR-072](ADR-072_承認済みの契約の保護をTECHへ広げ、途中のコミットの状態で再承認を判定する.md)、
[ADR-078](ADR-078_承認済みの契約の保護で認める途中の版を変更したコミットに限り、履歴の読取りに上限を設ける.md)、
[ADR-079](ADR-079_承認済みの契約の保護の途中のコミットの読み方と診断の形を定める.md)、
[ADR-081](ADR-081_承認済みの契約の保護で認める途中の版を状態を戻した版に限る.md)）の実装の独立した検収で、次のことが分かった。

1. **遅延取得**。部分クローンで取得元に届く環境では、Gitは欠けたオブジェクトを読むときに取得元から取得する。基準版と途中のコミットの読取りで
   ネットワークへ接続し、リポジトリのオブジェクトを増やす。[Core実行環境・CLI基盤契約](../../03.詳細設計/00_共通契約/06_Core実行環境・CLI基盤契約.md)の
   「Coreの通常の操作はネットワークへ接続せず、Gitにもネットワークの操作を要求しない」に反する（実測）。
2. **読めない基準版**。単一ワークスペースで、基準版の仕様文書の内容をGitから読めない場合、Coreはその文書を比較から除き、保護、状態遷移、削除の検出が
   働かないまま`passed`になる（実測。既存の挙動）。複合ワークスペースでは、基準版の内容を読めない場合を`SPEC-MULTI-GIT-001`（`blocked`）と定めている
   （[安全な入出力・互換性 §4.1](../../03.詳細設計/00_共通契約/02_安全な入出力・互換性.md#41-上限の設定)）。1.の遅延取得をやめると、この場合が起きやすくなる。
3. **途中の版の配列の上限**。安全な入出力・互換性 §4.1は、途中のコミットの版に`specBytes`と`frontmatterBytes`だけを当てると定め、
   [文書・フロントマター・状態仕様 §8.1](../../03.詳細設計/02_仕様文書モデル/02_文書・フロントマター・状態仕様.md#81-途中の状態)は、
   IDを読めない版を索引に入らない版と同じとする。現在版では、`documentArrayItemCount`を超えた版は索引に入らない。2つの規範が食い違う。
4. **保護の設定の版**。保護の有無（`safety.protectApprovedRequirements`）は現在版の設定で決まるので、意味を変える同じ変更の中で`false`にすれば、
   その場で保護を外せる（既存の挙動）。また、`--all-workspaces`でどのワークスペースの設定で決めるかが、仕様にない。

## Decision

1. **遅延取得をしない**。Coreが起動するGitの呼出しは、部分クローンの遅延取得をしない。手段は、対象のGit（2.30以上）のどの版でも効くものとする
   （たとえば、環境変数`GIT_NO_LAZY_FETCH=1`と、取得に使う転送の禁止の併用）。
   欠けたオブジェクトは、Gitから読めないものとして扱う。途中のコミットでは、ADR-078の決定2の「Gitから読めない」場合に当たる。
2. **読めない基準版**。単一ワークスペースの`check`で、基準版の仕様文書の一覧または内容をGitから読めない場合は、基準版との比較（状態遷移、削除の検出、
   承認済み要求の保護、影響候補）を始めず、新しい条件`CHECK-BASE-UNREADABLE`（診断コード`SPEC-GIT-BASE-001`、重大度`error`、結果への効果`blocked`、
   発生元`environment`、継続単位`stop-operation`）とする。`summary`は`基準版の仕様文書の内容をGitから読めません`とする。
   複合ワークスペースの規則（`SPEC-MULTI-GIT-001`）は変えない。
3. **途中の版の上限**（安全な入出力・互換性 §4.1の部分改訂）。途中のコミットの版には、`specBytes`、`frontmatterBytes`、`documentArrayItemCount`を当て、
   超えた版はIDを読めない版とする。ほかの上限は当てない。現在版で索引に入らない版と、同じ読み方にそろえる。
4. **保護の設定の版**。保護は、基準版と現在版の作業ワークスペースの設定のどちらかで有効なら有効とする。どちらの設定でも`false`と明示した場合だけ、
   無効とする。基準版に設定がない場合と、基準版の設定を読めないかスキーマに適合しない場合は、基準版の側を有効とみなす（既定値`true`）。
   保護を外すには、`false`にする変更を先に統合する。
5. **複合ワークスペース**。`--all-workspaces`では、各ワークスペースについて、そのワークスペース自身の基準版と現在版の設定で4.を判定する。
   単独の操作と同じ結果にする。

## Consequences

- Coreは、部分クローンでも取得元へ接続しない。欠けたオブジェクトがあれば、基準版は`blocked`、途中のコミットは完全に読めない側になる。
- 基準版を読めないまま、保護と状態遷移を黙って省いて`passed`にすることがなくなる。今は通っている起動が`blocked`になり得るので、Core 1.0の確定の前に入れる。
- 意味を変える同じ変更の中で保護を外せなくなる。保護を無効にする変更は、それだけで統合し、レビューで確かめる。
- 診断レジストリに条件を1つ加える。文言は、利用者の承認を得て決める（ADR-062）。
- Core実行環境・CLI基盤契約、`check`仕様、文書・フロントマター・状態仕様 §8、安全な入出力・互換性 §4.1、ワークスペース・設定仕様、診断レジストリを改める。
  適合fixtureを足す。

## Alternatives

1. **遅延取得を許す**: 通常の操作でネットワークへ接続しないという規範を、部分改訂することになる。採らない。
2. **読めない基準版の文書を比較から除く（今の挙動）**: 保護と状態遷移が、診断なしに働かなくなる。採らない（ユーザーの決定）。
3. **途中の版に`documentArrayItemCount`を当てない**: 現在版の索引と読み方が分かれる。採らない（ユーザーの決定）。
4. **保護の有無を現在版の設定だけで決める（今の挙動）**: 同じ変更の中で保護を外せる。採らない（ユーザーの決定）。
5. **`--all-workspaces`でルートの設定で決める**: 単独の操作と結果が変わる。採らない（ユーザーの決定）。

## Notes

- 2026-11-22に、利用者がDecisionの2から5のもとになった案を選んだ。Decisionの1は、既存の規範（Core実行環境・CLI基盤契約）に合わせる起票者の案である。
  診断コードの名前、`summary`の文言、基準版の設定を読めない場合の扱い（Decisionの4の3つ目の文）は、起票者の案である。
- 2026-11-22に、利用者がADRを承認した。Decisionの2の診断コードと`summary`の文言も、このとき承認した（ADR-062）。
- 本ADRは、ADR-078の決定3（途中のコミットの各ファイルに当てる上限）と、ADR-072の決定7（設定のキーの意味）を部分改訂する。そのほかの決定は変えない。
- `GIT_NO_LAZY_FETCH`は新しいGitで加わった環境変数であり、それを解さない版では、ほかの手段を併せないと遅延取得が起き得る（推測。この環境のGit 2.43.0では効いた）。
  対象のGitの版（Core実行環境・CLI基盤契約）で効くことを、Coreの単体試験で確かめる。
- 生まれていないブランチ（コミットのない`HEAD`）で`--base`を指定した場合に、基準版との比較が行われない既存の挙動は、本ADRの範囲に含めない。
