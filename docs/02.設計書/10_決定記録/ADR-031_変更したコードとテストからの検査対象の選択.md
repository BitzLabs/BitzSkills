# ADR-031 変更したコードとテストからの検査対象の選択

## Context

引数なしの`bitz check`はGitの変更集合を出発点にすると定めている。一方、通常の実行の詳細な記述は
「変更されたSPEC、その強い依存先、その直接の逆参照を再検査する」であり、変更されたコードのパスと
テストのパスをどの仕様文書へ正規化するかを定義していなかった。仕様文書を変更せず、コードとテストだけを変更した
コミットでは、検査対象が空になり得た。

さらに`docs/02.設計書/02_specディレクトリ仕様.md`の状態表は`outdated`を「上位要求または実装変更の
影響候補」と説明していたが、影響候補の診断`SPEC-IMPACT-OUTDATED-001`は、変更されたREQまたはTECHへ強く
依存する`approved`の文書だけを対象としており、実装の変更を出発点にしていなかった。

## Decision

1. 引数なしの`bitz check`の出発点は、Gitの変更集合にある各パスを次のとおり正規化して決定する。

   | 変更のパス | 正規化先 |
   |---|---|
   | 仕様文書のパス | そのパスを所有する文書のID |
   | コードのパス | `implements`の逆索引が示す、そのパスを所有するREQまたはTECH |
   | テストのパス | `tests[].path`の逆索引が示す、そのパスを所有するREQまたはTECH |

2. どの逆索引にも該当しないコードまたはテストのパスは検査の対象外とし、診断を出さない。対象外となった
   パスの件数だけを結果へ残す。
3. 逆索引は、§2のID解決がすべての仕様文書から構築する、フロントマターの軽量な索引から作る。`implements`と
   `tests[].path`はフロントマターの項目であり、追加のファイル走査を必要としない。
4. 正規化して選択した文書に対し、従来どおり強い依存閉包と直接の逆参照を検査する。
5. 影響候補は、変更されたREQまたはTECHへの逆参照に限る現行の契約を維持し、コードとテストの変更を
   `SPEC-IMPACT-OUTDATED-001`の出発点にしない。
6. `outdated`の説明から「実装変更」を削除し、上位要求または依存仕様の変更による影響候補とする。

## Consequences

- コードとテストだけを変更したコミットでも、所有するREQまたはTECHと、その依存閉包が検査される。
- 仕様文書をまだ持たないコードの変更は、検査対象を増やさず、警告も出さない。仕様文書を段階的に整備する
  リポジトリで、通常のコードの変更が常に`passed_with_warnings`になることを避ける。
- 逆索引が既存の軽量な索引から得られるため、変更範囲の検査の1秒以内という性能目標に影響しない。
- `outdated`の意味が、影響候補の診断の実装と一致する。

## Alternatives

1. **所有されていないコードまたはテストのパスを警告にする**: 通常のコードの変更が常に`passed_with_warnings`となり、
   影響候補の警告のシグナルが埋没するため採用しない。複合ワークスペースで対象が0件のメンバーを警告にとどめた
   [ADR-019](ADR-019_検証対象と縮退判定の明確化.md)の方針とも整合しない。
2. **コードの変更を`outdated`候補の出発点にする**: Coreが意味的な影響を断定しない方針に反し、実装を変えるたびに
   仕様の再確認を促す偽陽性を生むため採用しない。
3. **コードのパスを出発点にしない**: 仕様文書が変更されていないコミットで検査対象が空になり、`implements`と`tests`の
   静的なトレースが利用されないため採用しない。
