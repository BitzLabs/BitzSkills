# ADR-005 規範文IDの階層と記法

## Context

文書間でID階層の記述が食い違っていた。Core構文仕様は `REQ-001:AC-01` の2階層を例示する一方、`.spec/` ディレクトリ仕様は `REQ-001:AC-01:R-01` の3階層を、親子2行に分割した箇条書きで例示していた。後者はACTORと規範強度を欠き、Core構文の1行1文モデルにも適合しない。旧検討版の記法が残存したものである。

## Decision

規範文IDは `<文書ID>:<ローカルID>` の**2階層固定**とする。

```text
document-id = prefix, "-", 3*DIGIT           ; 例 REQ-001
local-id    = 1*( ALPHA / DIGIT / "-" )      ; 例 AC-01, SPEC-04, CONST-01
statement-id = document-id, ":", local-id
```

現在の`local-id`字句規則とCore文書prefixは[ADR-013](ADR-013_文書IDとローカルIDの字句規則訂正.md)で
訂正されている。実装はEARS-AI Core構文仕様を正とする。

- 1つの規範文は1行で完結し、ID、ACTOR、発動条件、規範強度、処理種別を必ず備える。
- 条件と結果を親子の箇条書きへ分割する記法を禁止する。
- 1つの発動条件から複数の独立した結果が生じる場合は、同一の発動条件を持つ複数の規範文へ分割し、それぞれに独立したIDを付ける。
- 分割した規範文の関連付けは、Core拡張の `reference` 種別または上位仕様側の `relations` で表現する。

### 理由

- 階層深度を可変にすると、ID解決、トレース表、影響分析、差分検出のすべてが階層数に依存し、実装と検証が複雑化する。
- 親子分割記法は、親行だけでは合否判定できず、子行だけでは適用条件が不明という点で、Core原則「一つの規範文は一つの安定IDと一つの主要結果を持つ」に反する。
- 2階層固定であれば、IDの正規表現を確定でき、`EAI-CORE-ID-001` を決定論的に判定できる。

## Consequences

- [02_specディレクトリ仕様.md](../02_specディレクトリ仕様.md) の例を Core 1.0 準拠へ修正する。
- 移行表に「親子分割記法 → 発動条件を繰り返した複数の規範文」を追加する。
- 移行ツールは3階層IDを検出した場合、決定論的に変換できないため人間確認へ回す。

## Alternatives

1. **3階層を正式サポート**: 却下。実装コストに見合う表現力の増加がない。同一発動条件の繰り返しは冗長だが、機械可読性と検証容易性を優先する。
2. **階層数を無制限とする**: 却下。ID衝突検出とトレース実装が著しく複雑になる。
