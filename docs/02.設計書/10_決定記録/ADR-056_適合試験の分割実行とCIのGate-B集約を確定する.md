# ADR-056 適合試験の分割実行とCIのGate B集約を確定する

## Context

通常の適合試験とGate Bの認定を別に実行すると、`main`のCIでは同じ全適合fixtureを3回実行する。
上限境界の実寸の検査と、独立したチェックアウトの間の再現性を維持し、分割実行と結果の統合で待ち時間を短縮する。
2026-09-26に管理者が、計時の常設、`main`の重複の整理、適合試験の分割という方針を承認した。

## Decision

1. **計測と判定の分離**: harnessの合否のレポートの外形と比較方法を維持する。fixtureごとの総時間、
   生成、準備手順、実行環境の準備、プロセスの実行、比較、副作用のスナップショットの時間は、別のJSONへ記録する。
   進捗は標準エラー出力へ出し、合否の標準出力へ混ぜない。時間の値はGateの決定性の比較へ含めない。
2. **選択と分割**: `run_conformance.py`は`--shard`と`--shards`で対象を決定的に分割する。
   合否条件は分割によって変えない。初期の配分は、関係とトレースが大規模なケースの観測と、次元ごとの
   推定の重みを用いる。重みは性能のベースラインではなく、検証の配置だけを決める補助値とする。
   `main`のCIの独立2組から得たfixtureごとの時間の中央値で重みを校正し、境界の内側と外側で、早期終了の有無を分ける。
   固定した観測元のコミットとCIの実行をコードに残し、各分割のジョブの予測時間をCIのジョブ名とStep Summaryへ表示する。
   予測値は合否、タイムアウト、性能要件には使用しない。
   開発用に`--suite standard`と`--suite scale`を提供するが、認定は必ず`full`の全対象を使う。
3. **独立した2組**: ADR-052の`Decision`の4番目の項目の単一のコマンドによる認定に加え、CIで分割の結果を集約する
   認定を許可する。CIでは、独立実行番号1・2の各組に対し、分割ごとに、固定した同一の`HEAD`から新しいクローンを
   作成してCoreをビルドする。Coreのwheel・仮想環境・fixtureの作業ツリー・Coreの観測結果をワーカーの間で共有しない。
   依存パッケージのダウンロードのキャッシュの利用は許可する。各組は全fixtureをちょうど1回実行し、Step 2以降は
   各組の分割1のクローンで、構文解析器のアダプターも実行する。既存の2つのクローンによる方式を置き換える場合も、
   全件の独立した2回と、構文解析器のアダプターの独立した2回という条件を弱めない。
4. **集約**: `tests/bitz-core/ci_gate_b.py`が、各ワーカーのコミット、CIの実行と試行、分割番号、独立実行番号、
   チェックアウトの識別子、実行の前後のクリーンな状態、harnessの終了コード、構文解析器の結果を検査する。
   全分割の欠落・重複・未知のID・順序の不整合・失敗・集計の不整合を拒否する。分割の間と2組の間で、実行環境も一致させる。
   各組のfixtureの列を`steps.json`の累積の順序へ戻し、既存のGate Bの比較関数で、2組の全件の結果と構文解析器の出力を比較する。
   成果物は、同じCIの実行と試行のワーカーからだけ受け入れる。PRの1組だけの成功を、Gate Bの`Passed`と呼ばない。
5. **CIの構成**: PRは4分割の1組を実行する。`main`へのプッシュ・週次・手動は4分割の2組を実行し、通常の適合試験は
   1組目を兼ねる。これとは別の3回目の適合試験を実行しない。Gate Aは独立したジョブで実行する。
   全体としての認定にはGate AとGate Bの両方の成功が必要であり、一方の成功が他方を代替しない。
   同時に動かすワーカーの数の初期値は4とする。
6. **既存の契約**: fixtureの入力・期待値・副作用の比較・上限境界・タイムアウトの条件を変更しない。
   harnessからCoreをインポートしないというADR-049の依存方向を保つ。CIの集約と構文解析器の実行は`tests/bitz-core/`が所有する。

## Consequences

- 並列化は待ち時間を短くするが、ワーカーごとのビルドと起動の分の計算量は増える。不要な3回目の適合試験を減らすことで
  総実行量も減らす。CIの実測値を見て、分割の重みと同時実行数を調整する。
- 部分実行で全件の適合や認定を主張してはならない。集約器の陰性対照を単体試験で常時実行する。
- 分割結果の比較は同じCIの実行と試行を要求するため、CIを再実行するときは全ジョブを再実行する。
- 既存の`certify_gate_b.py --step N`は、ローカルで逐次に行う、2つのクローンによる認定として引き続き利用できる。

## Alternatives

- 境界の値を縮める、上限超過だけを残す、独立実行を1回にする案は、実寸・境界内・再現性の保証を失うため採らない。
- 実行結果のキャッシュを合否に使う案は、今回のコミットでの実行を証明しないため採らない。
