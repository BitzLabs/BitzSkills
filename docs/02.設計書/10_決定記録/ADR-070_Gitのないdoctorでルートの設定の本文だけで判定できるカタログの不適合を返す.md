# ADR-070 Gitのないdoctorでルートの設定の本文だけで判定できるカタログの不適合を返す

## Context

Gitを利用できない（またはリポジトリの外の）複合ワークスペースで、`doctor`は`SPEC-MULTI-GIT-001`だけを返し、ルートの設定の`multiWorkspace`の型の不正、
メンバーの件数の不正、除外のパスの不正、ルートの`workspace.id`の省略（いずれも`SPEC-MULTI-CONFIG-001`）を隠していた（実装の確認事項C50）。
Gitがあれば、同じ入力で`SPEC-MULTI-CONFIG-001`を返す。カタログの検査をGitの境界の確定の後に行っていたためである。

[ADR-063](ADR-063_複合ワークスペースの単独操作の全体事前検査を確定する.md)の`Decision`の5番目の項目は、Gitを利用できない場合、設定自身のスキーマまたは
EARS-AIのメジャーバージョンが非対応で止まればその診断とし、そうでなければ`SPEC-MULTI-GIT-001`（`blocked`）とする、と定めた。
[ADR-065](ADR-065_doctorのGit不在と設定の停止を独立した原因として返す.md)は、この項目を`doctor`について部分改訂し、設定で止まった場合も
`SPEC-MULTI-GIT-001`を返すとした。ただし、ルートの設定が読めて、Gitの不在で止まる場合に、`SPEC-MULTI-GIT-001`だけを返すという部分は変えていなかった。
[`doctor`仕様](../../03.詳細設計/03_操作仕様/04_doctor.md) §3は、設定の不適合とGitの不在を独立した原因とする。

## Decision

1. **部分改訂**。本ADRは、ADR-063の`Decision`の5番目の項目（`doctor`についてはADR-065で部分改訂済み）のうち、
   「そうでなければ診断`SPEC-MULTI-GIT-001`（`blocked`）とする」を、`doctor`についてだけ次の2.のとおり部分改訂する。
   ADR-063とADR-065のほかの`Decision`と、`doctor`以外の操作についての5番目の項目は変えない。
2. **`doctor`**。`doctor`（`--all-workspaces`と単独の`doctor`の全体事前検査）は、Gitの境界を確定できずに止まる場合も、ルートの設定の本文だけで
   判定できる`SPEC-MULTI-CONFIG-001`の条件（ルートの`workspace.id`の省略、`multiWorkspace`の型と件数、除外のパスの不正）を
   `SPEC-MULTI-GIT-001`と並べて返し、検査項目`catalog`を`failed`とする（ユーザーの決定）。検査項目`git`は今どおり`blocked`とする。
   診断の件数はGitがある場合と同じ規則による（ルートの`workspace.id`の省略と`multiWorkspace`の形状の不正はそれぞれ単独の1件、
   除外のパスの不正は要素または2つの要素の組ごとに1件）。メンバーの設定、メンバーのパス、未登録の設定など、ルートの候補の位置に依存する検査は行わない。
3. **ほかの操作**。`context`、`check`、`verify`は、ADR-063の5番目の項目のとおり、`SPEC-MULTI-GIT-001`だけを返す。

## Consequences

- `doctor`が、Gitの不在とカタログの不適合を一度に報告し、利用者が2つの原因を一度に直せる。ADR-065の「設定の不適合とGitの不在は独立した原因」の扱いがそろう。
- カタログの不適合を返した`doctor`の状態は、最悪値の`failed`（終了コード1）になる。
- ルートの候補の位置に依存する検査は、Gitがない場合には結果がGitがある場合と食い違い得るため行わない。
- この扱いを固定する適合fixtureを追加する（ADR-051の追加）。既存のfixtureの入力と期待値は変えない。

## Alternatives

1. **`SPEC-MULTI-GIT-001`だけを返す（今の挙動）**: 規範には反しないが、Gitを入れた後で初めてカタログの不適合が分かる。採らない（ユーザーの決定）。
2. **すべての操作でカタログの不適合をGitの不在より先に判定する**: ADR-063の判断（処理を始められない最初の原因を返す）を変え、`check`と`verify`の結果が変わる。採らない。
3. **メンバーの設定とパスの検査も行う**: ルートの候補の位置がGitの境界と一致する保証がなく、Gitがある場合と結果が食い違い得る。採らない。
