# ADR-037 Gitの基準版と現在版の間の仕様文書の同一性と削除規則

## Context

Gitの変更集合は削除とリネームを保持するが、削除された仕様文書のパスを基準版の文書IDへ対応付ける規則がなかった。
現在版だけを索引すると、承認済みの文書や、不採用・中止の理由を保持する終端の文書の削除を状態遷移として検査できず、
複合ワークスペースのメンバーをカタログから外すことで、配下の仕様文書を検査の対象から除外できる。

またADR-032は、1つのGitの基準版と現在版の2時点の比較で、「現在は削除されているIDが別の意味で再出現した場合」を
検出するとした。しかし、現在版に同じIDが存在すれば、それが同一の文書の移動または改訂か、削除された後の再利用かを、
中間の履歴なしに区別できない。`semanticHash`の差だけでは、正当な改訂との違いを判定できない。

## Decision

1. Coreは、Gitの基準版と現在版について、文書種別、パス、フロントマターのIDを読み、複合ワークスペースでは
   `(workspaceId, documentId)`、単一ワークスペースでは実効ワークスペースIDを補った同じ組を、文書の同一性のキーとする。
2. 基準版と現在版に同じキーが存在する場合は、同一の文書とする。パスだけが異なる場合はリネームとして扱い、
   本文、状態、関係の変更は既存の保護と遷移の規則で検査する。Coreは`semanticHash`の差からIDの再利用を推測しない。
3. 基準版に存在するキーが現在版に存在しない場合は、仕様文書の削除とする。Git管理済みの仕様文書の削除は、種別や状態を問わず、
   診断`SPEC-STATE-TRANSITION-001`（重大度`error`、結果への効果`failed`）とする。廃止・不採用・中止は、`outdated`、`superseded`、
   `rejected`、`cancelled`などの既存の状態と理由で表現し、履歴の文書を残す。
4. Gitの基準版に存在しない、未追跡の新しい仕様文書を、Gitへ記録する前に破棄する操作は、Coreの検査の対象外とする。
5. 複合ワークスペースでは、基準版のカタログと現在版のカタログの両方から索引を作る。メンバーの削除またはパスの変更によって、
   基準版側の仕様文書を現行の索引から隠さず、同じワークスペースIDと文書IDが現在版にあれば移動、なければ削除として、
   `Decision`の2番目または3番目の項目を適用する。仕様文書を持たないメンバーの削除には、既存のカタログの検査だけを適用する。
6. 現在の集合の中の重複は、診断`EAI-CORE-ID-002`および診断`SPEC-ID-DUPLICATE-001`で検出する。
   診断`EAI-CORE-ID-003`はCore 1.0の診断から削除する。削除を含むコミットがCoreの検査を迂回した後の
   長期的なID再利用の禁止は、Gitのレビューの責務とする。
7. Git不在またはコミットのないリポジトリでは、基準版の索引を作れないため、現在の集合の重複と状態の語彙だけを検査する。
   仕様文書の削除と長期的なID再利用を検査できないことを、警告として表示する。
8. Coreは削除済みIDの索引を構築せず、到達可能なGitの履歴を走査しない。

## Consequences

- 削除とリネームが実装者ごとのパスの推測に依存せず、終端の履歴の物理削除も状態遷移として防止できる。
- メンバーのカタログの変更で、基準版側の仕様文書を検査から隠せない。
- 2時点の比較で証明できない「別の意味」を機械で判定せず、正当なリネームと改訂をID再利用と誤判定しない。
- Gitの全履歴の索引と永続する状態を追加せず、Core 1.0の決定論性と軽量性を維持する。
- Coreの検査を経ずに過去の削除がコミットされた場合、後日のID再利用はCoreだけでは検出できない。

## Alternatives

1. **`semanticHash`が変わったリネームをID再利用とみなす**: リネームと同時の正当な改訂を誤検出するため採用しない。
2. **到達可能なGitの履歴から、削除済みIDの索引を構築する**: クローンの深さで結果が変わり、永続する索引と性能の負荷も増えるため
   採用しない。
3. **終端の文書だけ削除を禁止する**: `draft`や`open`などの、終端でない文書の物理削除で、不採用・中止の理由の記録を迂回できるため採用しない。
4. **メンバーのカタログは現在版だけを読む**: メンバーの削除により、基準版の仕様文書を検査の対象外にできるため採用しない。
