# ADR-057 性能基準環境を継続利用可能なWSL2ホストへ更新する

## Context

性能の基準環境のマニフェストはIntel Core i5-13500Hを固定していたが、そのハードウェアを継続利用できない。
Gate Cのフェーズ1の実測照合により、利用可能な環境はAMD Ryzen 9 9900X上のWSL2であり、旧マニフェストとは
CPU、論理コア数、ストレージの種類が一致しないことを確認した。存在しない環境名を自己申告して証拠を作ることはできない。

性能のベースラインはまだ1件も受け入れていないため、基準環境を今変更しても比較可能な履歴を失わない。
一方、GitHubが提供するランナーはハードウェアが固定されないため性能のベースラインには使えないが、性能値を判定しない
下限CPython環境の適合試験には利用できる。

## Decision

1. **性能の基準環境**: `fixtures/performance/environments/core-1-reference.json`の基準を、継続利用できる
   AMD Ryzen 9 9900X（24個の論理コア）上のWSL2へ更新する。環境IDは
   `core-1-linux-wsl2-ryzen-9-9900x`とする。CPython 3.12.x、Git 2.30以上、ext4、cgroup v2による
   プロセスの木構造全体のメモリの計測という条件は維持する。
2. **仮想化の境界**: `comparisonKey`へ`platformClass`を追加し、基準環境は`WSL2`とする。
   WSL2の仮想ディスクは物理媒体をLinuxのゲストから証明できないため、`storageClass`は
   `wsl2-virtual-disk`と記録する。ネイティブのLinuxや別のストレージの種類の結果は`not_comparable`とする。
3. **二環境の独立性**: Gate Cのロール`minimum`は、CPython 3.12を使う別のLinux実行環境で取得し、
   GitHub Actionsを利用してよい。ロール`reference`は本ADRの基準環境で取得する。両ロールは、別々の新しいチェックアウトであることに加え、
   OS、カーネル、アーキテクチャ、CPU、論理コア、プラットフォームの種類、ストレージの種類、ファイルシステムから作る
   環境フィンガープリントが異ならなければならない。同一のホストでロール名だけを変えた2回の実行は認定しない。
4. **隔離条件**: ネットワークの無効、Coreの永続キャッシュなし、`--report`なし、逐次実行という性能測定の隔離条件は維持する。
   フェーズ1の適合試験と単体試験の証拠は、`comparisonKey`と`requiredTools`を照合し、隔離条件は性能測定のランナーで強制する。
5. **既存のSLO**: 経過時間とメモリの固定のSLO、データセット、測定回数、暖機、回帰許容は変更しない。
   最初のベースラインを新しい環境IDの下で取得するまではGate Cを`Pending`とする。

## Consequences

- 用意できないハードウェアへの依存を除き、同じホストでベースラインと将来の回帰測定を継続できる。
- WSL2はWindowsのホストの負荷や電源の状態の影響を受ける。測定するときは他の高負荷の処理を止め、逐次実行し、
  不安定な実行を採用しない。固定のSLOを満たすことは引き続き必要である。
- WSL2の仮想ディスクをローカルSSDと推定しない。比較可能性は観測できるゲスト側の条件だけで判定する。
- 基準環境のマニフェストとスキーマは性能fixtureの変更なので、ADR-051に従ってGate Aを再認定する。
- 旧環境のベースラインは存在しないため、移行または保存すべき測定結果はない。

## Alternatives

1. **i5-13500Hを維持する**: 実行できず、Gate Cと性能のベースラインを永久に確定できないため採らない。
2. **GitHubが提供するランナーを性能の基準にする**: ハードウェアと仮想化の条件が実行ごとに変わり、回帰の比較を安定して
   行えないため採らない。ロール`minimum`の機能適合の証拠に限って利用する。
3. **WSL2のディスクをローカルSSDとみなす**: ゲストから物理媒体を証明できず、実測照合を自己申告へ戻すため採らない。
4. **2つのロールを同一のホストで実行する**: 環境をまたぐ再現性を示さないため、最終認定には採らない。
