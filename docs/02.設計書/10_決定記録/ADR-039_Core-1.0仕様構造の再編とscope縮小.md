# ADR-039 Core 1.0仕様構造の再編とscope縮小

## Context

Core 1.0の設計は、EARS-AI、単一ワークスペースの仕様文書、型付きの依存、コンテキスト、静的検査、実行による検証を
中心に開始した。レビューで契約の欠落を解消する過程で、複合ワークスペース、IDの衝突を自動で改番する支援、将来の
プロファイル、公開する4種類のハッシュ値、必須の改訂履歴、厳格な本文のスタイル、内容の同一性による
`verify`のテスト割当ての重複排除が追加された。

各判断は個別には成立するが、同じ契約を設計書、詳細設計、ユースケース、運用、ADRへ再掲したため、
変更するときに同期すべき範囲が広がった。主要な操作仕様2文書だけで980行あり、Core 1.0の価値を実証する前に、
拡張どうしの相互作用まで実装しなければならない状態になった。

構造化設計、KISS、YAGNI、DRYの観点から、中心的な垂直スライスを残したまま、規範の所有者とスコープを縮小する。
検討事項と採決した事項は提案11に記録した。

## Decision

1. 規範の所有者を、共通契約、EARS-AI言語、仕様文書モデル、コンテキストの解決モデル、操作仕様、SDDフローへ分ける。
   スキーマのフィールド、状態遷移、診断の効果、対象の選択の規則は、1つの正本だけが定義する。
2. ADRは、判断の理由と代替案を保持する、規範ではない履歴とする。現行の契約はADRを読まずに実装できなければならず、
   規範の本文から「ADRを正とする」と参照しない。
3. `check`と`verify`を独立した操作仕様へ分割する。ID、関係、パス、カバレッジは、共有するトレースモデルが所有する。
4. コンテキストの型付きの関係、適用可能性、完全閉包、カバレッジを共有するモデルへ置き、`context`の操作仕様は、入力、提示、
   コンテキストのハッシュ値、取得後の仕様変更の検出、結果を所有する。
5. Core 1.0は、単一のGitリポジトリ内の単一ワークスペースを対象とする。`monorepo.members`、修飾ID、横断所有、
   `--all-workspaces`、複合ワークスペースの対応機能を1.1以降へ延期する。結果のワークスペースIDは`root`に固定する。
6. Core 1.0は、現在の集合の重複IDを`failed`にするが、勝敗の判定、自動での改番の候補、フィールド`idCollisions`、
   診断`SPEC-BASE-AMBIGUOUS-001`、専用の`Integrate`の段階を提供しない。人間が改番し、通常の`check`で確認する。
7. Coreの構文解析器は、名前空間付きの拡張を、不透明な値として保持する。プロファイルのマニフェスト、外部の検証プログラム、
   プロファイル固有の直列化器と移行、プロファイルの互換性の判定を1.1以降へ延期する。SDD、Quality、DDDの各プロファイルの案は、
   規範ではない将来の候補とする。
8. 仕様文書の本文の`Revision History`をCoreの必須項目から外す。正確な差分、変更者、時刻はGitを正とし、重要な理由は
   ADR、PR、コミット、または任意の`Notes`へ記録する。ADRのディレクトリのローカルな記載規則は維持してよい。
9. 公開するハッシュ値は、取得後の仕様変更の検出のための`contextDigest`だけとし、`semanticHash`、`fileHash`、
   `projectionDigest`は公開スキーマから除く。実装は、内部のキャッシュのキーとして、任意の内容のハッシュ値を使ってよい。
10. `verify`のテスト割当ては、コマンド名で識別する。同じコマンド名に属するテストのパスを重複排除して1回実行する。
    異なるコマンド名は、引数列と作業ディレクトリが同じでも、別のテスト割当てとして実行する。
11. Coreの本文の構造の検査は、フロントマター、H1、EARS-AIの配置、REQの`Intent`、`Acceptance Criteria`、
    `Verification`へ限定する。H2の順序、空の任意の節、太字の疑似的な節は、テンプレートと任意のリンターの責務とする。
12. 実装ロードマップは規範の設計から分離し、提案・計画の資料として扱う。
13. EARS-AIの安定ID、走査器、型付きの依存の完全閉包、`MUST`の規範文単位のカバレッジ、承認済み要求の保護、
    未信頼の入力、テストのプロセスのタイムアウトと出力の上限、`failed`、`blocked`、`error`の区別は維持する。

## Consequences

- Core 1.0の実装対象は、単一ワークスペースにおける`context -> check -> verify`の垂直スライスへ縮小される。
- 仕様の変更理由が異なる機能は別の文書となり、操作固有の変更が、ほかの操作の再レビューを要求しにくくなる。
- モノレポの利用者は、Core 1.0ではGitリポジトリのルートの単一の`.spec/`を使用する。複数の`.spec/`による複合ワークスペースはできない。
- 並行するブランチのID衝突は、マージまたはリベースの後の、`check`による重複の検出で見つけ、人間が参照を含めて改番する。
- 改訂履歴の短い要約を、各仕様文書だけで確認する機能は失われる。Gitのログ、PR、ADRを使用する。
- 表示内容そのものの公開ハッシュ値はなくなり、Core 1.0が保証するのは、仕様解釈が古くなったことの検出だけになる。
- 同一の引数列を別のコマンド名で定義した場合は2回実行される。コマンド名が、利用者の実行の意図を表す。
- 旧ADRは判断の履歴として残るが、現行の実装の入力にはしない。

## Alternatives

1. **現行の仕様をそのまま実装する**: すでに契約は詳細化されているが、中心的な価値を実証する前に、横断的な機能を
   一括で実装する必要があり、変更のコストが高いため採用しない。
2. **文書だけ分割し、スコープを維持する**: 発見性は改善するが、相互作用とfixtureの数は減らないため採用しない。
3. **公開操作を`context`と`check`だけに縮小する**: テストの実行までの垂直の価値を検証できないため採用しない。
4. **複合ワークスペースとID改番だけ維持する**: 両機能は、互いにワークスペースの修飾、基準版、集約スキーマへ波及するため、
   単一ワークスペースを実証した後にまとめて再評価する。
5. **すべてのハッシュ値を維持する**: 表示の再現性とキャッシュの観測性は得られるが、Core 1.0の安全の判定に必要なのは
   コンテキストのハッシュ値だけであるため採用しない。

## Notes

- 本ADRはADR-015、ADR-017、ADR-030、ADR-038を文書全体として置換する。
- ADR-014の意味中間表現と段階的な提示形式は維持するが、提示内容のハッシュ値の公開だけを`Decision`の9番目の項目で変更する。
- ADR-018のプロファイルの予約スキーマは現行のCore 1.0から外す。名前空間付きの拡張を失わず保持する判断は維持する。
- ADR-026のタイムアウトとコマンドの結果スキーマは維持するが、テスト割当ての同一性と公開するハッシュ値の構成は`Decision`の9番目と10番目の項目で変更する。
- 再評価の条件は提案11のS1〜S7を参照する。
- `Decision`の5番目の項目の複合ワークスペースの延期、対応する`Consequences`、および本項の再導入の条件は
  [ADR-040](ADR-040_複合workspaceをCore-1.0へ再導入する.md)で置き換えられた。`Decision`の1〜4番目と6〜13番目の項目と、
  複合ワークスペース以外のスコープの縮小は変更しない。
