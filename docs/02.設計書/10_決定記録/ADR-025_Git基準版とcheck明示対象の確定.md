# ADR-025 Git基準版とcheck明示対象の確定

## Context

変更範囲の検査、承認済み要求の保護、TASK境界は「Gitの基準版」を参照していたが、`HEAD`、インデックス、
PRのマージベースのどれを指すか、未追跡のファイルを含むかが未定義だった。また`bitz check`の公開文法は
`ids-or-paths`を受け付ける一方、IDとパスの種別、複数の対象、`--full`との関係を定義していなかった。

## Decision

1. `bitz check`へ`--base <git-revision>`を追加する。未指定の場合の基準版は`HEAD`とし、CIでPR全体を
   検査する場合は、マージベースなどの比較元を明示する。
2. 変更集合は、基準版から現在のインデックスおよび作業ツリーまでの変更と、未追跡かつGitが無視しない
   パスとの和集合とする。削除とリネームを保持し、パスはワークスペース相対の`/`区切りへ正規化する。
3. `--base`は、変更範囲の検査、承認済み要求の保護、TASK境界のすべてへ同じ値を適用し、結果のJSONの
   `revision.base`へ、解決済みのコミットIDを記録する。
4. 基準版を必要とする検査でリビジョンを解決できない場合は、引数不正として終了コード4を返す。
   Git不在またはコミットのないリポジトリでは、既存の縮退の規則に従い、実施できない安全検査を成功として扱わない。
5. 明示対象を指定した`check`は、REQ、TECH、ADR、TASKの文書ID、規範文ID、それらの仕様文書のパスを受け付ける。
   規範文IDとパスは、それらを所有する文書のIDへ正規化する。
6. コードのパス、テストのパス、ディレクトリ、構文上不正なIDまたはパスは、引数不正として終了コード4を返す。
   形式が正しいが存在しないIDは診断`CTX-ROOT-MISSING-001`を、存在しない、または範囲外の仕様文書のパスは
   診断`SPEC-PATH-INVALID-001`を返す。
7. 明示対象は同じ作業ワークスペースに限定し、対象の文書、その強い関係の閉包、直接の逆参照を完全検査する。
   すべての仕様文書の、軽量なフロントマターの索引を作る既存の規則は変更しない。
8. `--full`と明示対象は排他的とする。TASKのIDまたはパスを明示した場合だけ、そのTASKの`changes`の境界を強制する。

## Consequences

- ローカルの作業とCIで、比較の範囲を再現できる。
- 未追跡のファイルがTASK境界から漏れる実装を防止できる。
- `check`の明示した入力を、`verify`と同じく型で検証できる。
- CIは、比較対象のブランチをCoreに推測させず、信頼されたワークフローから`--base`を渡す必要がある。

## Alternatives

1. **常に`HEAD`だけを使う**: クリーンなチェックアウトのCIで、PRの中の承認済みのREQの変更を検出できないため採用しない。
2. **既定のブランチを自動で探索する**: リモートの名前やネットワークの状態に依存し、オフラインでの決定性を失うため採用しない。
3. **コードとテストのパスから仕様文書を逆引きする**: 多対多の暗黙の選択となり、対応のないパスの扱いも不安定なため採用しない。

## Notes

- 本ADRは2026-08-31のP2の残存契約レビュー「Git基準版」と「check明示対象」に対する裁定である。
- `Decision`の8番目の項目の明示対象の限定は、引数なし、`--full`、`--all-workspaces`でTASKが検査の対象になった場合にも維持する。
  これらはTASKの文書を検査するが、`changes`の境界を適用しない。完了または取止めのときは、TASK IDを明示して境界を検査する。
