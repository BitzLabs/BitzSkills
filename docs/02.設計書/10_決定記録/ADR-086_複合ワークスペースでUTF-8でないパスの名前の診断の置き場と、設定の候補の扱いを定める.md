# ADR-086 複合ワークスペースでUTF-8でないパスの名前の診断の置き場と、設定の候補の扱いを定める

## Context

[ADR-084](ADR-084_Gitの読取りの既知の問題を解消し、SHA-256のリポジトリに対応する.md)の決定1は、Coreが`check`と全体事前検査で読むGitのパスの一覧に、
UTF-8として復号できないパスがある場合に、そのパスごとに`CHECK-PATH-NOT-UTF8`（`SPEC-PATH-INVALID-001`、`failed`、継続単位`continue`）を返し、
そのパスを一覧から除いて続けると定めた。

適合fixtureを作る中で、複合ワークスペースについて次の点が決まっていないことが分かった。

1. **診断の置き場**。`check --all-workspaces`の変更集合にUTF-8でないパスがある場合に、診断を最上位の`diagnostics`に置くか、パスを所有するワークスペースの
   `diagnostics`に置くか。`source.workspaceId`と`source.path`を、どのルートから表すか。
2. **設定の候補の一覧**。全体事前検査は、Gitが認識する`.spec/bitz.yaml`の候補の一覧を、カタログと比べる（[複合ワークスペース仕様 §8](../../03.詳細設計/02_仕様文書モデル/05_複合ワークスペース仕様.md#8-全体操作の共通規則)）。
   カタログのパスはUTF-8なので、UTF-8でない候補は必ずカタログにない。ADR-084の決定1のとおり除いて続けると、未登録の設定の検査をすり抜ける。
   また、`failed`の診断で処理を続けることは、全体事前検査が非成功ならワークスペースの処理を始めないという§8の規則と食い違う。
3. **submoduleとworktreeの一覧**。全体事前検査がメンバーのパスの検査に使うsubmoduleとworktreeの一覧にも、同じ問題がある。

## Decision

1. **所有するワークスペースに置く**。全体操作の`check`で、変更集合のUTF-8でないパスの`CHECK-PATH-NOT-UTF8`は、そのパスを所有するワークスペースの`diagnostics`に置く。
   `source.workspaceId`はそのワークスペースのID、`source.path`はそのワークスペースのルートからの相対のパスとする（単独の`check`と同じ結果）。
   所有の判定（[複合ワークスペース仕様 §5](../../03.詳細設計/02_仕様文書モデル/05_複合ワークスペース仕様.md#5-所有境界)）では、UTF-8として復号できないセグメントは、
   どのメンバーのパスのセグメントとも一致しないものとする。
2. **設定の候補は未登録の設定とする**（ADR-084の決定1の部分改訂）。全体事前検査で、Gitが認識する設定の候補の一覧に、UTF-8として復号できないパスがある場合は、
   `CHECK-PATH-NOT-UTF8`を返さず、既存の`MULTI-UNREGISTERED`（`SPEC-MULTI-UNREGISTERED-001`、`blocked`、継続単位`stop-multi-workspace`）とする。
   全体事前検査を止め、`workspaces: []`で結果を返す。`source.workspaceId`は`null`、`source.path`はADR-084の決定1と同じく`\xNN`で表したパス、
   `summary`は既存の`Gitが認識する設定ファイルがカタログに登録されていません`とする。単独の`check`の入れ子のワークスペースの判定
   （[ADR-074](ADR-074_入れ子のワークスペースをTASK境界から除き、経過の記録と計画の置き場を予約する.md)）は、ADR-084の決定1のままとする。
3. **submoduleとworktreeの一覧では診断しない**（ADR-084の決定1の部分改訂）。全体事前検査がメンバーのパスの検査に使うsubmoduleとworktreeの一覧に、
   UTF-8として復号できないパスがある場合は、診断を返さずに一覧から除く。メンバーのパスはUTF-8なので、UTF-8でないパスは、メンバーのパスと同じにも、
   その上位のディレクトリにもならない。検査の結果は変わらない。
4. **適合harnessの入力**。`setup.objectFormat`は`setup.git: true`を要し、`setup.git`が`false`のfixtureに書けば準備の誤りとする
   （[ADR-085](ADR-085_適合harnessでUTF-8でない名前とSHA-256のコミットIDを扱い、壊れたリビジョンの設定の診断の形を定める.md)の明確化）。

## Consequences

- 複合ワークスペースの`check`で、UTF-8でないパスの診断が、単独の`check`と同じ形になる。
- UTF-8でない名前の設定があれば、全体操作は止まる。未登録の設定の検査をすり抜けない。
- 全体事前検査は、`failed`の診断で処理を続けることがない（§8の規則のまま）。
- 診断レジストリの`CHECK-PATH-NOT-UTF8`の説明、安全な入出力・互換性 §6、複合ワークスペース仕様 §5と§8、適合fixture仕様 §3.1を改める。
  新しい条件と文言は加えない。適合fixtureを足す。

## Alternatives

1. **最上位の`diagnostics`に置く**: 単独の`check`と形が分かれる。採らない（ユーザーの決定）。
2. **設定の候補も除いて続ける（ADR-084の文面のまま）**: 未登録の設定の検査をすり抜け、§8の規則とも食い違う。採らない（ユーザーの決定）。
3. **設定の候補に新しい条件を設ける**: 原因（カタログにない設定）が同じなので、既存の条件と文言で足りる。採らない。

## Notes

- 2026-11-28に、利用者がDecisionの1と2のもとになった案を選んだ（所有するワークスペースに置く、全体事前検査を止める）。
  2で既存の`MULTI-UNREGISTERED`を使うこと、Decisionの3と4は、起票者の案である。
- 本ADRは、ADR-084の決定1の適用範囲（全体事前検査で読む一覧）を部分改訂する。そのほかの決定は変えない。
