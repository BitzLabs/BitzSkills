# ADR-032 ID再利用検出のCore保証範囲

## Context

文書IDと規範文IDは削除後の再利用を禁止し、`EAI-CORE-ID-003`を「削除済みIDの再利用」として定義している。
一方、通常検査が参照する履歴範囲は現在のSPEC集合と1つのGit基準版であり、過去のcommitで削除・commit済みの
IDを探索する規則は定義されていなかった。禁止規則の適用範囲が、実装者から一意に読み取れなかった。

保証範囲を到達可能Git履歴全体へ広げる案も検討した。しかしshallow cloneでは到達できるcommitが異なるため、
同じ作業ツリーに対する`EAI-CORE-ID-003`の有無がclone深度で変わる。「同一入力から同一Semantic IRと
Diagnosticを再現できる」ことはPhase 1の完了条件であり、Core 1.0の中核契約である。

## Decision

1. `EAI-CORE-ID-003`の適用範囲を「Git基準版に存在し、現在は削除されているIDが、別の意味で再出現した場合」
   と定義する。Coreが保証するID再利用検出はここまでとする。
2. 現在のSPEC集合内の重複は従来どおり`EAI-CORE-ID-002`および`SPEC-ID-DUPLICATE-001`で検出する。
   本決定はこれを変更しない。
3. Git基準版を利用できない場合（Git不在、unborn repository）は`EAI-CORE-ID-003`を実施不能とし、
   [更新・互換性・安全性](../../03.詳細設計/02_SPECファイル規定/07_更新・互換性・安全性.md) §8の縮退表へ
   warningとして明示する。実施できなかった検査を成功扱いしない。
4. Git基準版より前の履歴におけるID再利用の禁止は、Coreの機械保証ではなくGitレビューの責務とする。
   規範としての禁止規則自体は維持し、保証主体だけを分ける。
5. CoreはID tombstone索引を構築せず、到達可能Git履歴の走査を行わない。
6. 実際のID再利用事故が確認された場合に限り、履歴索引の導入を新しい提案またはADRとして再評価する。

## Consequences

- ID再利用検出の結果がclone深度に依存せず、決定論性の契約が保たれる。
- 通常検査と`--full`のいずれでも、履歴走査による性能劣化が発生しない。
- 長期間を隔てたID再利用はCoreが検出しない。禁止規則の最終的な担保はレビューとなる。
- Git不在時に失われる保証の一覧へ1項目が加わり、`bitz doctor`の表示と一致する。

## Alternatives

1. **到達可能Git履歴からtombstone索引を構築する**: shallow cloneで結果が変わり、決定論性の契約を破る。
   10,000 SPECの索引作成性能とも両立しないため採用しない。
2. **削除済みIDの再利用禁止を規範から外す**: IDを永続識別子とする前提が崩れ、`addresses`、`covers`、
   Context Bundleの網羅判定が過去の意味と混線するため採用しない。
3. **再利用検出をwarningへ降格する**: 基準版内で検出できる範囲では意味の取り違えが確実に起きるため、
   errorを維持する。
