# ADR-084 Gitの読取りの既知の問題を解消し、SHA-256のリポジトリに対応する

## Context

[ADR-083](ADR-083_変更集合をGitの名前の変更の検出なしに求め、Gitの読取りの失敗をblockedにする.md)の`Notes`に、次の既知の問題を記録した。

1. **UTF-8でないパスの名前**。Gitから得たパス（未追跡のパスなど）の名前がUTF-8として復号できないと、変更集合の出力を復号できず、`check`全体が`blocked`になる。
   [安全な入出力・互換性 §6](../../03.詳細設計/00_共通契約/02_安全な入出力・互換性.md)は、Gitから得たパスをUTF-8のセグメントの列とするとだけ定め、復号できない場合を定めていない。
2. **比べるリビジョンの壊れたルートの設定**。複合ワークスペースの全体事前検査は、比べるリビジョンのルートの設定が通常のファイルでない場合と、YAMLのマッピングとして
   読めない場合を「設定がない」とする。そのため、そのリビジョンのルートの設定を壊すと、そのリビジョンの未登録の設定の検査が行われない。
3. **`context`と`verify`の`revision`**。作業ツリーの状態と`HEAD`の読取りが失敗すると、`revision.dirty`を`false`、`HEAD`を`null`と黙って扱う。
4. **`doctor`**。`check`を止める状態（壊れた`HEAD`の参照、Gitが所有者を疑ってリポジトリを拒む状態など）を報告せず、単一ワークスペースで`git: passed`を返す。
5. **SHA-256のリポジトリ**。Coreはコミットを40桁の16進数だけで扱い、SHA-256のリポジトリでは`HEAD`を解決できない。`check`は`SPEC-GIT-CHANGES-001`で止まる。
   結果のJSON Schemaも、コミットIDを40桁に固定している。

## Decision

1. **UTF-8でないパスの名前**。Coreが`check`と全体事前検査で読むGitのパスの一覧に、UTF-8として復号できないパスがある場合は、操作を止めず、そのパスごとに
   新しい条件`CHECK-PATH-NOT-UTF8`（診断コード`SPEC-PATH-INVALID-001`、重大度`error`、結果への効果`failed`、発生元`file`、継続単位`continue`）を返し、
   そのパスを一覧から除いて続ける。変更集合では、そのパスを`selection`の件数に数える（どの逆索引にも該当しないパスとして数える）。
   診断の`source.path`と`summary`のパスは、復号できないバイトを`\xNN`（小文字の16進数2桁）で表した文字列とする。`summary`は`パス{path}の名前をUTF-8として読めません`とする。
2. **比べるリビジョンの壊れたルートの設定**。比べるリビジョンにルートの設定のパスが存在するのに、通常のファイルでない場合と、YAMLのマッピングとして読めない場合は、
   全体事前検査の不適合として、新しい条件`MULTI-REVISION-ROOT-CONFIG-INVALID`（診断コード`SPEC-MULTI-CONFIG-001`、重大度`error`、結果への効果`failed`、
   発生元`file`、継続単位`stop-multi-workspace`）とする。`summary`は`比べるリビジョンのルートワークスペースの設定が不正です`とする。
   Gitがパスの不在を示した場合だけ、設定がないとする（ADR-083のまま）。
3. **`context`と`verify`の`revision`**。作業ツリーの状態、`HEAD`、リポジトリのルートの読取りが失敗した場合は、推測せず、結果の`revision`を`null`とする
   （Git不在と同じ形）。操作は止めず、診断は返さない。
4. **`doctor`**。`doctor`の検査項目`git`は、Gitの利用可否と版に加えて、`check`と同じGitの読取り（リポジトリのルート、`HEAD`の解決、作業ツリーの状態）を確かめる。
   失敗した場合は、単一ワークスペースでは新しい条件`DOCTOR-GIT-READ`（診断コード`SPEC-DOCTOR-GIT-001`、重大度`warning`、結果への効果`passed_with_warnings`、
   発生元`environment`、継続単位`continue`）とし、検査項目`git`を`warning`にする。`summary`は`Gitからリポジトリの状態を読めません`とする。
   複合ワークスペースでは`SPEC-MULTI-GIT-001`（`blocked`）とする。コミットのないリポジトリとリポジトリの外は、失敗としない（ADR-083と同じ判定）。
5. **SHA-256のリポジトリ**。Core 1.0は、オブジェクトの形式がSHA-1とSHA-256のリポジトリを対象とする。コミットIDは、リポジトリのオブジェクトの形式に応じて
   40桁または64桁の小文字の16進数とする。結果のJSON Schemaの`revision`のコミットIDは、どちらも受け付ける。ほかの規則（変更集合、途中のコミット、基準版）は、
   オブジェクトの形式によらず同じとする。適合harnessの準備に、リポジトリのオブジェクトの形式を指定する入力（`setup.objectFormat`、既定は`sha1`）を加え、
   SHA-256のリポジトリの適合fixtureを置く（[ADR-048](ADR-048_適合fixtureの生成入力とGit構造の準備の処理を確定する.md)と
   [ADR-080](ADR-080_適合harnessの準備の処理にコミット、枝、マージ、シャロークローンを加える.md)の部分改訂）。

## Consequences

- UTF-8でないパスの名前があっても、`check`全体は止まらず、そのパスだけを診断する。
- 比べるリビジョンのルートの設定を壊して、未登録の設定の検査を外すことができなくなる。
- `context`と`verify`は、Gitの不調で誤った`revision`を返さない。
- `doctor`が、`check`を止める状態を報告する。単一ワークスペースでは`warning`なので、`doctor`の終了コードは`check`より軽い（Git不在と同じ）。
- SHA-256のリポジトリで、Coreが動く。結果のJSON Schemaの`revision`の形が広がる。
- 診断レジストリに条件を3つ加える。文言は、利用者の承認を得て決める（ADR-062）。
- 安全な入出力・互換性、`check`仕様、`context`仕様、`verify`仕様、`doctor`仕様、複合ワークスペース仕様、結果・診断・終了コード、結果のJSON Schema、
  適合fixture仕様、Core実行環境・CLI基盤契約を改める。適合fixtureを足す。

## Alternatives

1. **UTF-8でないパスの名前で、今のまま止める**: 無関係な1つのファイルで、`check`全体が使えなくなる。採らない（ユーザーの決定）。
2. **壊れたルートの設定を「設定がない」とする（今の扱い）**: 設定を壊して検査を外せる。採らない（ユーザーの決定）。
3. **`context`と`verify`も`check`と同じく止める**: Gitがなくても動く操作が、Gitの不調で使えなくなる。採らない（ユーザーの決定）。
4. **`doctor`はGitの利用可否と版だけを確かめる（今の扱い）**: 原因を調べる道具が、手がかりを返さない。採らない（ユーザーの決定）。
5. **SHA-256のリポジトリを非対応と明示し、Git不在として縮退する**: 結果の形は変わらないが、SHA-256のリポジトリで差分の保証を失う。採らない（ユーザーの決定）。

## Notes

- 2026-11-23に、利用者がDecisionの1から5のもとになった案を選んだ。条件の名前、診断コードの割り当て、`summary`の文言、パスの表し方（`\xNN`）、
  `setup.objectFormat`は、起票者の案である。
- 起票者は、Decisionの2の案を選んでいただく質問で、`SPEC-MULTI-CONFIG-001`の結果への効果を`blocked`と書いた。これは誤りで、既存の条件のとおり`failed`である
  （継続単位`stop-multi-workspace`で、操作は止まる）。
- ADR-083の`Notes`に記録した既知の問題のうち、本ADRの5つを解消する。
