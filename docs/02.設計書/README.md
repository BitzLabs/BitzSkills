# Bitz AI-SDD Core 1.0設計

## 1. 目的

個人から数人のチームがAI CLIを利用するとき、仕様の取り違え、参照切れ、検証漏れ、危険な自動変更を
少ない待ち時間で防ぐ。

EARS-AIと、単一ワークスペースまたは明示的に束ねた複合ワークスペースの`.spec/`を、人間、AI、テストが共有する小さな契約面とする。

## 2. 中心価値

EARS-AIは、自然言語の要求へ、安定したID、実行主体、発動条件、規範強度、期待結果を付与する。人間が読め、
構文解析器が決定論的に構造化でき、必要な制約をコンテキストとしてAIへ渡せることを価値とする。

保証するのは、構文、参照、型付きの依存、機械で検査できるトレースとテストの実行である。自由記述の意味の正しさ、
LLMの出力の決定論性、実装の完全性は保証せず、人間のレビューとテストで補う。

## 3. 原則

1. Core 1.0は、ワークスペース単位の垂直スライスと、同一のGitリポジトリ内の明示的な複合ワークスペースを提供する。
2. 既定の処理はローカル、オフライン、決定論的にする。
3. 強い依存を完全解決し、部分的なコンテキストを成功として扱わない。
4. すべての`MUST`の規範文とテスト対応を追跡する。
5. LLMの評価を必須の合否に使わない。
6. Gitを変更履歴、レビュー、監査の正とする。
7. 仕様文書の本文からコマンドと権限を取得しない。
8. 結果の状態にかかわらず既定の保存物を作らず、明示したときだけ最小のレポートを保存する。
9. 1規則1正本とし、ADRを現行契約の正本にしない。
10. 実測で必要性を確認してから拡張を追加する。

## 4. 公開操作

| 操作 | 役割 |
|---|---|
| `bitz context` | 完全な依存解決、制約台帳、カバレッジ、コンテキストのハッシュ値 |
| `bitz check` | EARS-AI、スキーマ、ID、関係、トレース、Gitの差分の検査 |
| `bitz verify` | 規範文に対応するテストコマンドの実行 |
| `bitz doctor` | 導入、設定、互換性、環境の診断 |

## 6. Core 1.0対象外

- ID衝突の勝敗判定と自動の改番候補
- プロファイルのマニフェスト、外部の検証プログラム、プロファイル固有の直列化器／移行
- 必須の`Revision History`節
- 文書単位のハッシュ値と、提示内容のハッシュ値の公開
- 厳格なMarkdownのH2の順序・空の節のスタイルの検査
- LLMによる意味の監査、DDD、自動の逆同期
- 永続的な実行、承認サービス、ワークフローエンジン
- 複数のGitリポジトリ、Gitのサブモジュール、ネットワーク越しの仕様文書による複合ワークスペース

複合ワークスペースは[ADR-040](10_決定記録/ADR-040_複合ワークスペースをCore-1.0へ再導入する.md)により
Core 1.0へ含める。`verify`の検証対象ごとの証跡と、レポートを明示して保存することは
[ADR-041](10_決定記録/ADR-041_検証対象ごとの証跡とレポートの明示保存の分離.md)に従う。その他の対象外の機能は
[ADR-039](10_決定記録/ADR-039_Core-1.0の仕様構造の再編とスコープの縮小.md)の簡素化の判断を維持する。
複合ワークスペースについて、ワークスペースの同一性、所有境界、公開スキーマ、CLI、リソースと性能の条件は
[ADR-042](10_決定記録/ADR-042_複合ワークスペースの同一性・所有境界・公開契約を確定する.md)で確定した。継続、
TASK境界、ロールバック、計算量、適合条件は
[ADR-043](10_決定記録/ADR-043_複合ワークスペースの継続・TASK境界・適合契約を確定する.md)で確定した。
