# テスト戦略

このリポジトリは「AIエージェント向け標準環境をプラグイン／スキルとして配布する」
library であり、対象は主にスクリプト（`scripts/`）・SDDツール・スキル定義（Markdown +
frontmatter）である。UIやAPIサーバーは持たないため、検証は「機械チェックの直列実行」と
「スキルの効果測定」の2系統が中心になる。

## 検証は3系統＋スキル層品質ゲート

| # | コマンド | 検証対象 |
|---|---|---|
| 1 | `python3 scripts/release_check.py` | 3マニフェストのversion整合、`marketplace.json`⇔`plugins/`実体の双方向整合、全SKILL.mdのfrontmatter必須項目、委譲レジストリ（CLAUDE.md）⇔`.claude/agents/*.md`の整合、依存グラフ、対訳辞書SSOT整合、フェーズ正規語彙⇔文書マーカー整合 |
| 2 | `pytest tests/ -v` | `scripts/` 配下の各ツール（`bump_version.py`／`release_check.py`／`spec` ラッパー等）のロジック回帰。対象は `tests/test_*.py`（例: `test_release_check.py`・`test_bump_version.py`・`test_docs_inspect.py`・`test_spec_*.py`・`test_delegation_registry.py` 等） |
| 3 | `python3 scripts/spec inspect --workspace . plugins/* --check-only` | `.spec/` 配下のEARS要件・spec-issue・クロスリファレンスの機械検証。このモノリポでは常に `--workspace . plugins/*` を使う（ルート単体はクロスワークスペース参照を解決できず幽霊参照でFAILするため使わない）。日常の検証は `--check-only` を既定とし、`inspection-report.md` を書き換えない。判定は終了コードが正であり、CI もコミット済みレポートを読まない。レポート更新は締め工程だけで行う |

`docs/` の整合は上記に加えて `sdd-docs` の `docs_inspect.py` を用いる
（本文書自身もこの検査対象）。

## スキル層の品質ゲート（スキル追加・変更時）

- **skill-validator**: `plugins/skill-creator/skills/skill-validator/references/checklist.md`
  に基づく構造・frontmatter・記述スタイルのチェックリスト検査
- **skill-tester**: `plugins/skill-creator/skills/skill-tester/references/test-design.md` の
  書式で `evals/<skill-name>/cases.md` にテストケースを設計し、「スキルあり」と
  「スキルなしベースライン」の両方を実行して `evals/<skill-name>/runs/` に記録する
- **skill-evaluator**: 上記の実行結果をアサーションに照らして採点し、
  `evals/<skill-name>/report.md` を作成する（スキルの有無で差が出ているかを確認する）

## CIゲート（`.github/workflows/ci.yml`）

- `pull_request` イベントでPRタイトルがConventional Commits（`feat|fix|docs|refactor|test|chore`、
  破壊的変更は `!`）に準拠するかを検査する
- `push`/`pull_request` の両方で `pytest tests/ -v` → `python3 scripts/release_check.py` を
  この順で実行する。いずれかが失敗すればCIは red

## 「緑」の定義

以下が揃った状態のみを「検証済み」とみなす。カバレッジ数値そのものは目的にしない。

- `pytest tests/` が全件PASS
- `python3 scripts/release_check.py` が全項目PASS（1つでもFAILがあれば未検証）
- `python3 scripts/spec inspect --workspace . plugins/* --check-only` がERROR 0
- スキルを追加・変更した場合は skill-validator のチェックリストで❌が無いこと
  （⚠️は許容するが根拠を残す）

## 検証義務（他エージェントの自己申告を信用しない）

`AGENTS.md` の検証義務に基づき、委譲先・相談先が「成功しました」「PASSしました」と
報告しても、それ自体を合格の根拠にしない。司令塔（または担当者本人）が上記1〜3の
コマンドを**自分で再実行**し、実際の出力（exit code とログ）を確認してから
「検証済み」と扱う。これはテスト戦略の一部であり、レビュー・マージ判断の前提条件である。

## ロールバックと粒度

検証が失敗した変更は1 PR = 1関心事の粒度でマージしない。失敗の切り分けは
`git revert` で丸ごと戻せることを前提に設計する（詳細は「運用・リリース」参照）。
