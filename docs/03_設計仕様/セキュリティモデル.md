# セキュリティモデル

このリポジトリの脅威モデルは「AIエージェントが自律的にコマンドを実行する」ことを前提とし、
機密漏洩・破壊的操作・意図しないリポジトリ外書き込みの防止に焦点を置く。外部ネットワーク攻撃面
（Web アプリの認証・認可等）は対象外（`docs/00_はじめに/対象外.md` の Won't 節）。

## 信頼境界とデータ分類

- **信頼境界1: リポジトリ内 / リポジトリ外** — リポジトリ内の書き込みは通常操作。リポジトリ外
  （`~/.claude/skills/`・`~/.gemini/config/skills/`・`~/.agents/skills/` 等、skill-packager による
  配置・上書き・削除を含む）への書き込みはユーザーの明示承認を要する。
- **信頼境界2: エージェント種別** — Claude Code / Codex CLI / Antigravity(agy) はそれぞれ独立した
  実行環境として扱い、各々のガードレール（permissions・フック）を個別に持つ。一方の緩和が他方に
  波及しない。
- **データ分類**: 認証情報・トークン類（`~/.claude/.credentials.json`・`.env` 等）は最高機密として
  扱い、読み取り・出力ともに禁止。それ以外のリポジトリ内容（`.spec`・`docs`・`plugins`・`evals`）は
  Git 追跡下の非機密データとして扱う。

## 想定脅威と緩和方針

| 脅威 | 影響 | 緩和 |
|---|---|---|
| エージェントが破壊的 Git 操作を実行（`push --force`・`reset --hard`・`clean -f`） | 作業消失・履歴破壊 | `.claude/settings.json` の `permissions.deny` で機械的にブロック（AGENTS.md 禁止操作と対応） |
| エージェントが `rm -rf` / `sudo` を実行 | ホスト破壊・権限昇格 | 同上、`deny` リストに列挙 |
| エージェントが認証情報ファイルを読み取り・出力 | 秘密漏洩 | `permissions.deny` の `Read(~/.claude/.credentials.json)` / `Read(.env)` / `Read(.env.*)` |
| エージェントがリポジトリ外へ無承認で書き込み | 他プロジェクト・ホーム環境の汚染 | `permissions.ask` でユーザー確認を強制（skill-packager の配置系操作を含む） |
| main / デフォルトブランチへの直接コミット | レビュー無しの変更混入 | AGENTS.md ガードレールで禁止（機械強制は各リポジトリの CI/ブランチ保護に委ねる） |
| 他エージェント（サブエージェント・委譲先）の「成功しました」自己申告の誤り | 未検証の不具合が見過ごされる | `release_check.py` 等の機械チェックを司令塔が自分で再実行して検収する（検証義務） |
| skill-improver 等の自動修正がスキルを意図せず壊す | スキル品質劣化 | コミット前に人間が diff を確認する運用ルール |

## ガードレール3層の対応関係

`.claude/settings.json` の permissions ⇔ プラグイン同梱フック ⇔ AGENTS.md ナラティブの3層は
常に同期させる（片方だけを緩めない）。

| 層 | 実体 | 役割 |
|---|---|---|
| 機械強制（設定） | `.claude/settings.json` の `permissions.allow/deny/ask` | Claude Code が起動時に読み込み、該当コマンドを機械的にブロック/確認要求 |
| 機械強制（フック） | 各プラグイン同梱フック（bitz-env 等） | ツール実行前後で危険操作を検査（PreToolUse 等） |
| ナラティブ（規律） | AGENTS.md ガードレール節・CLAUDE.md | エージェントが読んで従う人間可読の規約。機械強制の意図を説明する |

同期ズレの検出は `bitz-env:env-doctor` が担う。ルールを緩めるときは、この3層すべてを見直す
（AGENTS.md に明記）。

## library 固有

- **入力検証**: `scripts/*.py`（`release_check.py` / `bump_version.py` / `spec` ラッパー等）は
  リポジトリ内の JSON / Markdown frontmatter のみを対象とし、外部ネットワーク入力を受け付けない。
- **安全なデフォルト**: 新規プラグイン導入時も `enabledPlugins` で明示的に有効化しない限り
  無効（全プラグイン強制導入をしない設計）。
- **依存の供給網（supply chain）**: プラグイン間依存は `metadata.dependencies` に semver 制約付きで
  宣言し、`release_check.py` が依存先の実在・制約充足・循環の不在を検査する（CORE-FR-013）。
  外部パッケージレジストリへの依存は現時点で無い。
- **秘密情報の非取り扱い**: ログ・エラーメッセージ・コミット・観察ログ（`observations.jsonl`）に
  認証情報を出力しない契約。委譲先エージェントへのプロンプトにも秘密情報を含めない。
