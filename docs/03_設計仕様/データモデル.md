# データモデル

本リポジトリは RDB を持たない。「データ」はすべてファイルベースの構造化ドキュメント
（JSON / Markdown+frontmatter / JSONL）であり、各正（SSOT）はディレクトリ単位で分散する。

## 論理データモデル（構造とその正の所在）

```
plugins/<name>/.claude-plugin/plugin.json   ─┐
plugins/<name>/plugin.json                   ├─ 3マニフェスト JSON（version 同値。CORE-CON-001）
plugins/<name>/.codex-plugin/plugin.json    ─┘

plugins/<name>/skills/<skill>/SKILL.md
  frontmatter: name, description, metadata{version,author,created,updated}, [installed-at, installed-from]

.spec/requirements/<ID>.md          … EARS要件 frontmatter（id, version, status, domain, priority ...）
.spec/design/DSN-*.md               … 設計文書 frontmatter（id, implements, origin, status ...）
docs/**/*.md                        … ナラティブ frontmatter（id, title, status, version, changeImpact,
                                       project_type, updated, owner, superseded_by）

evals/observations/observations.jsonl  … 1行1観察の JSON（JSONL、追記のみ）
.claude/<plugin>.local.md              … プラグインごとのローカルレジストリ（YAML frontmatter + 本文）
```

各構造の「正」は次の通り:

| データ | 正の所在 |
|---|---|
| 3マニフェスト JSON のキー体系 | `scripts/bump_version.py` / `release_check.py` の読み取り実装 |
| SKILL.md frontmatter 仕様 | `plugins/skill-creator/skills/skill-creator/references/spec.md` |
| `.spec/` 成果物 frontmatter 書式 | bitz-sdd の sdd-core（artifact-frontmatter 書式） |
| `evals/observations/observations.jsonl` スキーマ | `plugins/skill-creator/skills/skill-observer/references/observation-schema.md` |
| `.claude/<plugin>.local.md` の形式 | 各プラグインのライフサイクルスキル（例: `bitz-env:env-init` が生成する `bitz-env.local.md`） |

## 格納方式の選定

- 全データを Git 管理下のプレーンテキスト（JSON / Markdown）で格納する。DB・キャッシュ層は
  採用しない。理由: エージェントによる読み書きと人間レビュー（diff）の両立、`git revert` による
  ロールバックの単純さを優先するため（実運用上の証拠: AGENTS.md の 1PR=1関心事規約）。
- JSONL（`observations.jsonl`）のみ追記専用ログとして例外的に採用する。集計・分析
  （`skill-improver`）は読み取り専用で行う。

## 物理スキーマ / ファイル形式

- **3マニフェスト JSON**: `name` / `version` / `description` / `metadata.dependencies`（任意）を持つ。
  3ファイルの `version` は常に同値（`bump_version.py` が原子的に更新）。
- **SKILL.md frontmatter（YAML）**: `name`（親フォルダ名と一致必須）/ `description` / 任意で
  `license` / `compatibility` / `metadata`（version・author・created・updated が必須） /
  `allowed-tools`。
- **`.spec` frontmatter（YAML）**: 要件は `id` / `version` / `status` / `domain` / `priority` /
  `origin` / `verification_method` / `derived_from` / `supersedes` / `superseded_by` / `confidence`。
  設計文書は `id` / `title` / `implements` / `origin` / `status`。
- **`docs/` frontmatter（YAML）**: `id` / `title` / `status` / `version` / `changeImpact` /
  `project_type` / `updated` / `owner` / `superseded_by`（本6ファイルが従う契約と同一）。
- **observations.jsonl**: 1行1 JSON オブジェクト。フィールド定義は observation-schema.md が正。
  整形（複数行 JSON）は禁止。

## 永続化戦略

- トランザクション境界は「1コミット」。集約境界に相当するのは「1プラグイン」または
  「1 `.spec` 成果物」で、変更は原則そのファイル群に閉じる。
- 整合性は Strong（Git コミット単位でしか状態遷移しない。中間状態を他エージェントと共有しない）。
- 保持期間は無期限（Git 履歴で全履歴を保持）。`evals/` 配下の既存成果物削除は事前確認必須
  （AGENTS.md ガードレール）。

## マイグレーション方針

- プラグインが配置先に残す状態（SKILL.md frontmatter の `metadata` スキーマ・`.spec` 系
  frontmatter 書式・`.claude/<plugin>.local.md` 等）の形式変更は、`<plugin名>:update` の
  累積マイグレーション機構（宣言的 Markdown + guard 必須）で移行する。設計の正は
  `.spec/design/DSN-002-update-migration.md`（CORE-CON-009）。
- 中間バージョンのステップ欠落・チェーン断裂時は安全側（書き込み前に停止・提示）で振る舞う。
  ロールバックは適用前バックアップからの復元を原則とし、破壊的置換を避け加算的変換を推奨する。
