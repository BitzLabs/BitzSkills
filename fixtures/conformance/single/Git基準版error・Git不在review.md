## 準備検証と補助スキーマ

既存の副作用のスキーマの`git`だけに`null`を許可し、Git不在と、正常なGitの空の`git status`・インデックスを区別する。
既存のGitありのfixtureのオブジェクトの形式は維持し、各検証プログラムが、実際の準備の状態へ照合する。
Gitの取得の失敗を捕捉して`null`へ変換せず、Git不在を明示した2件だけが`null`を持つ。

3件とも、隔離環境で準備手順を2回行い、固定した入力のバイト列、フロントマターの値、マニフェスト、結果またはCLIの出力の形状、副作用の期待値を照合する。
036では、`HEAD`とインデックスのブロブと、無効なGitの参照を、037と038では、Gitを解決できないことと、ローカルの`.git`の不在を、直接検査する。
`HOME`・キャッシュ・`TMPDIR`も、固定したスナップショットで比較し、`before=after`を要求する。Coreの実際の副作用を観測したとは扱わない。

回帰試験は、終了コード4への`status`の追加、CLIの出力の形状の改変、レポートの消失、Git不在の正常なGitへの変更、`PATH`の制約の除去、
警告の消去、TASKの診断の置換と重複を拒否する。無効なGitの参照が実際に解決可能になった状態、fixtureへの`.git`の追加も拒否する。
