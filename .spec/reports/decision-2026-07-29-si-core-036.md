## 採用理由

`scripts/bump_version.py` は `sys.argv[1]` でしか `-h` / `--help` を見ておらず、
`sys.argv[3]` 以降を一切検査しない。このため
`python3 scripts/bump_version.py <plugin> minor --help` は help を表示せず bump を実行する。

破壊的操作を持つツールが、ユーザーが安全のために付けたフラグを無視して変更を適用する。
ガードレールが「事前確認が必要」としている操作の手前で、ユーザーの確認動作そのものが
空振りする性質の問題であり、実際に SI-SDD-026 の実装中に意図しない bump（3.2.0 → 3.3.0）が
発生している。

## 実施スコープ（今回やること / やらないこと）

のみ**を今回の実施範囲とする。

### 今回実施する

- `--help` が引数位置に関わらず効くようにする
- `--dry-run`（副作用なしで結果を確認する手段）を追加する
- 既存の呼び出し形 `<plugin名> [major|minor|patch]` と part 既定値 `patch` は維持する（後方互換）

## 裁定1: hook スクリプトの扱い → **対象外**

`agy_guard.py` / `env_guard.py` は stdin の JSON で駆動し、CLI 引数契約を持たない。
hooks 設定上も引数なしで起動される（`python3 scripts/env_guard.py`、
`python3 "${CLAUDE_PLUGIN_ROOT}/scripts/env_guard.py"`）。

- 対象外とする理由: これらを「余分な引数を拒否する」実装にすると、将来プラットフォーム側が
  引数を付けて起動する仕様へ変わった瞬間に**ガードレールフックそのものが機能停止**する。
  失うもの（危険操作のブロック）が得るもの（人が手で叩かないスクリプトの引数検査）より大きい
- 要件本文に除外理由を明記し、除外が暗黙の見落としではないことを残す

## 裁定2: 要件の種別 → **CORE-CON（規約）**

対象は特定ツールの機能ではなくリポジトリ全体のスクリプトが従う制約であるため、
`CORE-FR` ではなく `CORE-CON` 系で起票する。既存の `CORE-FR-018`
（`bump_version.py` 単体の引数契約）は本規約の具体化事例として残し、
「共通契約化は未着手」と述べている説明文を改訂する。

## 裁定3: 検証方式 → **動的収集による回帰テスト**

棚卸しを静的な表として文書に固定するのではなく、リポジトリ内の CLI スクリプトを
テスト実行時に glob で収集し、各々へ解釈できない引数を渡して非ゼロ終了することを
確認する回帰テストで担保する。新規スクリプトが追加されたとき、明示的な除外宣言が
無い限り自動的に契約対象へ入る。

- 安全性: テストは一時ディレクトリを作業ディレクトリとして起動する。
  仮に契約違反のスクリプトが処理を続行しても、副作用は一時ディレクトリ内に閉じる

## 残余リスク

- 除外リスト（hook・ライブラリ・ディスパッチャ）はテストコード内の宣言であり、
  新規スクリプトを安易に除外へ追加すれば契約を回避できる。除外の追加は
  レビューで検出する運用に依存する
- 本契約は「未知引数を拒否する」ことだけを保証し、引数の意味が正しいことは保証しない
