# DSN-004 scripts/spec の Claude/Codex 横断解決

- **背景 / 課題**: `scripts/spec` は `BITZSKILLS_PLUGINS_DIR` 未指定時に
  `~/.claude/plugins` の `installed_plugins.json` と `cache/` だけを探索する。
  Codexに `bitz-sdd@bitzskills` がインストール済みでも、実体が
  `$CODEX_HOME/plugins/` 配下にあるため正規コマンドがexit 3で失敗する。
  明示overrideでは成功するため、委譲先ツールや引数透過ではなくプラグインルート探索だけが欠落している。

- **候補モデル**: 解決候補を `platform`（codex / claude / override）、
  `discovery_kind`（cli-pinned / manifest-pinned / cache）、
  `version`、`plugin_root`、`tool_path`、`fingerprint` で表す。
  `plugin_root` は4ツールとルート `plugin.json` を持つ実行対象の版ディレクトリであり、
  Codex CLIの一時的な配布元 `source.path` とは区別する。`fingerprint` はルートmanifestと
  4ツールのSHA-256から算出し、同一versionの実体同一性確認に使う。

- **設計判断**:
  1. 解決処理を「明示override」「インストール済み固定版」「キャッシュfallback」の3段へ分離する。
     `BITZSKILLS_PLUGINS_DIR` が指定された場合は現在と同じ単一ルート契約とし、
     Codex CLIを呼ばず、他プラットフォームのルートへ暗黙fallbackしない。
  2. override未指定時は `codex plugin list --json` を読み取り専用で実行し、
     `pluginId == bitz-sdd@bitzskills` かつ `installed == true`、`enabled == true` の項目を
     Codex固定版メタデータとする。`marketplaceName`、`name`、`version` から
     `${CODEX_HOME:-~/.codex}/plugins/cache/<marketplace>/<name>/<version>` を
     `plugin_root` として決定する。`source.path` は配布元であり実行先には使わない。
  3. Codex discoveryを次の4状態で扱う。
     - `valid`: 有効な固定版を検証して使う。
     - `authoritative-negative`: CLIが正常にdisabled / uninstalled / no-entryを返した状態。
       利用者の無効化を尊重し、Codex cacheをfallback候補から除外する。
     - `unavailable`: CLI不在・timeout・非ゼロ終了。Codex cacheを検証付きfallback候補にできる。
     - `corrupt`: JSON不正・出力上限超過・必須フィールド不正。Codex cacheを候補外にする。
     `valid` な固定版のmanifest不正、version不一致、4ツールのいずれかの欠落・読取不能は
     fallbackせずexit 3で安全停止する。
  4. Claude固定版は従来どおり `~/.claude/plugins/installed_plugins.json` の
     projectPath一致エントリの `installPath` を `plugin_root` として解決する。
     有効な固定版の検証失敗はCodexと同じく安全停止する。
     Codex/Claude両方に固定版がありversionが異なる場合は
     曖昧性としてexit 3で停止し、`BITZSKILLS_PLUGINS_DIR` の明示を要求する。
     同一versionでもfingerprintが異なれば同様に停止し、一致する場合だけCodex候補を優先する。
  5. 固定版がない場合は、Codex discovery状態に応じて許可された
     `${CODEX_HOME:-~/.codex}/plugins/cache` と `~/.claude/plugins/cache` を横断する。
     厳格なSemVerとして妥当で、manifest versionが一致し、4ツールをすべて備えるplugin単位の候補から
     最大版へfallbackする。pre-releaseは同一core versionのreleaseより低く、build metadataは
     precedenceに影響しない。同一最大versionの複数候補はfingerprintが一致する場合だけCodex側を
     優先し、異なる場合は安全停止する。不完全版をツール単位で混用しない。
  6. 解決不能時は探索したルートと、`BITZSKILLS_PLUGINS_DIR=<plugins-root>` を使う
     暫定回避方法をstderrへ出す。`codex-discovery=valid|authoritative-negative|unavailable|corrupt`
     と安全な理由分類、採用経路だけを診断し、CLIのstderrやユーザー設定内容は転記しない。
  7. Codex CLIはshellを介さない引数配列で、`cwd=repo_root`、timeout 5秒、stdout上限1 MiBとして
     実行する。timeout時は子プロセスを終了してから縮退し、既知の起動・timeout・JSON解析エラーだけを
     扱う。認証ファイルやグローバルconfigをラッパー自身が直接読み取らない。
  8. 版ディレクトリは1回のラッパー実行中に不変というプラットフォーム前提を置くが、実行直前にも
     manifest・4ツール・fingerprintを再検証する。消失・置換・実行失敗はtracebackを出さずexit 3と
     再実行案内へ正規化する。完全な原子的実行は保証せず、並行更新時は再試行を復旧手段とする。

- **テスト設計**:
  - 既存のoverride固定版、cache semver、引数・終了コード透過、固定版欠落時の安全停止を維持する。
  - fake `codex plugin list --json` によるCodex固定版解決、disabled/uninstalled除外、
    不正JSON・非ゼロ終了・timeout・出力上限の状態別縮退を検証する。
  - custom `CODEX_HOME` のcache fallback、Claude/Codex固定版競合、明示override優先を検証する。
  - 固定版のmanifest/version/4ツール破損時の安全停止、同一version異fingerprintの停止、
    全ツールを備える単一版の選択、release/RC/不正SemVerの順序を検証する。
  - 実ユーザーのキャッシュ・認証・ネットワークへ依存しないfixtureだけで自動化する。

- **代替案と却下理由**:
  - `~/.codex/plugins/cache` の直接探索だけを追加: 現在の実測配置には合うが、
    インストール済み・有効な固定版を判別できず、Codex更新で内部配置が変わると再発するため却下。
  - `CODEX_HOME` の有無だけで実行プラットフォームを推測: デフォルト値では環境変数が未設定であり、
    Claude/Codexが同じシェルに共存する場合も判別できないため却下。
  - `codex plugin list --json` を唯一の経路にする: Claude専用環境やCodex CLI未導入環境で
    現行機能を失うため却下。公式CLIを固定版発見に使い、既知cache探索は縮退経路として残す。

- **影響範囲・ロールバック**: 変更対象はルート `scripts/spec` と回帰テスト、
  CORE-FR-011の1.1改版、タスク・テスト仕様に限定する。プラグイン本体は変更しない。
  既存overrideとClaude解決をテストで固定してからCodex discoveryを追加する。
  問題時はCodex discoveryと要件1.1を同一実装コミットでrevertすれば1.0挙動へ戻せる。
