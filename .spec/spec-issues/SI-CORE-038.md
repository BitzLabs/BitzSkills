- **目的**: SDD ツールの起動方法が2系統に分かれている。`scripts/spec <tool>` のラッパー経由
  （`inspect` / `scaffold` / `status` / `update`）と、スキル同梱スクリプトの直接実行
  （`sdd_sync.py` / `docs_inspect.py` / `sdd_report.py` / `spec_verify.py`）である。
  ラッパーは候補プラグイン版の検証時に **sdd-core の4ツールすべての実在を必須**とする設計
  （CORE-FR-011）のため、新しいツールをラッパーへ追加すると、そのツールを含まない既存の
  プラグインキャッシュ版で `inspect` を含む**全ツールが解決不能**になる。
  SI-SDD-016 の `spec_verify.py` はこの制約により直接実行を選ばざるを得なかった。
  結果として、利用者は「どのツールがラッパー経由でどれが直接実行か」を暗記する必要がある。
- **提案する修正**:
  1. ラッパーに**任意ツール**の概念を導入する（必須解決集合と提供ツール集合を分離し、
     要求されたツールが解決先に無い場合だけ明確なエラーを返す）
  2. または全ツールを直接実行へ統一し、ラッパーを廃止または版解決専用に縮退させる
  3. いずれの場合も、後方互換（既存キャッシュ版での動作）と移行手順を明示する
  4. 決定した規約を AGENTS.md の「定型手順」節へ反映し、宣言と実体を一致させる
- **対象ファイル**: `scripts/spec`、`AGENTS.md`、CORE-FR-011 の改訂または後継要件、
  `tests/test_spec_wrapper.py`、`plugins/bitz-sdd/skills/*/SKILL.md`（呼び出し例の記述）。
- **確認観点**: 既存のプラグインキャッシュ版（新ツールを含まない版）で従来ツールが
  引き続き解決できること。未提供ツールを要求したときのエラーが原因を特定できる内容であること。
  fingerprint による同一性検証（CORE-FR-011）が緩まないこと。
- **影響推定・ロールバック**: `scripts/spec` はリポジトリ全体の SDD 操作の入口であり、
  bitz-sdd を消費する全ワークスペースに影響する。軽量レーン不可・Design Gate 必須。
  1 は加法的に実装でき、問題時は必須解決集合を元へ戻せる。2 は破壊的変更となる。
- **依存**: CORE-FR-011（SDD ツールのバージョン非依存解決）、SI-CORE-022 / SI-CORE-034。

## 予備判定（推薦）— 裁定は人間専用

| 判定軸 | 確認結果 |
|---|---|
| 既存要件との矛盾 | なし。CORE-FR-011 の安全性（固定版検証・fingerprint）は維持したまま拡張できる |
| ガードレール抵触 | なし |
| 影響範囲 | `scripts/spec`（全ワークスペースの入口）、AGENTS.md、bitz-sdd の全スキル文書 |
| 軽量レーン適否 | 不適。共有ツールの解決契約に触れる |

**推薦: accept、ただし案1（任意ツールの導入）を推す**。案2 の全面直接実行は、
CORE-FR-011 が解決している版競合・fingerprint 検証の価値を失う。
優先度は SI-SDD-031 / 032 より低い（利用者の混乱であって、無音の欠陥ではない）。
