# 保持ケースの保存計画

次工程は、確定した製品6本文に対する発火・停止の保持ケースを別文脈で作成する。
公開prototypeの本文と製品本文を同一視せず、ケース生成前に製品資源manifestを固定する。
本文準備は `prepare.py` で確定commitのblobから取得し、hashを検査する。

承認を求める外部領域:

```text
/home/hide/BitzLabs/BitzSkills-private-evals/core-sdd-quality-20261006/
```

必要な操作は、新規領域の作成、所有者だけが利用できる権限の設定、
非公開の合成ケースJSON・集合manifest・検分ログ・後続評価証拠の新規保存。
既存ファイルの上書き・既存領域の削除・外部送信・公開を含めない。
公開repoには集合の版・件数・hashと集計結果だけを記録する。
privateに置いたprompt/context/期待値と生軌跡をPUSHしない。

初期収集は最大12ケース（製品6経路の正例と負例/境界を含む）。
生成SOL1枠と別文脈の検分SOL1枠、一次測定0、自動再試行0。
失敗・中断・重複・未知イベント・条件不一致で停止し、原記録を保持する。
公開ケースとのID/input重複、case schema、固定イベントカタログとの整合性を実検査する。
件数を揃えただけでprototype/releaseの全分母を充足したとは主張しない。

保持ケースの入力・出力は公開repo外へ置く既存契約を守る。
候補の改変やSKILL最適化へ保持prompt/期待値を戻さず、
新測定は集合hash・確定source・候補版・環境・分母・反復・停止・有限予算を起動前に固定する。
実モデル一次評価の予算はこの保存承認だけでは増やさず、SOL包括承認下の別有限contractへ記録する。
外部領域を使うため、AGENTS.mdの「リポジトリ外への書き込み・上書き・削除」の明示承認が必要。
承認前には外部領域も保持ケースも作成しない。
