# 保持ケースの意味重複を防ぐ後続工程

初期集合0.1.0は独立P2で停止した。公開IDとprompt/context文字列の衝突検査だけでは、
公開ケースと同じ状況・判断を言い換えたケースを排除できなかった。
原集合・検分・有限予算を保持し、同じ集合で測定したり成功へ置換したりしない。

次の収集では候補source `3252a29642323a403a51d9bd10acc6f4a7f3d236` と6本文/71資源を固定したまま、
公開集合との意味重複を排除する条件を生成前の契約に加える。保持内容を製品の最適化へ戻さない。

1. 公開ケース全件を除外資料として確認し、要求された主判断、状況・因果前提、期待する行動、
   停止を導く理由の組合せを非公開の作成根拠に記録する。名前や表現だけの変更を新規と扱わない。
2. 新ケースの各組合せについて最も近い公開ケースと比較し、決定に関係する差を説明する。
   主判断と決定を導く状況・因果前提が同じなら、単語・数値・対象名が違っても採用しない。
3. 既存の停止集合も除外照合だけに使用する。候補変更や解答誘導の材料にしない。
4. 生成後の別文脈検分者が全件を本文・公開集合へ照合し、新規性と一意な判定根拠を検査する。
   根拠不足・意味重複・曖昧さを、件数を満たすために許容しない。不足なら停止する。

新集合は別setVersion・別case IDs・別出力とし、承認済み領域の新規子ディレクトリへ保存する。
旧集合とファイルを変更せず、新旧の入力hash・条件・停止結果を区別する。
公開側には集合の版・件数・hashと集計を記録し、個別比較・本文・期待値・生ログを公開しない。

起動前に別有限contractへ最大12件、作成SOL1、ケース独立検分SOL1、一次0、retry0を固定する。
先に契約・監査コードを是正し、その確定sourceに対する準備独立SOL1も別枠で固定する。
この文書だけではモデル枠を消費せず、後続の確定contractを起動根拠とする。
監査CLIは新集合の固定path・setVersion・IDsと旧集合衝突を検査し、公開出力を集計に限定する。
意味重複の合否は機械的な文字列非重複から推定せず、独立検分の証拠を必要とする。
保持集合を通過した後でのみ、製品用runnerと一次発火測定の別有限contractへ接続する。
